# 開発日誌 2026年11月

## 2026-11-29

### ローカルマッチと対局前の確認を改善し、v4.2.0へ

#### ユーザー向けの説明

- ローカルマッチの設定画面からコンシェルジュを外しました。別窓の対局盤では、対応エンジンの評価値を確認できます。
- 同じ思考エンジンを使う場合も、エントリーごとにエンジンオプションを設定できます。思考エンジンが外部管理と指定した項目は、値と編集できない理由を表示します。
- WindowsのCGOS接続画面に現在のWi-Fi名を表示し、対局前に接続先を確認できるようにしました。着石音を再生できない環境でも対局を続けられます。
- 配布内容は [v4.2.0リリースノート](../../リリースノート/RELEASE_NOTES_v4.2.0.md) にまとめました。

#### 開発者向けの説明

- GTPオプションの定義で `externallyManaged` を使えるようにしました。Game OasisとCGOS通信ホストは対象項目への書き込みを省きます。切替ラッパーも対局開始時に選択先の定義を確認し、外部管理になった項目に仮起動時の設定を再送しません。固定指定と切替要求の両方を隔離環境で確認しました。
- 別プロジェクトのきふわらべプリプロピレンでは、各系統の実行ファイルの隣に研究設定を保存し、実効値を外部管理として返すようにしました。同エンジンの自己テスト29,367件が通り、切替先の研究設定で着手できることを確認しました。
- 日本語のVisual Studioで、`dotnet-mgcb` の復元メッセージをMSBuildがコードページ932として読み取ると文字化けすることを再現しました。復元処理をUTF-8に統一し、Game OasisのWindows版とインストーラーの両方で、日本語の復元ログとReleaseビルドを確認しました。

## 2026-11-27

### ビルド環境の整理とローカルマッチ起動中の表示

#### ユーザー向けの説明

- ロビーを起動するスタートアッププロジェクトは `KifuwarabeGo2026.GameOasis.Gui.Windows` であることを確認しました。
- 久しぶりのビルドで発生した、同梱NuGetパッケージの破損と、以前のSAC対策の開発用署名処理によるビルドエラーを解消しました。利用者からもSAC関連のビルドエラーが解消したとの確認を得ました。
- 別PCでローカルマッチの起動に約８秒かかり、待っている間に再度［START］を押すとエラーになっていました。起動準備中はボタンを無効にし、`STARTING...` と回転するスピナーを表示するようにしました。起動後は `RUNNING` と表示し、対局終了・起動失敗後は再び開始できます。利用者が実画面でスピナーの表示を確認しました。

#### 開発者向けの説明

- `.gitattributes` の一律の改行変換がZIP形式の `.nupkg` にも適用されていたため、StationeryUIのローカルパッケージ３個を修復し、`*.nupkg binary` を追加しました。
- 現在はSACをオフにする運用のため、ルートの `Directory.Build.targets` にあった署名連携を通常ビルドから外しました。署名用ビルド設定と、証明書作成・署名・診断のスクリプト３本は [Scripts/Archive/SmartAppControl](../../../../Scripts/Archive/SmartAppControl/README.md) へ退避しました。OS設定、証明書ストア、保存済み環境変数は退避作業では変更していません。
- `LocalMatchProcessLaunchCoordinator` に起動準備中の状態を追加し、準備完了通知または終了通知で解除します。GUIは起動直後と更新ループでセッションの状態へ反映し、開始可否、ボタン表示、スピナー描画を切り替えます。開始処理側でも実行中・準備待ちの重複要求を無視します。
- 既存の起動回帰検査に、起動準備中・準備完了・終了の状態検査を加えました。GUI移植性テストに `--play-room-launch` を追加し、起動関連の検査だけを実行できるようにしました。

#### 検証と次回の確認

- SAC対策退避後、`InstallerEngine.JsonLinesHost` と `GameOasis.Gui.Windows` のビルドは警告０・エラー０で成功しました。スピナー対応後のGUIビルドも警告０・エラー０でした。
- `--play-room-launch` の回帰検査は `PASS`。GUI移植性テスト全体の実行は、CGOS HostのRelease DLLが未ビルドだったため完走していません。
- 利用者によるスピナー表示の確認済み。別PCで起動が遅い場合の連打防止、起動失敗後の再試行、対局終了後の再開は、次回の実機確認項目です。

## 2026-11-24

### CGOSの連続観戦と、次局からの思考エンジン切り替え

#### ユーザー向けの説明

- CGOSで前局の終局図を表示したまま待っていると、次局が始まっても盤面が切り替わらない問題を修正しました。終局図で待っている場合は次局のライブ盤面に自動で戻ります。過去の手を確認している場合は、通知の［対局を見る］から切り替えられます。
- 思考エンジンを１系・２系・３系に分け、CGOSへの接続を維持したまま、次局から使う系統を選べるようにしました。たとえば１系で対局中に２系へ新版を置き、設定で主系を２系にすると、今の局は１系で最後まで打ち、次局は２系で始まります。３系を開発中の版の置き場にでき、１系の対局が終わった後は１系にも新版を置けます。
- CGOS接続画面の［説明］欄に、PLAYER 1とプラクティスプレイヤーそれぞれが実際に起動した系統を表示します。次局用の設定を変更しても対局中の表示は変わらず、終局や切断で `-` に戻ります。

#### 開発者向けの説明

- ルートの `Docs` を `docs2` 経由で `docs` に改名しました。READMEなどの参照、リリーススクリプト、開発日誌向けの `.gitignore` の例外を更新し、変更対象のローカルリンク18件の参照先を確認しました。
- 前局の共通レビューを描画しているときも、CGOSの画面遷移上は観戦中だったため、次局の開始通知が閉じられていました。終局図からの自動復帰と、過去の手から通知を使って戻る経路を修正し、次局の着手が終局前に盤面へ反映されることを回帰検査に加えました。実装は `159b7e66`。
- GTPラッパー `KifuwarabeGo2026.Tools.GtpEngineSwitch` は、局ごとの起動時に `engine-switch.json` の `primary` とエンジンのパスを読み込みます。開発PCの `D:/Projects/KifuwarabeGoPolypropylene` では、現行版 `0.3.1` のEXE・DLL・deps.json・runtimeconfig.jsonを１系にコピーし、既存のエンジン登録の［EXE］をラッパーへ変更しました。思考エンジン側のCodexには、配布スクリプトで配置先の系統を指定できるよう相談しました。ラッパーの実装は `9564b523`。
- 通信ホストが子プロセスの起動メッセージを汎用のエンジン説明通知に変換し、GUIは接続ごとに表示します。系統の選択とパスの管理はラッパー側が担当します。実装は `c6b78390`。

#### 検証と次回の確認

- ビルドとGUI移植性テストは成功しました。実エンジンでGTPの応答と着手を確認し、模擬CGOSサーバーとの１接続で３局を進め、１系・２系・３系の説明通知が各局に順番に届くことを確認しました。
- 次回は実際のCGOSサーバーで連続対局を行い、前局の終局図から次局のライブ盤面に移ることと、接続画面の［説明］欄が終局・次局の開始に合わせて変わることを目視確認します。
