# Protocol M v1.0

Protocol Mは、ゲームコンシェルジュと人間またはコンピューターのゲームマスター実装を接続します。

## 最小ライフサイクル

```text
Describe
StartSession
    ├─ SelectCommand
    ├─ NotifyCommand
    └─ EndSession
```

同じ実装が複数ゲームを運営できるよう、ゲームへの割り当てごとに`GameMasterBindingId`を発行します。人間のゲームマスターは、運営用GUIをこのインターフェースへ適合させるアダプターとして参加できます。

## 運営命令

命令名はGame Oasis共通の安定した文字列です。最初の縦方向実装では`pause`、`resume`、`adjudicate`、`end-session`を定義します。命令固有の追加情報は自己記述的な`ContractDocument`で渡せるため、Contractsが特定ゲームの石、盤、得点などを所有する必要はありません。

コンシェルジュは、ゲームマスターが命令の前提にしたプレイスペース・リビジョンと運営リビジョンを現在状態と照合してから実行し、受理または拒否を`NotifyCommand`で返します。停止・再開は盤面を変更しないため、プレイスペースとは独立した`OperationRevision`で競合を検出します。停止中はプレイヤーへの着手要求とプレイスペースへの行動適用を拒否します。

`adjudicate`は、勝者、無勝負、失格理由などを表す自己記述的な結果文書を確定します。裁定後のGame Oasisスナップショットは終局となり、行動適用を拒否します。結果文書はProtocol G、P、Mへ同じ内容で渡されます。

## 今後追加する運営領域

- ハンディキャップおよび初期局面の確定
- 時間補正
- 裁定結果文書の標準スキーマと、無勝負・失格などの補助コマンド
- プレイスペースだけでは判断できない状況への問い合わせと回答
- 権限、監査履歴、複数ゲームマスター間の優先順位
