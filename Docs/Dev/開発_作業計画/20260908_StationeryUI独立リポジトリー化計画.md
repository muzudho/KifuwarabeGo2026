作成日: 2026-09-08

状態: 計画作成済み。新リポジトリー作成・コード移行・公開は未実施。

## 目的と合意した方向

文房具UIを独立したリポジトリーで育て、MITライセンスのオープンソースライブラリーとして提供する。MonoGameを使ったPC向けGUIを作りやすくし、日本語IMEによるテキスト入力と、文房具をモチーフにした外観を特徴にする。

Windows Formsの代わりに設定画面や編集画面を作れることを目指す。初期版ではMonoGameの単一ウィンドウ内のGUIに範囲を絞る。Windows Forms全機能との互換やデザイナーは初期版の目標に含めない。

- リポジトリー名は `StationeryUI` を採用する方向。説明文では「MonoGame向けのデスクトップGUIライブラリー」と用途を補足する。
- Windows依存部分は `StationeryUI.Windows` のような別プロジェクトへ分ける。
- テーマでアプリに合わせた色変更を可能にする。
- きふわらべの碁2026とサークルスペースコーディネーターを、同じライブラリーの実利用者にする。
- 以下のプロジェクト構成とAPI名は実装案。依存調査・試作結果を記録して調整する。

## 構成案と依存方向

```text
StationeryUI/
  src/
    StationeryUI/            # 状態、レイアウト、入力管理、テーマ、サービス契約
    StationeryUI.MonoGame/   # 描画、MonoGame入力接続、Update/Drawへの組み込み
    StationeryUI.Windows/    # Windows IME、クリップボード、文字描画
  samples/
    StationeryUI.Demo/       # Windows + DesktopGLで動く部品・入力・テーマの実演
  tests/
  docs/
  LICENSE
  README.md
  THIRD-PARTY-NOTICES.md
```

- `StationeryUI.MonoGame → StationeryUI`、`StationeryUI.Windows → StationeryUI` を基本とする。
- アプリが必要な実装を生成・接続する。共通部分からWindows実装や利用アプリへ依存しない。
- 共通部分の公開型にMonoGame型、Win32ハンドル、SDL固有型を漏らさない。小さな座標・色の値型を検討し、変換は接続側で行う。
- Windows実装がMonoGameとの接続を必要とする場合は、その理由と接続箇所を明示する。三分割を守るためだけの過剰な抽象化はしない。
- OSと描画・ウィンドウバックエンドを別々に扱う。初期の検証対象はWindows + DesktopGL。WindowsDX、Linux、macOSは未検証と明記し、動作を推測で保証しない。
- Linux/macOS用の空プロジェクトは初期版では作らず、実装追加可能な契約を用意する。

## 初期版の機能と設計条件

### テーマと表示

- `StationeryTheme` 等に背景・文字・枠・アクセント・選択・無効・フォーカスの色をまとめる。
- 通常、ホバー、押下、選択、無効、フォーカスの状態別表示を決める。
- 適用優先順位は「コントロール個別指定 → アプリのテーマ → 標準テーマ」を基本とする。
- フォント、文字サイズ、余白、枠幅、角丸、影も設定可能な項目として整理する。大規模なCSS相当の仕組みは初期版では作らない。
- 文房具らしい標準テーマと、配色の異なるサンプルテーマを用意する。
- レイアウトの最小限の測定・配置、クリッピング、スクロール、リサイズ時の再配置を設計する。
- 論理座標から画面・物理ピクセルへの変換を統一し、描画・ヒット判定・IME候補位置を一致させる。

### 入力とフォーカス

- キー操作と文字入力を分離する。UIが処理した入力をゲーム側にも渡すかを明示できるようにする。
- Tab/Shift+Tab、クリックによるフォーカス移動、モーダル時の入力制限をまとめて管理する。
- ドラッグ中のポインター保持、ホイール、ウィンドウ非アクティブ化時の解除を定義する。
- マウスとタッチの共通化を見据え、ポインター識別・座標を扱う。タッチの動作保証は実機検証後とし、未検証状態を記録する。
- コントロールのアクセシブルな名前とキーボード操作を用意する。OSの画面読み上げとの接続は後続課題とする。

### テキスト編集とIME

- 単一行入力を最初の縦通し実装にする。複数行入力や既存の数値・時間入力は利用箇所を調べて段階的に移行する。
- 共通契約には入力開始・終了、未確定文字、未確定範囲内のカーソル・選択、確定文字、入力領域の通知を含める方向で試作する。
- 取消・フォーカス喪失・確定時の状態遷移と、UIスレッドへの受け渡しを定義する。
- MonoGameとOSサービスからの確定文字の二重配信を防ぐ。どちらを入力元にするかを明記する。
- 選択、コピー・切り取り・貼り付け、Undo/Redoを用意する。IMEの一度の確定を編集履歴でどう扱うかも決める。
- UTF-16の位置と利用者が認識する文字単位を区別し、サロゲートペア・結合文字を壊す削除や移動を防ぐ。
- フォント選択、フォールバック、文字測定と描画の一致を検討する。絵文字を含む対応範囲・制約を明示する。
- イベント購読解除、ネイティブフック解除、テクスチャ・フォントキャッシュの破棄を定義する。
- OSサービスがない場合の動作・制限を明確にし、診断表示は通常のコントロール契約から分ける。
