# ランチャーエンジン JSON Lines プロトコル

## 目的

ランチャーＧＵＩとランチャーエンジンを、プログラミング言語とＯＳに依存しない標準入出力で接続するための試験仕様です。
第１版は読み取り専用操作から開始し、安全性を確認できた設定変更と検証付きアンインストールまで段階的に広げます。

## 搬送規則

* 文字コードは UTF-8 とします。
* １行に１個の JSON オブジェクトを記述する JSON Lines とします。
* クライアントからホストへの要求は標準入力へ書き込みます。
* ホストからクライアントへの応答は標準出力へ書き込みます。
* 標準出力にはプロトコルメッセージ以外を書き込みません。
* ログと診断情報は標準エラー出力へ書き込みます。
* 要求１件につき応答１件を返します。現在は逐次処理です。

## 要求

```json
{"protocolVersion":1,"requestId":"任意の一意な文字列","method":"getState"}
```

| フィールド | 型 | 意味 |
|---|---|---|
| `protocolVersion` | 整数 | 現在は `1` |
| `requestId` | 文字列 | 要求と応答を対応付ける識別番号 |
| `method` | 文字列 | 操作名 |

## 成功応答

```json
{"protocolVersion":1,"requestId":"要求と同じ値","success":true,"result":{},"error":null}
```

## 失敗応答

```json
{"protocolVersion":1,"requestId":"取得できた場合は要求と同じ値","success":false,"result":null,"error":"失敗理由"}
```

## 第１版の操作

### `getState`

引数なしでランチャーの現在状態を返します。結果は `LauncherState` と同じ意味を持ちます。

### `getInstalledVersions`

引数なしでインストール済みバージョンの配列を返します。各要素は `InstalledVersion` と同じ意味を持ちます。

### `getCurrentDirectory`

`parameters.product` に `gui` または `engine` を指定し、現在版のディレクトリーを返します。未インストールの場合の結果は `null` です。

### `changeInstallationDirectory`

`parameters.directory` に新しいインストール先を指定します。`null` は自動設定へ戻す指定です。結果は業務結果と変更後の状態です。

### `changeScreenshotDirectory`

`parameters.directory` にスクリーンショット保存先を指定します。結果は業務結果と変更後の状態です。

### `changeCloseAfterStartingGui`

`parameters.value` に真偽値を指定します。結果は業務結果と変更後の状態です。

### `uninstall`

`parameters.installedVersion` に一覧取得で得た対象を指定します。エンジンは保護状態と管理フォルダー境界を再検証してから削除します。既に存在しない同一対象への再実行は成功として扱います。

## 障害の扱い

* クライアントはプロトコルバージョンと `requestId` の一致を検証します。
* 応答待ちにはタイムアウトを設けます。既定値は10秒です。
* 不正な JSON、応答の欠落、子プロセス終了、未対応バージョンを通信障害として扱います。
* ホストは要求単位の失敗を `success: false` で返し、可能なら次の要求を待ちます。
* 第１版の読み取り操作には要求単位のキャンセルを設けません。終了が必要な場合はクライアントを破棄して標準入力を閉じ、終了しないホストは停止します。
* クライアント終了時は標準入力を閉じます。ホストは入力終端を受けて終了します。
* `success: true` の応答内にある `LauncherOperationResult` の失敗は業務上の失敗です。通信障害とは区別します。
* 通信障害を検出したクライアントはホストを停止し、同一プロセスエンジンへ切り替えます。ＧＵＩには復旧したことと通信エラーを表示します。

## 試験導入時の切り替え

通常起動では、従来の `InProcessLauncherEngine` を使用します。
ランチャーへ `--engine-stdio` を指定した場合、上記の操作を `JsonLinesLauncherEngine` 経由で子プロセスへ依頼します。
更新と管理対象ＧＵＩの起動は同一プロセスエンジンへ委譲します。更新は進捗、キャンセル、途中終了後の再実行設計が必要であり、ＧＵＩ起動はランチャー自身の更新・再起動経路を正しく引き継ぐ必要があるためです。

ホストの既定位置はランチャーと同じディレクトリーの `KifuwarabeGo2026.LauncherEngine.JsonLinesHost.dll` です。アプリケーション制御ポリシーが補助 EXE を拒否する環境を考慮し、ランチャーと同じ .NET ランタイムの `dotnet` コマンドで DLL を起動します。
開発時は環境変数 `KIFUWARABE_LAUNCHER_ENGINE_HOST` で別のホスト実行ファイルを指定できます。

## 他言語による実装

ホスト実装に必要なのは、UTF-8 の標準入出力、１行単位の読み書き、JSON の解析だけです。
C# 固有の型名やバイナリーシリアライズは搬送規則に含まれません。
他言語版では、フィールドの意味と JSON の値をこの仕様に合わせます。
