# カジュアル・コアとフォーマル・アダプター

## 目的

ゲームオアシスの内部は、既存のゲーム界隈ごとの仕様へ直接合わせるのではなく、ゲームオアシス自身の小さく扱いやすい契約を使って実装します。この内部領域を［カジュアル・コア］と呼びます。

GTP、CGOS、USI、CSA、SGF、KIFなど、既存界隈で利用されている仕様は、［フォーマル・アダプター］を介してカジュアル・コアへ接続します。これにより、新しい実装は既存仕様の歴史的事情をすべて背負わずに作ることができ、既存のエンジン、サービス、棋譜、ツールも引き続き活用できます。

```text
既存界隈のフォーマルな仕様
  GTP / CGOS / USI / CSA / SGF / KIF / その他
                    ↓
             フォーマル・アダプター
                    ↓
ゲームオアシスのカジュアル・コア
  Contracts / Protocol G・P・M・S / 各役割の実装
```

ここでいう［カジュアル］は、無規則または無契約という意味ではありません。外部仕様の都合から独立し、ゲームオアシス自身の言葉で、作成、交換、検査しやすくするという意味です。

## 三つの実装区分

* ［カジュアル・コア］：ゲームオアシス内部の意味契約と、その契約を使う実装。GTPやUSIなど、個別の外部仕様を知らない。
* ［カジュアル・ネイティブ］：外部仕様を介さず、Protocol G、P、M、Sなどのゲームオアシス契約へ直接接続する実装。
* ［フォーマル・アダプター］：既存界隈の仕様とゲームオアシス契約の間で、意味、形式、ライフサイクルを変換する実装。

例えば、GTP、USI、独自AIをプレイヤーとして利用する場合は、次のようになります。

```text
GTPエンジン ── GTPアダプター ──┐
USIエンジン ── USIアダプター ──┼─ Protocol P ── Game Oasis
独自AI ──────────────────────────┘
```

独自AIはカジュアル・ネイティブとして直接接続できます。既存エンジン固有のコマンド、座標、オプション、終了手順などは、各フォーマル・アダプターの内側へ閉じ込めます。

## `FormalAdapter` ProjectFamily

きふわらべ公式のフォーマル・アダプターは、次のProjectFamilyへ整理します。

```text
KifuwarabeGo2026.FormalAdapter.{FormalSpecification}.{SubNamespace}
```

候補例：

```text
KifuwarabeGo2026.FormalAdapter.Gtp
KifuwarabeGo2026.FormalAdapter.Cgos
KifuwarabeGo2026.FormalAdapter.Usi
KifuwarabeGo2026.FormalAdapter.Csa
KifuwarabeGo2026.FormalAdapter.Sgf
KifuwarabeGo2026.FormalAdapter.Kif
```

一つの仕様が複数の役割へ接続され、分割する必要が生じた場合は、役割を下位名に含めます。

```text
KifuwarabeGo2026.FormalAdapter.Gtp.PlayerEngine
KifuwarabeGo2026.FormalAdapter.Cgos.GameMasterEngine
KifuwarabeGo2026.FormalAdapter.Sgf.GameRecord
```

物理プロジェクトを必ずこの粒度で分けるという意味ではありません。責務、依存関係、配布単位が小さい間は一つのプロジェクトにまとめ、必要になった時点で同じProjectFamilyの配下へ分割します。

既存の`KifuwarabeGo2026.Reference.Communication.*`などは、実際に責務と依存関係を確認するまで機械的に改名しません。新しい配置へ段階的に移し、既存の実行ファイル名、設定、ランチャー、外部利用者との互換経路を維持します。

2026年8月29日、次のビルド可能なプレースホルダーをソリューションへ追加しました。

```text
KifuwarabeGo2026.FormalAdapter.Gtp
KifuwarabeGo2026.FormalAdapter.Cgos
KifuwarabeGo2026.FormalAdapter.Usi
KifuwarabeGo2026.FormalAdapter.Csa
KifuwarabeGo2026.FormalAdapter.Sgf
KifuwarabeGo2026.FormalAdapter.Kif
```

プレースホルダーは将来の所属先を先に示すためのもので、旧実装を参照するだけの中継アセンブリにはしません。実装を移すまでは空のProjectFamily入口として維持します。

## 継続的な移行方針

GTP、CGOS、棋譜形式などに関係する機能を新設または変更する際は、作業対象を次の三つに分類します。

1. 外部仕様の解釈、形式変換、実装差の吸収であれば、対応する`FormalAdapter`へ新設または移動する。
2. ゲームオアシス自身の意味契約またはゲーム状態であれば、カジュアル・コア側に残す。
3. 両方を含む場合は境界を作り、外部仕様側だけを`FormalAdapter`へ分割する。

移行は関連箇所を触る機会ごとに、安全な最小単位で進めます。ただし、別目的の変更へ大規模改名を混ぜません。各移行では、依存方向、公開型、保存形式、実行ファイル名、発行物、ランチャー参照を確認し、既存の回帰試験または新しい適合性試験が成功してから旧配置を除きます。

GTP、CGOS、SGFの現行使用箇所と具体的な移行順序は、[`GTP・CGOS・SGFのFormalAdapter移行調査・計画.md`](../開発_作業計画/GTP・CGOS・SGFのFormalAdapter移行調査・計画.md)を参照してください。

## フォーマル・アダプターの責務

フォーマル・アダプターは、原則として次を所有します。

* 外部仕様の要求、応答、通知、ファイル形式の解釈。
* 外部仕様とゲームオアシス契約の相互変換。
* 座標、識別子、文字コード、オプション、エラーの変換。
* 接続、初期化、再接続、終了など、外部仕様固有のライフサイクル。
* 正式仕様と実際の実装差を吸収する互換処理。
* 未対応能力、情報欠落、変換不能を表す診断。

次のものは所有しません。

* 権威あるゲーム局面、合法手、勝敗判定。
* ロビーやプレイルームの画面状態。
* コンシェルジュのセッション運営状態。
* 外部仕様と無関係なプレイヤー戦略。

変換できない情報を黙って捨てたり、推測で補ったりしません。完全変換、情報を失う変換、未対応、相手実装の違反を呼び出し側が判別できる結果または診断にします。

## 実行可能なリファレンスとして残すもの

各`FormalAdapter`領域は、変換コードだけでなく、その界隈を理解する入口として次をまとめます。

* 仕様が生まれた界隈、目的、想定する役割。
* 参照した仕様書、版、取得元、確認日。
* 必須機能、任意機能、私的拡張の区別。
* 仕様書に記載された規則と、実際に普及している慣習の区別。
* ゲームオアシス契約との対応表。
* 完全には対応付けられない概念と情報損失。
* 入出力例、サンプル設定、代表的な接続手順。
* 既知の実装差、互換性上の注意、診断方法。
* 単体試験、実プロセス試験、適合性試験とテストベクトル。

文書とコードの内容が離れないよう、可能なものはサンプルや適合性試験として自動実行できる形にします。外部仕様の更新を取り込むときは、対応版、変換規則、テストベクトルを一緒に更新します。

## 依存方向

カジュアル・コアから特定のフォーマル・アダプターを参照しません。アプリケーションの構成点が必要なアダプターを選び、外部仕様側とゲームオアシス契約側を接続します。

```text
FormalAdapter.Gtp ────────┐
FormalAdapter.Cgos ───────┼─→ GameOasis.Contracts
カジュアル・ネイティブ ─┘

GameOasis.Contracts ─X→ FormalAdapter.Gtp
```

ゲームオアシス自身のProtocol G、P、M、Sは、外部界隈のフォーマル仕様ではなく、カジュアル・コアの意味契約です。JSON Linesなどの配送方式は、その意味契約をプロセスや言語の境界越しに運ぶための通信アダプターです。GTPやCGOSなどとの意味変換を行うフォーマル・アダプターとは区別します。

## 完了の判断

新しいフォーマル・アダプターは、最低限、次を満たしたときに利用可能と判断します。

* 対応する外部仕様と版が明記されている。
* ゲームオアシス契約との意味対応が説明されている。
* 情報損失と未対応能力が明記されている。
* 外部仕様固有の型がカジュアル・コアへ漏れていない。
* 正常系、異常系、代表的な実装差の自動試験がある。
* 標準出力をプロトコルに使う場合、ログが標準エラー出力へ分離されている。
