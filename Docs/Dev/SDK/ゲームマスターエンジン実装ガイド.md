# ゲームマスターエンジン実装ガイド

状態：プレースホルダー

## この文書の読者

Kifuwarabe Go 2026へ新しい［ゲームマスターエンジン］を接続したい開発者を対象とします。単純なゲームルールだけでは決められない運営命令、例外裁定、勝敗・失格等を扱います。

## 接続境界

ゲームマスターエンジンとゲームオアシスはProtocol Mで接続します。

```text
GameOasis Concierge
  ↓ Protocol M
IGameMasterProtocol
  ↓
ゲームマスターエンジン
```

.NET実装の現在の契約は次にあります。

* `KifuwarabeGo2026.GameOasis.Contracts.ProtocolM.IGameMasterProtocol`
* `KifuwarabeGo2026.GameOasis.Contracts.ProtocolM`の命令、通知、裁定モデル。
* 参照調停実装：`KifuwarabeGo2026.GameOasis.Concierge.GameOasisGameMasterCoordinator`。
* 人間による参照実装：`HumanGameMasterProtocol`。

## 役割の境界

Play Room Engineは通常のゲームルールに基づく合法性、状態遷移、終局を判定します。Game Master Engineは運営上の命令と例外裁定を担当します。

想定する命令には、開始、停止、再開、中止、無勝負、失格、時間補正、打ち直し、結果の上書きがあります。正式に利用可能な命令はProtocol Mの能力記述と契約版で合意します。

## 最小実装手順（予定）

1. 安定したID、表示名、Protocol版、対応命令を記述する。
2. `IGameMasterProtocol`を実装する。
3. セッション開始とゲームへの割当てを処理する。
4. 運営命令要求に対して命令または待機を返す。
5. 実行された命令とゲーム状態の通知を受け取る。
6. セッション終了と異常切断を処理する。
7. 将来追加するProtocol M適合性ランナーへ合格する。

## 実装してはいけない責務

* 通常の合法手判定や局面更新をGame Master側へ複製すること。
* プレイヤーの次の行動を選ぶこと。
* GUIやLobbyの保存型を参照すること。
* 対応していない命令を無言で成功扱いすること。
