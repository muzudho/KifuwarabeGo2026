# 開発日誌 2026年9月

## 2026-09-08

### 文房具UIを独立したMITライブラリーとして公開

#### ユーザー向けの説明

- 文房具UIを、MonoGameでPC向けGUIを作るための独立ライブラリー `StationeryUI` として公開しました。これからはアプリを作るたびに共通部品をコピーせず、同じライブラリーを参照して使い回せます。
- 日本語IMEの入力接続、文字編集、ボタンや下線などの部品、アプリに合わせた配色を共通の場所で育てていきます。
- リポジトリーの作成と移行はCodexが担当し、むずでょさんがGitHubのリポジトリーをブラウザーで確認しました。
- [StationeryUIの公開リポジトリー](https://github.com/muzudho/StationeryUI)はMITライセンスです。[初版v0.1.0](https://github.com/muzudho/StationeryUI/releases/tag/v0.1.0)にパッケージを添付しています。NuGet.orgへの公開はまだ行っていません。

#### 開発者向けの説明

- OS・MonoGame非依存の `StationeryUI`、描画・入力接続の `StationeryUI.MonoGame`、IME・クリップボード・文字描画を担当する `StationeryUI.Windows` の3プロジェクトへ分離しました。
- サンプル、明暗テーマと個別上書き、文字編集・フォーカス・モーダル・ポインター保持の共通モデル、テスト、Windows/LinuxのCI、導入文書を整えました。
- きふわらべの碁2026とサークルスペースコーディネーターを、同じ0.1.0パッケージの参照へ切り替えました。各アプリの `LocalPackages/StationeryUI` と `NuGet.Config` で復元でき、開発者固有の絶対パス参照を避けています。
- 碁石・対局結果・背景・画面別の付箋配置などは、きふわらべ側に残しました。Windowsの合成監視はライブラリーへ抽出し、アプリ側には通知形式をつなぐアダプターを保持しています。
- Windows/LinuxのCI、両アプリのビルドと自動検査は成功しました。検証の詳細と未確認事項は[StationeryUIの検証記録](https://github.com/muzudho/StationeryUI/blob/main/docs/validation.md)に保存しています。

### コントロールのプログラム解説も移行

- コードの抽出後、元の `Controls/Button` などに `プログラム解説.md` が残っていることを、むずでょさんの指摘で確認しました。
- 元の解説12件を見直し、共通部分の解説11件を独立リポジトリーのコードの隣へ移しました。READMEからたどれる[解説一覧](https://github.com/muzudho/StationeryUI/blob/main/docs/control-guide.md)も追加しました。
- 古い描画クラス名、リンク部品の使用例、文字編集やIMEの説明を現在の実装に合わせました。
- GTP設定の下書き保存、SGFコメントへの反映、チャートの表示仕様は、きふわらべ側の[アプリ固有連携](../../../../KifuwarabeGo2026.StationeryUI/Presentation/StationeryUI/アプリ固有連携.md)へ整理しました。付箋とテキストダイアログの説明は、残したアプリ側コードとともに保持しています。
- 文書18件と相対リンク35個を確認し、移動元の重複文書9件を取り除きました。この追加作業は文書のみで、公開済みパッケージは変更していません。

#### 今日の終了地点と次回への引き継ぎ

- StationeryUIはGitHubへ反映済みです。初版の実装コミットは `fcb5b14`、解説移行は `9b6936c` です。
- きふわらべの移行は `aa59a254`、解説整理は `f134f1ba`、サークル側の移行は `52de77e7` にローカルコミット済みです。両アプリ側のpushは未実施です。
- 次回は実際の日本語IMEでの変換・候補選択・取消し、DPI変更、両アプリの対象画面の操作を確認します。自動検査の成功と、これらの手動確認は区別しています。
- 再開時は[実装・引き継ぎの正本](https://github.com/muzudho/StationeryUI/blob/main/docs/implementation-plan.md)と各リポジトリーの差分を確認します。公開済み0.1.0は固定し、コードを修正して配布する場合は新しい版にします。
- 独立化の実装、初回公開、解説の移行までを今日の区切りとし、ここで作業を終了しました。

### インストーラーへの改名とロビー起動導線

#### ユーザー向けの説明

- ランチャーの名前をインストーラーへ変更しました。
- デスクトップの標準ショートカットから、管理画面を経由せずロビーを起動できるようにしました。インストーラー画面にもショートカット作成ボタンを追加しました。
- ロビーのボタンは［インストーラーを起動］、インストーラーのボタンは［START LOBBY］（ロビーを起動）になりました。
- 既存の設定と導入済みの版を維持し、旧Launcher名のexe・配布ZIPも互換用に残します。
- Products、Installationと開発者向け文書を更新しました。この実装作業時点では未公開で、続けて上記のv4.0.8リリース作業を行いました。

#### 開発者向けの説明

- InstallerGui、InstallerEngine、Platform、Presentation、JsonLines、Host、対応テストへプロジェクト・型・参照を改名しました。汎用のPlay Room／Desktopプロセス起動サービスはLauncherの名前を維持しています。
- `--launch-lobby` を管理画面のMutex判定前に処理し、現在版・直前版の選択と起動をエンジンに委譲します。起動できない場合は管理画面から導入・復旧できます。
- `--local-application-data` により検査用設定を分離できます。特殊フォルダーを取得できない環境では保存先を補完します。
- パッケージ更新・削除・起動・設定変更の競合をファイルロックで検出します。設定ファイル名、既存JSONキー、管理用 `Launcher/Current` は維持します。
- 新旧の環境変数を受け付け、ロビーへ両方の起動元パスを渡します。既存管理画面への再要求では、前面化して正常終了します。
- WindowsショートカットのTargetPathとArgumentsを検証し、別用途の同名リンクを保護します。登録済みの旧標準リンクはロビー起動引数へ移行し、独自の管理用引数は保ちます。
- 全体ビルド、InstallerEngine・Windows・移植性の検査、およびWindows実画面でのインストーラー→ロビー→インストーラーの往復を確認しました。
- 段階別の状態、配布物検査、公開時に残る確認は[実装計画](../../開発_作業計画/20260907_インストーラー改名とロビー起動導線変更計画.md)へ記録します。
