# 外部アプリからのプレイルーム利用計画

2026-09-09の利用者確認を反映。目的は、誰もがロビーとプレイルームのどちらも作れるように、公開インターフェースとリファレンス実装を提供することです。外部ロビー→公式プレイルーム、公式ロビー→外部プレイルーム、外部同士を同じ契約で接続できることを目指します。DLL分離は準備段階です。標準入出力による接続まで進めることは決定済みで、gRPC採用は未決定です。

## 現在の入口

[今回のコード確認](../CurrentState/ExternalPlayRoomIntegration.md)に、既存経路と未確認範囲を記録しています。過去の段階3〜7の完了は、その段階の条件に対するものです。外部アプリから画面付きプレイルームを一通り利用できることの完了判定には流用しません。

## 実施順序と完了条件

### 1. 外部クライアントから既存JSON Linesホストを操作する

2026-09-09：最小CLIと正常・異常系の試験を実装済み。[サンプルと手順](../../../Samples/External.PlayRoomClient/README.md)。公式LobbyやGUIのDLLを参照せず、ホストのパスを引数で受け取ります。次の主作業は段階2の画面付きホストへの接続です。

独立Python Board Editorホストも追加し、公式.NETクライアント→外部ホストおよび外部Pythonクライアント→外部ホストを検証済みです。画面なしの最小契約で両側の実装例を揃えました。

- まずBoard Editorで `open → replacePosition → adopt` と `open → discard` を通し、返却局面を検査する。
- 続いてReviewの局面選択、Matchの状態更新・完了を同じ方法で検査する。
- 実際の送受信JSON、起動方法、終了コード、必要な配布ファイルを文書化する。
- 不正な版、セッションID不一致、途中終了、タイムアウトでも呼出元が停止せず、子プロセスを回収することを検査する。

この段階は通信契約の実証です。画面付きプレイルームの利用完了とは扱いません。既存Protocol Sの外部Counterはルール実装の例なので、外部呼出元の例とは別に保持します。

### 2. 画面付き囲碁プレイルームを同じ外部境界へ接続する

2026-09-09：Match用`--stdio`を実装し、実ウィンドウの起動・状態更新・終了スモークを通しました。[実装結果と未確認範囲](../CurrentState/GoWindowStdio.md)。実マウス・キーと閉じる操作の手動確認が残ります。

現在の保存済み要求ファイルによる起動との互換を保ち、標準入出力から起動要求・状態更新・終了要求を受け取る経路を追加します。最初はMatch一種類を対象にします。

- 外部クライアントから画面を開き、初期局面と更新局面を表示できる。
- 画面での着手・パス・投了を外部の進行役へ返し、確定状態を受けて表示を更新できる。
- ウィンドウを閉じた場合と外部から終了要求を送った場合の双方で結果を返せる。
- 通信の読取りで画面ループを止めず、描画状態の変更は画面側へ受け渡す。

既存Matchホストの `submitAction` は要求への応答であり、画面から自発的に発生する入力通知の契約には不足します。実装前にイベント取得方式、要求とイベントの識別、順序、終了通知を定義し、必要なら版または能力で拡張を区別します。Protocol Gとの責務も照合し、同じ役割の独自契約を重複して作りません。

### 3. 公式Lobbyも公開された同じ接続経路を使用する

外部クライアントで通った経路へ公式Lobbyを接続します。起動準備は自己完結した公開文書にし、プレイルームがLobbyの設定保存先や内部セッションを読まなくても動くことを検査します。ルール判定の正本は既存の進行役・Engineに保ちます。

Matchの開始・操作・終了・異常終了を通した後、Board Editor、Review、ポン抜き、CGOSなどの経路を個別に棚卸しして移行します。一種類の成功を全種類の完了とは扱いません。

### 4. 配布物だけで再現できるようにする

ソースツリーや開発用設定のない配置で、外部クライアントと発行済みホストだけから再現します。公開する通信仕様、対応版・能力、起動方法、JSON例、エラー、必要ファイルをSDKガイドへまとめます。公式Lobbyと外部アプリで同じ適合性試験を使用します。

## gRPCの位置づけ

現時点の提案は、内部処理と公開データ契約を通信方式から独立させ、標準入出力と、採用した場合のgRPCをそれぞれ接続アダプターにする構成です。標準入出力を使うためにgRPCサーバーの起動まで必須にする構成は、現時点では採用しません。

まず上記の標準入出力経路を成立させ、その後、別マシン接続、複数クライアント、通知方式、配布・運用負担の具体的な要件からgRPCを判断します。採用する場合も標準入出力の公開契約を維持し、同じ意味操作・結果・エラーの適合性を検査します。

## 描画DLL分離との関係

[Lobby描画境界の分離](LobbyRenderer.md)は補助作業です。中断時点の変更についてReleaseビルドは再開後に成功しました。外部接続の完了条件には数えず、通信変更の検証と区別して記録します。
