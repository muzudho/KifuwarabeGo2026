CGOS観戦画面 評価値チャート実装計画（引継ぎ用）
作成日: 2026-07-25
整理状態: 完了（ファイル名の日付は開始日）

===============================================================================
1. 目的
===============================================================================

CGOS観戦画面に、対局者が各自の手番でCGOSサーバーへ送った評価値を時系列で
表示する。

人間の対局観戦では地の差（Score）を主情報とし、勝率（Winrate）は補助情報
として扱う。ScoreとWinrateは別々のチャートにせず、1つのチャートへ重ねる。

完成イメージ:

  RepositoryAssets/UiMockups/
    20260725-cgos-position-trend-chart-mock-v4.png

表示方針:

  ・背景は黒白の識別を妨げないスレートブルー
  ・Scoreは前面に、不透明度の高い縦棒として表示
  ・Winrateは背面に、薄い折れ線として表示
  ・黒番から届いたデータと白番から届いたデータを混ぜず、別系列にする
  ・黒系列は黒色＋シアン系の縁取り
  ・白系列はアイボリー系＋暗色の縁取り
  ・上側に「黒有利 BLACK ADVANTAGE」
  ・下側に「白有利 WHITE ADVANTAGE」
  ・両ラベルの左端と幅を揃える
  ・BLACK DATA / WHITE DATAという凡例は付けない
  ・SCORE / BOTH / WIN RATEの表示切替を付け、初期値はBOTH


===============================================================================
2. 現在の実装と、利用できるデータ
===============================================================================

CGOSから受信した着手は、CgosGameObservationのMovesに全件保持されている。

主な関連ファイル:

  KifuwarabeGo2026.GameOasis.Gui/Application/Cgos/Watching/
    CgosGameObservation.cs
    CgosMoveAnalysisParser.cs

  KifuwarabeGo2026.GameOasis.Gui/Application/Local/Playing/
    GoMoveAnalysis.cs

  KifuwarabeGo2026.GameOasis.Gui/Presentation/Cgos/Watching/
    GoScreenRenderer.CgosWatching.cs
    CgosWatchingRenderer.cs

  KifuwarabeGo2026.GameOasis.Gui/Presentation/Shared/
    GoScreenRenderer.MoveAnalysis.cs

  KifuwarabeGo2026.GameOasis.Gui/Sgf/
    SgfGameRecordConverter.cs

GoGameMoveにはStoneとAnalysisがあり、Analysisには次の値が入る。

  double? Winrate
  double? Score
  long?   Visits
  string  PrincipalVariation

CgosMoveAnalysisParserはCGOSの解析JSONからwinrate、score、visits、pvを読み込む。
Winrateは0.0～1.0の範囲外ならnullにしている。

CgosGameObservation.ApplyMoveは、着手ごとの解析結果をGoGameMoveへ格納している。
したがって、ライブ観戦チャートのために通信層を大きく変更する必要はない。

SGFではKFAプロパティに解析JSONを保存し、再読込時にもGoMoveAnalysisへ復元する
実装が既にある。このため、同じチャート描画部を将来の棋譜レビュー画面でも
再利用できる。


===============================================================================
3. 評価値の視点を統一する
===============================================================================

CGOSの評価値は、その手を打った対局者が自分の手番で送った値である。
チャートの縦軸は「上が黒有利、下が白有利」に統一する。

黒番の着手:

  blackScore = rawScore
  blackWinAdvantage = rawWinrate * 2.0 - 1.0

白番の着手:

  blackScore = -rawScore
  blackWinAdvantage = -(rawWinrate * 2.0 - 1.0)

blackWinAdvantageは次の意味になる。

  +1.0 = 黒勝率100%
   0.0 = 五分
  -1.0 = 白勝率100%

重要:

  CGOSが返すscoreの正負およびwinrateの視点について、実際の通信ログまたは
  保存済みSGFで上記解釈を実装前に再確認すること。エンジンによって値が常に
  黒視点で送られる仕様なら、白番データの反転は行わない。

表示系列は視点を黒側へ正規化した後も、次の2本に分けたままにする。

  ・黒番が報告した評価値系列
  ・白番が報告した評価値系列

黒番と白番は交互に着手するため、同じ系列の隣接点は通常2手離れる。
折れ線は、黒系列同士、白系列同士だけを結ぶ。黒点と白点を1本の線で結ばない。


===============================================================================
4. 欠損値と異常値
===============================================================================

CGOSの全着手にScoreとWinrateが付くとは限らない。

  ・Scoreがnullの着手は縦棒を描かない
  ・Winrateがnullの着手は点を描かない
  ・Winrateの線は、欠損区間を無条件に接続せず、そこで切る方が安全
  ・解析情報全体がnullでも観戦画面を正常に描画する
  ・片方の対局者だけが評価値を送る対局にも対応する
  ・Passにも解析値があれば手数上の点として表示する

Scoreの表示範囲は初期値を-20～+20目とする案がある。ただし20目を超える値を
単純に捨ててはいけない。次のいずれかを採用する。

  案A: 描画だけ上下端へクランプし、端に超過マークを付ける
  案B: 20、40、80…の段階で自動的に軸を拡張する

初回実装は案Aの方が画面が安定する。ツールチップにはクランプ前の実値を出す。


===============================================================================
5. 画面レイアウト
===============================================================================

現在の仮想画面は1920×1080を基準に描画されている。
CGOS観戦画面では、おおむね左側1100pxが碁盤、右側760pxが情報パネルである。

現在の右パネルには以下が縦並びで置かれている。

  ・画面タイトル
  ・RULES
  ・PLAYERS
  ・FACTS
  ・ANALYSIS（最新手のみ）
  ・STATUSまたはRESULT/ACTION

モック画像は現行画面よりチャート領域が広い。そのまま座標を転記せず、右側
760pxの範囲へ適応させる。

推奨構成:

  上部:
    CGOS WATCH / RESULT、ゲーム番号、手数などのコンパクトな情報

  上～中央:
    黒白の対局者名、残り時間

  中央～下部:
    POSITION TREND統合チャート

  最下部:
    ライブ中は状態表示
    終局後は結果、KIFU REVIEW、SGF OUTPUT

RULESのBOARDとKOMI、FACTSのMOVESは独立した大きなセクションをやめ、横一列の
小さな情報バーへまとめるとチャート面積を確保できる。

現在のANALYSIS欄にある最新手のWINRATE、PV、SCORE、VISITSは完全には削除しない。
チャートの現在手ツールチップへScoreとWinrateを移し、PVとVisitsはチャート下の
細い行またはマウスオーバーツールチップで表示する。


===============================================================================
6. チャート描画仕様
===============================================================================

6.1 描画順

  1. パネル背景
  2. グリッドと左右の目盛り
  3. Winrateの黒系列・白系列（薄い背面）
  4. Scoreの黒棒・白棒（濃い前面）
  5. 0ライン
  6. 現在手カーソル
  7. 黒有利・白有利ラベル
  8. ツールチップと表示切替ボタン

6.2 Score

  ・左軸を使用
  ・+20、+10、0、-10、-20
  ・各着手を細い縦棒で表示
  ・0から評価値まで伸ばす
  ・黒番の棒はほぼ黒＋細いシアンの縁
  ・白番の棒はアイボリー＋細い暗色の縁
  ・BOTHモードでは不透明度85～90%程度

6.3 Winrate

  ・右軸を使用
  ・+100%、+50%、EVEN/0、-50%、-100%
  ・黒系列と白系列を別々に結ぶ
  ・BOTHモードでは不透明度20～30%程度
  ・黒線は暗色の芯＋シアン系の薄い縁またはグロー
  ・白線はアイボリーの芯＋暗色の縁
  ・線が交差または重なっても両系列を識別できるよう、縁を1～2pxずらして描く

6.4 表示切替

  SCORE:
    Score棒だけ表示

  BOTH:
    Winrate線を背面、Score棒を前面に表示（初期値）

  WIN RATE:
    Winrate線を通常の濃さで表示し、Score棒は非表示

状態を表すenum例:

  CgosTrendDisplayMode.Score
  CgosTrendDisplayMode.Both
  CgosTrendDisplayMode.WinRate

この状態は最初はGoAppSessionに保持すればよい。将来、ユーザー設定として永続化
するかは別課題とする。

6.5 横軸

初期実装では全着手をチャート幅へ収める。

  ・0～100手程度では手数をそのまま配置
  ・100手を超える場合は全手数をチャート幅へ圧縮
  ・現在手はライブ中なら末尾
  ・棋譜レビューへ再利用する場合はReviewMoveIndexを現在手とする

長手数では棒が1px未満になり得るため、最低1pxで描画し、同じX座標に重なる
場合の優先順位を決める必要がある。将来は横スクロールまたは表示範囲切替を
追加できるが、初回実装の必須要件にはしない。

6.6 ツールチップ

現在手またはマウスに最も近い着手について、次を表示する。

  MOVE 67
  B SCORE +6.0
  B WIN 63.0%

値がない項目は行ごと省略する。元データが白番視点の場合でも、表示値は
「黒有利を正」とした正規化後の値に統一し、B/Wはデータ送信者を示す。

7. 実装構成案
===============================================================================

描画コードがGoScreenRenderer.CgosWatching.csへ集中し過ぎないよう、チャートは
別partialファイルへ分ける。

追加候補:

  Presentation/Cgos/Watching/
    GoScreenRenderer.CgosTrendChart.cs

必要なら表示用データへの変換も分離する。

  Application/Cgos/Watching/
    CgosTrendPoint.cs
    CgosTrendSeriesBuilder.cs

CgosTrendPointの例:

  int MoveNumber
  GoStone Reporter
  double? BlackPerspectiveScore
  double? BlackPerspectiveWinAdvantage
  long? Visits
  string PrincipalVariation

描画側でCGOSプロトコル上の視点変換を行わないこと。変換ロジックは
CgosTrendSeriesBuilderへ集約し、単体テスト可能にする。

既存の矩形、枠、文字描画などはGoScreenRendererの共通処理を再利用する。
折れ線については、1×1テクスチャを回転・拡縮して2点間の線分を描く共通関数が
利用できるか確認する。既存関数がローカル画面専用ならShared側へ移す。


===============================================================================
8. 実装手順
===============================================================================

Phase 1: データ仕様の確認

  1. 実際のCGOS通信ログまたはSGFのKFAを数局分確認する
  2. 黒番・白番それぞれのwinrateとscoreの視点を確定する
  3. 欠損、Pass、終局直前のデータ例を確認する

Phase 2: 表示用モデル

  1. CgosTrendPointを追加する
  2. Movesから黒視点の表示値を作る変換処理を追加する
  3. 黒系列と白系列を分離できるようにする
  4. 視点変換と欠損処理の単体テストを追加する

Phase 3: チャート描画

  1. 固定のダミーデータで背景、軸、グリッドを描く
  2. Winrateの2系列を描く
  3. Scoreの黒白棒を描く
  4. 有利ラベル、現在手、ツールチップを描く
  5. 実際のobservation.Movesへ接続する

Phase 4: 右パネル再配置

  1. RULESとFACTSをコンパクトな情報バーにする
  2. PLAYERSを必要な高さに調整する
  3. POSITION TREND領域を確保する
  4. ライブ中と終局後の双方でボタンが重ならないことを確認する

Phase 5: 操作

  1. SCORE / BOTH / WIN RATEのヒット領域を追加する
  2. Game1.csのCGOS観戦画面クリック処理へ接続する
  3. 非アクティブウィンドウの最初のクリックでは操作されない既存仕様を守る
  4. 必要なら着手ホバーによるツールチップを追加する

Phase 6: 再利用

  ライブ観戦で安定した後、同じチャートを棋譜レビュー画面へ適用できるか検討
  する。最初から両画面を同時に変更して作業範囲を広げない。

9. テスト観点
===============================================================================

データ:

  ・黒白双方にScoreとWinrateがある
  ・黒だけに解析値がある
  ・白だけに解析値がある
  ・Scoreだけ、Winrateだけ、解析値なし
  ・Passに解析値がある
  ・Scoreが±20を超える
  ・Winrateが0%、50%、100%
  ・白番データの視点変換
  ・SGFへ保存後、再読込して値が一致する

描画:

  ・黒線と白線が交差する
  ・黒線と白線が同じ位置に重なる
  ・Score棒がWinrate線より前面に見える
  ・有利ラベルの左端と幅が揃う
  ・3つの表示モードが正しく切り替わる
  ・9路、13路、19路でレイアウトが変わらない
  ・ウィンドウ拡大縮小時にVirtualScreen変換が崩れない
  ・ライブ中に着手が追加されても例外やちらつきがない
  ・終局後にRESULT/ACTIONと重ならない

操作:

  ・表示切替ボタンの境界
  ・ウィンドウが非アクティブな状態での最初のクリック
  ・チャートのホバーと既存ボタンのヒット判定が干渉しない

ビルド:

  dotnet build KifuwarabeGo2026.slnx
