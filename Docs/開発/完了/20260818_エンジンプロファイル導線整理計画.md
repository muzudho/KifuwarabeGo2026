# エンジン・エントリープロファイル導線整理計画

## 目的

LocalMatch のプレイヤー欄をクリックした利用者が、エンジンそのものを選ぶ画面ではなく
エントリープロファイルの選択画面へ移動することで迷う問題を改善する。また、プロファイルを
準備する操作と、対局へ参加させる候補を選ぶ操作を分離する。

画面の役割を次のように分離する。

- タイトル画面: エンジンプロファイル管理とエントリープロファイル管理の入口をそれぞれ置く。
- エンジンプロファイル管理画面: エンジンの起動方法を登録・編集・複製・削除・並べ替えする。
- エントリープロファイル管理画面: 人間またはエンジンを対局候補として登録・編集・削除・並べ替えする。
- LocalMatch のエントリー選択画面: 登録済み候補を黒番・白番のプレイヤーへ割り当てるだけにする。

## 決定事項

1. タイトル画面に `ENGINE PROFILES` と `ENTRY PROFILES` の常設ボタンを追加する。
2. `ENGINE PROFILES` の補助文は `ADD / EDIT / REMOVE` とする。
3. `ENTRY PROFILES` の補助文は `PREPARE MATCH ENTRIES` とする。
4. LocalMatch から開く画面は `SELECT ENTRY` とし、登録済みエントリーの割り当てだけを行う。
5. LocalMatch の `SELECT ENTRY` からエントリーの追加・編集・削除・並べ替えへ進めない。
6. ［EDIT ENTRY PROFILE］の ENGINE 欄は残す。ここでは登録済みエンジンプロファイルの選択だけを行う。
7. エントリープロファイルから開いたエンジン選択画面では、`ADD`、`EDIT`、`DUPLICATE`、`DELETE`、`ORDER` を表示しない。
8. エンジンが0件の場合、タイトル画面の `ENGINE PROFILES` から登録するよう案内する。画面間リンクは置かない。
9. エントリーが0件の場合、LocalMatch にはタイトル画面の `ENTRY PROFILES` から登録するよう案内する。画面間リンクは置かない。
10. プロファイルの保存形式および既存データは変更しない。

「エントリープロファイルからエンジンプロファイル画面へ飛べない」とは、ENGINE 参照先を
選択する操作まで禁止する意味ではない。エントリー編集の途中からエンジンの作成・編集・削除へ
進めない、という責務分離を指す。

## 目標画面遷移

```text
TITLE
├─ Local Match
│  └─ SELECT ENTRY                  登録済み候補を黒番・白番へ割り当てるだけ
│
├─ ENTRY PROFILES
│  └─ ENTRY PROFILE MANAGEMENT     追加・編集・削除・並べ替え
│     └─ EDIT ENTRY PROFILE
│        └─ SELECT ENGINE (GTP)     登録済み項目の選択のみ
│
└─ ENGINE PROFILES
   └─ ENGINE PROFILE MANAGEMENT    追加・編集・複製・削除・並べ替え
```

各管理画面を閉じた場合はタイトル画面へ戻す。LocalMatch の選択画面から管理画面へ進む経路は設けない。
エントリープロファイル編集の ENGINE 欄からは選択専用画面だけを開き、エンジン管理へは進めない。

## 実装方針

### 1. GTPエンジン画面の用途を明示する

`GtpEngineSelectionPurpose` に管理専用の値（例: `Management`）を追加する。

用途ごとの操作を次のようにする。

| 用途 | エンジン選択 | ADD/EDIT/DUPLICATE/DELETE/ORDER | 閉じた後 |
| --- | --- | --- | --- |
| EntryProfile | 可能 | 不可 | EDIT ENTRY PROFILE |
| LocalMatch / CGOS / AppProvider | 現行仕様を維持 | 現行仕様を確認して維持 | 呼び出し元 |
| Management | 選択確定は不要 | 可能 | TITLE |

管理用途では対局アプリ互換性によって管理対象を無効化しない。互換性は「その用途へ選択できるか」の
情報であり、プロファイル自体を編集できるかどうかとは別である。

### 7. 用語を明確にする

画面と付箋では、次の区別を一貫させる。

- `ENTRY` / `ENTRY PROFILE`: 対局者になる前の候補。人間またはエンジンを対局へ参加させるための設定。
- `PLAYER`: LocalMatchやOnline Matchで黒番・白番などへ割り当てられ、対局者として確定したEntry。
- `ENGINE PROFILE`: GTPエンジンの実行ファイル、作業フォルダー、引数、オプションの設定。
- LocalMatch のプレイヤー欄: `ENTRY PROFILE` を選び、その対局の `PLAYER` として確定する場所。

コード中に歴史的な `PlayerProfile`、`PlayerSelection` という名前が残っていても、画面文言では
候補を `ENTRY`、割り当て済み対局者を `PLAYER` と呼び分ける。大規模なクラス名変更は今回必須と
しないが、新規APIとコメントでは可能な限りこの区別を反映する。

LocalMatch の選択画面には、必要に応じて次の案内を追加する。

```text
Select an entry profile for this player.
Computer entries use a registered engine profile.
```

### 8. アイコンの意味を分離する

アイコンは装飾ではなく、モデルの意味を示す共通語彙として使う。次の対応を正本とする。

| アイコン | 意味 | 主な使用場所 |
| --- | --- | --- |
| 黒石と白石 | `PLAYER`。マッチされ、黒番・白番などの対局者として確定した状態 | LocalMatchの対局者欄、対局画面、対局結果 |
| バストアップの人物シルエット（ワイヤーフレーム） | `ENTRY`。人間・エンジンのどちらにもなり得る対局候補 | `ENTRY PROFILES`入口、Entry一覧、`SELECT ENTRY` |
| 顔文字（ワイヤーフレーム） | 人間のEntryまたは人間Player | Entryの種類表示、割り当て後の補助表示 |
| ロボットの顔シルエット（ワイヤーフレーム） | GTPエンジン、Engine Profile、エンジンEntryまたはエンジンPlayer | `ENGINE PROFILES`入口、Engine一覧、ENGINE参照欄 |
| 碁盤のシルエット（ワイヤーフレーム） | GUIアプリケーション | GUI本体、更新、起動などのアプリ操作 |

運用規則:

1. 黒石・白石は人間／エンジンの種類を表さない。対局で確定した役割を表す。
2. バストアップシルエットは人間専用にしない。未確定のEntryという上位概念を表す。
3. Entry一覧ではバストアップを主アイコンとし、顔文字またはロボットを種別バッジとして併記できる。
4. Engine Profile一覧ではロボットを主アイコンとする。バストアップは使わない。
5. 碁盤アイコンをEngine ProfileやEntry Profileへ流用しない。
6. 同じ概念へ画面ごとに異なるアイコンを割り当てない。
7. 線幅、基準サイズ、通常色、ホバー色、無効色はStationeryUI側で共通化する。

現状の `KfwStationeryDrawingTools.DrawPlayerRoleFaceIcon(center, isComputer)` は、人間とロボットを
一つのAPIへまとめており、名前も「割り当て済みPlayer」に見える。次のような意味単位のAPIへ分割する。

- `DrawMatchedPlayersIcon` または同等: 黒石と白石。
- `DrawEntryIcon`: バストアップシルエット。
- `DrawHumanIcon`: 顔文字。
- `DrawEngineIcon`: ロボット顔。
- `DrawGuiIcon`: 碁盤。

対象候補:

`isComputer` の真偽だけを新APIへ移すのではなく、その場所がEntry、Player、Engine Profileの
どれを表しているかを確認して選ぶ。

## 実装順序

1. Player、Entry、Human、Engine、GUIのアイコンAPIを分離し、タイトル画面で使える状態にする。
2. `PlayerSelectionPurpose.Management` とEntry Profile管理画面を開閉するセッションAPIを追加する。
3. Entry選択ダイアログの描画・ヒット判定を選択用途と管理用途へ分ける。
4. `GtpEngineSelectionPurpose.Management` とEngine Profile管理画面を開閉するセッションAPIを追加する。
5. GTPエンジンダイアログの描画・ヒット判定を選択用途と管理用途へ分ける。
6. タイトル画面に `ENTRY PROFILES` と `ENGINE PROFILES` のボタン、アイコン、遷移を追加する。
7. 各選択用途から管理ボタンと新規作成への戻り処理を除去する。
8. 0件時および参照切れ時の案内を追加する。
9. 既存アイコン利用箇所を意味に合わせて段階的に置換する。
10. 自動テスト、手動UI確認、文書更新を行う。
