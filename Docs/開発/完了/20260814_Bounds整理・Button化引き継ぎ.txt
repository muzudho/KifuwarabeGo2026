［Rectangle *Bounds 整理・文房具 UI Button 化　引き継ぎ］

作成日：2026-08-14
対象：KifuwarabeGo2026.GameOasis.Gui の Presentation 層


■ 目的

画面内の操作ボタンについて、配置を表す Rectangle とクリック判定を別々に管理する構造を整理する。
ページまたはコンポーネントが文房具 UI の Button インスタンスを所有し、描画では Button.Bounds、
クリック判定では同じインスタンスの Button.IsHit(Point) を参照する構造へ段階的に移行する。

ただし、名前が *Bounds の Rectangle を一律に Button へ変換してはいけない。
パネル、ダイアログ、リスト、行、テキスト、チャート、ツールチップなどの純粋なレイアウト領域は
Rectangle のまま維持する。

■ 棚卸し結果

C# ソース全体から Rectangle 型の *Bounds 宣言を検索した結果は次のとおり。

   対象ファイル数：40
   *Bounds 宣言：約352件
   名前に ButtonBounds を含む宣言：約155件

この件数には、プロパティ、フィールド、動的な Bounds 計算メソッドが含まれる。

ButtonBounds 約155件は、次の3種類に分類する必要がある。

1. 未移行の操作ボタン
   Rectangle を Button インスタンスへ置き換える。

2. 既存 Button.Bounds の転送プロパティ
   新しい Button は作らず、呼び出し側を既存 Button へ直接つなぎ、転送プロパティを削除する。

3. 名前に Button が含まれていても、動的レイアウト計算や複合コントロールの一部であるもの
   Button、Button のコレクション、専用コンポーネントのどれが適切か個別に判断する。


■ 基本的な移行規則

移行前：

   private static Rectangle OkButtonBounds => new(...);
   public static bool IsOkButtonHit(Point point) => OkButtonBounds.Contains(point);

移行後：

   public Button OkButton { get; } = new(new Rectangle(...), "OK", 0.34f);

描画側：

   DrawCommandButton(
       page.OkButton.Bounds,
       page.OkButton.Label,
       ...,
       scale: page.OkButton.LabelScale);

クリック側：

   if (page.OkButton.IsHit(point))

有効条件がある場合は、Button.IsEnabled と描画条件を同期させることが理想である。
既存コードとの段階的移行中は、次のように外側の条件を維持してもよい。

   if (canSave && page.SaveButton.IsHit(point))

動的に位置や幅が変わる場合は、クリック判定の前にも Button.Bounds を現在の状態へ更新する。

■ Button 化しない Bounds

以下は、原則として Rectangle のまま維持する。

   BoardBounds
   ChartBounds
   DialogBounds
   PanelBounds
   ListBounds
   PropertyBounds
   RowBounds
   TextBounds
   TooltipBounds
   CredentialBounds
   OutputBounds
   CardBounds
   ContentBounds
   動的な描画領域を返す GetXxxBounds(...)

操作可能かどうかだけで判断せず、その Rectangle が「UI 部品そのもの」なのか、
「別の UI 部品を構成する内部レイアウト」なのかを確認する。


■ 各段階の確認項目

   □ 描画位置とサイズが移行前から変化していない。
   □ Button.Bounds と Button.IsHit が同じインスタンスを参照している。
   □ 無効なボタンをクリックできない。
   □ ラベルと LabelScale が移行前と一致している。
   □ 動的 Bounds がクリック前にも更新される。
   □ 不要な *ButtonBounds 転送プロパティを削除した。
   □ 不要な *ButtonHit / IsXxxHit ラッパーを削除した。
   □ ボタン以外の Rectangle を誤って Button 化していない。
   □ dotnet build KifuwarabeGo2026.slnx --no-restore が成功する。
   □ 主要なクリック操作を手動またはスモークテストで確認した。


■ 最終確認用の検索観点

   Rectangle 型の *ButtonBounds
   => SomeButton.Bounds となっている転送プロパティ
   *ButtonHit / Is*Hit ラッパー
   ボタン名を持つ Rectangle に対する Contains(point)
   DrawCommandButton に直接渡される新規 Rectangle

残った箇所は、未移行、意図的に維持、専用コンポーネント待ちのいずれかを明示する。


■ 作業上の注意

・作業ツリーには、この整理とは無関係なユーザーの未コミット変更が存在する可能性がある。
  git status と git diff を確認し、無関係な変更を戻したり上書きしたりしないこと。

・現在の GoScreenRenderer.Cgos.cs には、以前削除したメソッドに付いていた文字化けした XML コメントが
  残っている可能性がある。関連箇所を編集する際に、対象メソッドとの対応を確認して整理すること。

・Button.Draw への全面統一は、この計画の必須条件ではない。
  既存画面固有の描画表現を維持しながら、Button.Bounds と Button.IsHit だけを利用する段階的移行も可とする。

・一度に全画面を変更しない。上記の段階または画面単位で変更し、その都度ビルドすること。
