# ローカル対局再開始時強制終了修正計画

作成日: 2026年8月26日  
対象版: v4.0.4リリース後の開発版  
状態: 完了

## 目的

Local Matchで前局を終了してLobbyへ戻った直後に［START］を押すと、GUIが強制終了する不具合を修正します。

今回の作業では修正と検査までを行い、製品バージョンの更新、配布ZIPの生成、GitHub Releaseの作成は行いません。

## 確認できた現象

2026年8月26日の操作ログでは、次の順序が記録されています。

1. `00:05:15`にLocal MatchのPlay RoomからLobbyへ戻りました。
2. 前局のGame Oasisセッションを非同期で終了し始めました。
3. `00:05:27`に次局の［START］が押されました。
4. `LocalMatchGameOasisLifecycle.BeginStart`が開始要求を拒否しました。
5. `PlayingScene.StartPlaying`が`InvalidOperationException`を送出し、未処理のままGUIを終了させました。

記録された例外は次のとおりです。

```text
The available Game Oasis local-match lifecycle could not begin a session.
```

## 原因

Game Oasis方式のローカル対局ライフサイクルは、次の条件を満たす場合だけ次局を開始できます。

- 状態が`Idle`である。
- 非同期処理が進行中ではない。
- ライフサイクルが破棄されていない。

前局の終了中は状態が`Closing`、またはプレイヤーの参加解除処理が進行中です。しかしLobbyの［START］は、プレイヤー選択条件だけで有効になっており、ライフサイクルの終了待ちを開始条件に含めていませんでした。

また、この一時的な開始拒否を利用者へ通知できる状態として扱わず、プログラム構成不良と同じ未処理例外にしていました。

## 修正方針

### 1. 開始前にライフサイクルの準備状態を確認する

`LocalMatchGameOasisLifecycle`へ、次局を開始可能か問い合わせる読み取り専用プロパティを追加します。

前局の終了中に開始要求を受けても、セッションを`Playing`へ変更しません。

### 2. 一時的な開始拒否を通常の操作結果として扱う

`PlayingScene`の開始処理は、構成部品が欠けている場合には従来どおりプログラムエラーとして扱います。一方、ライフサイクルが`Closing`などの一時状態にある場合は、例外ではなく開始失敗を返します。

GUIは強制終了せず、前局の終了を待ってもう一度［START］を押すよう案内します。操作ログにも開始を保留したことを記録します。

### 3. 開始途中の失敗でもLobbyへ戻す

開始前検査を通過したあとで設定値などが拒否された場合も、`Playing`状態を残さずLobbyへ戻します。

## 回帰テスト

既存のGame Oasis GUI portability smokeへ、同じライフサイクルを連続利用する検査を追加します。

1. 一局目を開始できる。
2. 前局の終了処理中は二局目を開始できない。
3. 開始拒否でセッションが`Playing`へ変化しない。
4. 終了処理の完了後は二局目を開始できる。
5. 二局目も正常に終了して`Idle`へ戻る。

## 完了条件

- 前局終了中に［START］を押してもGUIが終了しない。
- 利用者に待機を案内するメッセージが表示される。
- 終了完了後はアプリを再起動せず次局を開始できる。
- 回帰テストがPASSする。
- ソリューションのReleaseビルドが警告0・エラー0で完了する。

## 今回行わないこと

- v4.0.5などへの版番号更新
- 配布ZIPおよびSHA-256の生成
- Gitタグ、GitHub Releaseの作成
- LobbyとPlay Roomの別実行ファイル化
- 対局中に記録された外部GTPエンジンの不正着手に対する別件修正

## 実施結果

2026年8月26日に次を実施しました。

- `LocalMatchGameOasisLifecycle`へ次局を開始可能か示す`CanStart`を追加しました。
- 前局終了中の［START］を例外にせず、Lobbyに留めて待機案内を表示するよう変更しました。
- 開始処理の途中でライフサイクルに拒否された場合も、セッションを`Playing`に残さないようにしました。
- 前局終了中の開始拒否、終了後の二局目開始、二局目終了をportability smokeで検証しました。
- portability smokeはPASSしました。
- Windows platform servicesの非対話スモークはPASSしました。
- ソリューション全体のReleaseビルドは警告0・エラー0で成功しました。
- 計画どおり、版番号更新、配布物生成、GitHub Releaseは行っていません。
