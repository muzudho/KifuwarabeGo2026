# プレイヤーエンジン実装ガイド

状態：プレースホルダー

## この文書の読者

Kifuwarabe Go 2026へ新しい［プレイヤーエンジン］、いわゆる［思考エンジン］を接続したい開発者を対象とします。ゲームルールや盤GUIではなく、与えられた状態から次の行動を選ぶ実装を扱います。

## 接続境界

プレイヤーエンジンとゲームオアシスはProtocol Pで接続します。

```text
GameOasis Concierge
  ↓ Protocol P
IPlayerProtocol
  ↓
プレイヤーエンジン
```

.NET実装の現在の契約は次にあります。

* `KifuwarabeGo2026.GameOasis.Contracts.ProtocolP.IPlayerProtocol`
* `KifuwarabeGo2026.GameOasis.Contracts.ProtocolP`の要求、応答、識別子。
* 参照調停実装：`KifuwarabeGo2026.GameOasis.Concierge.GameOasisPlayerCoordinator`。

GTPエンジンはProtocol Pの外部にあるため、GTPとの変換はFormalAdapterまたは参照アダプターが担当します。新しいプレイヤーがGTPを直接実装する必要はありません。

## 最小実装手順（予定）

1. エンジンの安定したID、表示名、Protocol版、能力を記述する。
2. `IPlayerProtocol`を実装する。
3. セッション開始時に割当てられたゲーム、役割、初期状態を受け取る。
4. 行動要求へ、ゲームが理解できる自己記述的な行動文書を返す。
5. 状態通知とセッション終了を処理する。
6. 異常入力、取消し、タイムアウト、二重要求を安全に扱う。
7. 将来追加するProtocol P適合性ランナーへ合格する。

## 実装してはいけない責務

* 行動の合法性を最終決定すること。これはPlay Room Engineの責務です。
* 勝敗や失格を裁定すること。これはルールまたはGame Master Engineの責務です。
* GUI、MonoGame、Lobbyの保存型を参照すること。
* 標準出力へ診断ログを混ぜること。別プロセス版では診断を標準エラーへ出します。
