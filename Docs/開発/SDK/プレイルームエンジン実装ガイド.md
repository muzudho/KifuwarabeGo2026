# プレイルームエンジン実装ガイド

状態：プレースホルダー

## この文書の読者

Kifuwarabe Go 2026へ新しい［プレイルームエンジン］、いわゆる［新しいゲームのルール］を追加したい開発者を対象とします。画面ではなく、設定、状態、行動、終局を所有する実装を扱います。

## 接続境界

プレイルームエンジンとゲームオアシスはProtocol Sで接続します。

```text
GameOasis Concierge
  ↓ Protocol S
IPlaySpaceProtocol
  ↓
プレイルームエンジン
```

現在利用できるSDKと検査資産は次のとおりです。

* `KifuwarabeGo2026.GameOasis.Contracts.ProtocolS.IPlaySpaceProtocol`
* `KifuwarabeGo2026.PlaySpace.JsonLines.PlaySpaceJsonLinesHost`
* `KifuwarabeGo2026.PlaySpace.Conformance`
* `Conformance/ProtocolS/v1`のJSON Schemaとベクトル。
* 最小例：`Samples/External.PlaySpace.Counter`。

## 最小実装手順

1. `IPlaySpaceProtocol`を実装する。
2. 設定Schema、設定検査、セッション生成、状態取得、行動適用、終了を実装する。
3. 状態と行動を安定した`ContractDocument.SchemaId`を持つJSONにする。
4. リビジョンによる楽観的同時実行制御を実装する。
5. `PlaySpaceJsonLinesHost.RunAsync(protocol)`で標準入出力Hostを公開する。
6. `*.playspace.json`マニフェストと適合性ベクトルを作る。
7. CLI適合性ランナーへ合格する。

詳細は既存の[`PlaySpace外部実装SDK.md`](./PlaySpace外部実装SDK.md)を参照してください。このプレースホルダーは、4役分割後に用語と配布単位を揃えた正式な入口へ拡張します。

## 実装してはいけない責務

* GUI、描画、入力デバイスを所有すること。
* Lobbyのカタログ、更新、インストールを所有すること。
* プレイヤーの思考アルゴリズムをルールへ埋め込むこと。
* Game Masterによる例外裁定を通常ルールへ混ぜること。
