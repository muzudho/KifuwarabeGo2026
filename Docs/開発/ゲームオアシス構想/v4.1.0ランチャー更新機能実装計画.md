# v4.0.1ランチャー更新機能実装計画

作成日: 2026-08-24  
対象版: v4.0.1（当初のv4.1.0予定から前倒し）  
状態: 実装済み・動作確認待ち  
関連文書: `v4.0.0プロジェクト再構成計画.md`

## 目的

コンシェルジュから共通ランチャーを安全にインストール・更新できるようにします。ランチャー自身には自己更新機能を持たせません。コンシェルジュが停止中のランチャーを更新し、ランチャーは従来どおりGUI／コンシェルジュと公式Engineを更新・復旧します。

利用者が所有する通常のWindowsショートカットを最大5件まで登録できるようにします。初回移行時は登録済みショートカットを一覧表示し、上から一件ずつ「更新しますか？」と確認します。利用者が［はい］または［いいえ］を選ぶたびに、その行の状態が更新される画面演出を製品仕様に含めます。

## 基本方針

更新関係は次の相互救済構造にします。

```text
ランチャー
  ├─ コンシェルジュを更新・復旧する
  └─ コンシェルジュを起動する

コンシェルジュ
  ├─ ランチャーを更新・復旧する
  ├─ ゲームスペースを管理する
  └─ プレイヤーエンジンを管理する
```

`LauncherUpdater.exe`や`LauncherUpdaterUpdater.exe`は作りません。更新処理はコンシェルジュのユースケースとWindows実装へ分離します。

ランチャーのOS所定フォルダーには、管理者権限を必要とする`Program Files`ではなく、利用者単位の`LocalApplicationData`を使用します。

```text
%LOCALAPPDATA%\KifuwarabeGo2026\
  Launcher\
    Current\
      KifuwarabeGo2026.Launcher.exe
      KifuwarabeGo2026.Launcher.dll
      その他の依存ファイル
    Previous\
      直前の正常版
    Versions\
      v4.0.0\
      v4.1.0\
  Downloads\
  launcher-settings.json
  launcher-shortcuts.json
  Logs\
```

通常のショートカットはすべて`Launcher\Current\KifuwarabeGo2026.Launcher.exe`を指します。初回移行後は`Current`の内容をコンシェルジュが更新するため、原則としてショートカットを版ごとに張り替えません。

## v4.0.0以前からの移行経路

v3.15.0およびv4.0.0のランチャーにはランチャー更新機能がありません。最初の移行は次の順序で行います。

1. 既存ランチャーの［GUI UPDATE］でGUI／コンシェルジュをv4.1.0へ更新します。
2. v4.1.0のGUI／コンシェルジュを起動します。
3. コンシェルジュの設定画面から［ランチャー更新］を開きます。
4. v4.0.1ランチャーを所定フォルダーへダウンロード、検証、配置します。
5. 利用者が最大5件の既存ショートカットを登録します。
6. 登録順に一件ずつ更新確認を行い、承認されたショートカットだけを固定入口へ変更します。
7. 新しい固定入口からランチャーを起動できることを確認します。

旧ランチャーのファイルと旧ショートカットは、固定入口の起動確認が完了する前に削除しません。v4.x.xの互換期間中は、旧ランチャーからのGUI／Engine更新も維持します。

## ランチャーパッケージの取得と検証

対象Release資産は次です。

```text
KifuwarabeGo2026.Launcher-v{version}-win-x64.zip
KifuwarabeGo2026.Launcher-v{version}-win-x64.zip.sha256
```

既存`Launcher.Core`がGUI／Engine更新で実施している安全規則を、ランチャー更新でも同じ意味になるよう再利用します。

1. GitHub Releasesのlatestから完全一致する資産名を選びます。
2. ZIPとSHA-256文書を一時作業フォルダーへ取得します。
3. SHA-256を照合します。ハッシュ資産がないReleaseは正式更新対象にしません。
4. ZIP Entryの正規化を行い、絶対パス、`..`、管理ルート外への展開を拒否します。
5. stagingへ展開します。
6. EXE、DLL、deps.json、runtimeconfig.jsonと必要な依存ファイルを検査します。
7. `KifuwarabeGo2026.Launcher.exe`のファイル版がRelease版と一致することを検査します。
8. 対象版を`Launcher\Versions\v{version}`へ確定します。
9. ランチャープロセスが停止していることを確認します。
10. 現在の`Current`を`Previous`へ退避し、新版を新しい`Current`として確定します。
11. 設定を一時ファイルから原子的に置換します。

ダウンロード、検証、展開の途中では`Current`を変更しません。ランチャーが起動中の場合は強制終了せず、「ランチャーを閉じてから再試行してください」と表示します。

## Current切替とロールバック

実行中のEXEを直接上書きしません。コンシェルジュはランチャー停止を確認した後、同一ボリューム上のディレクトリー切替で`Current`を更新します。

```text
Current.new       検証済み新版
Current           現在版
Previous          直前版
```

切替時は次の順序を守ります。

1. 古い`Previous`を、保護対象でないことを確認して整理します。
2. `Current`を一時的な退避名へ移します。
3. `Current.new`を`Current`へ移します。
4. 退避した旧`Current`を`Previous`へ確定します。
5. 新ランチャーを起動し、短時間の生存確認を行います。
6. 起動できなければ新版を隔離し、`Previous`を`Current`へ戻します。

電源断などで中間状態が残った場合は、次回のコンシェルジュ起動時に`Current`、`Current.new`、退避フォルダー、`Previous`を検査し、最後に検証済みだった版へ復旧します。

## ショートカット登録

管理対象は利用者が明示的に登録した通常のWindows `.lnk`ファイルだけです。最大件数は5件です。

登録方法は次の二つを用意します。

- ファイル選択ダイアログから`.lnk`を選ぶ
- デスクトップ、OneDriveデスクトップ、スタートメニューフォルダーから候補を検索し、利用者が選ぶ

候補検索は登録を補助するだけで、自動変更は行いません。タスクバーへピン留めした項目、スタート画面のピン、`.url`、シンボリックリンクはv4.1.0の管理対象外とします。

登録文書は、例えば次の形にします。

```json
{
  "schemaVersion": 1,
  "items": [
    {
      "id": "shortcut-1",
      "path": "C:\\Users\\user\\Desktop\\Kifuwarabe Go 2026.lnk",
      "displayName": "デスクトップ",
      "lastKnownTarget": "D:\\Games\\KifuwarabeGo2026.Launcher.exe"
    }
  ]
}
```

保存場所は`%LOCALAPPDATA%\KifuwarabeGo2026\launcher-shortcuts.json`とし、一時ファイルから原子的に保存します。パスの重複登録は大文字小文字を無視して拒否します。6件目を登録しようとした場合は、既存項目の解除を案内します。

## ショートカット更新の安全規則

ショートカット更新前に、対象を読み取り専用で検査します。

- 登録パスが通常ファイルとして存在すること
- 拡張子が`.lnk`であること
- 現在のリンク先が`KifuwarabeGo2026.Launcher.exe`であること
- 現在のリンク先が、登録時の旧リンク先またはGame Oasis管理下の既知ランチャーであること
- 新しい`Launcher\Current\KifuwarabeGo2026.Launcher.exe`が検証済みであること

利用者が登録後にショートカットを別アプリへ変更していた場合は、勝手に取り戻しません。その行を［対象変更済み］として失敗扱いにせず保留し、再登録を案内します。

更新時はリンク先と、旧ランチャーフォルダーを指している場合の作業フォルダーおよびアイコン位置だけを新しい固定入口へ変更します。引数、説明、ホットキー、表示方法など利用者の設定は維持します。一時`.lnk`を同じフォルダーへ保存して検証した後、元ファイルと置換します。

権限不足、OneDrive同期競合、ファイル消失、壊れた`.lnk`など、一件の失敗で後続項目を中止しません。各項目を独立して処理し、最後に結果をまとめます。

## 画面仕様

設定画面に［ランチャー更新］を追加し、次の状態を一画面で扱います。

```text
ランチャー更新

現在: v3.15.0（外部フォルダー）
最新: v4.1.0
配置先: %LOCALAPPDATA%\KifuwarabeGo2026\Launcher\Current

[最新版を取得して配置]

ショートカット
  1. デスクトップ       確認待ち
  2. OneDriveデスクトップ 確認待ち
  3. ゲームフォルダー    確認待ち
  4. 未登録
  5. 未登録

[ショートカットを追加] [登録解除] [順番に更新]
```

［順番に更新］を押した後は、未処理の一番上の項目を選び、次の確認を表示します。

```text
1. デスクトップ\Kifuwarabe Go 2026.lnk

リンク先を新しいランチャーへ更新しますか？

[はい] [いいえ] [中止]
```

回答ごとに一覧へ戻るか、一覧を背面に表示したまま次の行へ進みます。行の状態は次のいずれかへ即時更新します。

- `確認待ち`
- `更新中`
- `更新済み`
- `今回は更新しない`
- `ファイルが見つからない`
- `対象変更済み`
- `更新失敗`

状態変更時は短い効果音または文房具UIのスタンプ風表示を使用できます。ただし、利用者の回答前に次項目へ自動進行しません。［中止］は残りを`確認待ち`のまま残し、後から再開できるようにします。

全件終了後は、更新済み、スキップ、保留、失敗の件数を表示します。一部失敗しても新ランチャーの配置は取り消しません。少なくとも一件のショートカットが更新済みなら、［新しいランチャーを起動］を強調表示します。

## 責務とプロジェクト配置

コンシェルジュの概念責務をGUI巨大クラスへ直接実装しません。次の分割を目標とします。

```text
KifuwarabeGo2026.GameOasis.Application
  LauncherMaintenance/
    LauncherReleaseDescriptor
    LauncherInstallationState
    LauncherUpdateUseCase
    LauncherEntryRegistration
    LauncherEntryUpdateSession

KifuwarabeGo2026.GameOasis.Storage
  LauncherMaintenance/
    LauncherPackageStore
    LauncherEntryCatalogStore
    LauncherMaintenancePathProvider

KifuwarabeGo2026.GameOasis.Gui
  ランチャー更新画面、確認ダイアログ、進捗表示

KifuwarabeGo2026.GameOasis.Gui.Windows
  Windows .lnkの読込・作成・置換
  ランチャープロセス照会
  LocalApplicationDataとWindows候補場所の解決
```

ApplicationはMonoGame、Windows COM、`Environment.SpecialFolder`、物理ファイルへ依存しません。Windows `.lnk`操作は`IShellLinkW`／`IPersistFile`相当のOS境界へ隔離し、Applicationの試験では偽実装を使用します。

既存`Launcher.Core`の安全展開、SHA-256、版検査と同じ規則を二重実装しないことを優先します。ただし、Game Oasis ApplicationからLauncher製品のPresentationやPlatformへ逆参照しません。再利用できる純粋なパッケージ検証部品だけを、依存方向を確認した上で共有境界へ抽出します。

## クロスプラットフォーム拡張方針

v4.1.0の正式対象はWindows x64ですが、Application層では「Windowsショートカット」ではなく「ランチャー起動エントリー」として扱います。`.lnk`、`.desktop`、macOS固有形式などのファイル構造を共通モデルへ持ち込みません。

```text
Application
  LauncherEntryRegistration
  LauncherEntryInspection
  LauncherEntryUpdateSession
  ILauncherEntryService
  ILauncherInstallationPlatform
             ▲
             │ OS非依存契約
     ┌───────┼────────┐
     │       │        │
 Windows   Linux    macOS
 .lnk      .desktop  Alias／アプリ入口（将来調査）
```

Applicationが使用する起動エントリーの共通情報は、次の範囲に限定します。

- 安定した登録ID
- 利用者向け表示名
- OS実装だけが解釈する不透明な場所識別子
- 検査状態
- 現在のリンク先を表す正規化済み表示値
- 更新可否と、更新できない理由
- 確認待ち、更新済み、スキップ、保留、失敗などの処理状態

共通契約に`.lnk`パス、Windows COM型、Linuxデスクトップエントリーのキー、macOS BookmarkやAliasの型を追加しません。OS固有の読込結果は各アダプター内で保持し、Applicationへは共通状態だけを返します。

### OS別アダプターの責務

| 責務 | Windows v4.1.0 | Linux将来版 | macOS将来版 |
|---|---|---|---|
| 利用者単位の配置場所 | LocalApplicationData | XDG Base Directory準拠の場所 | Application Support配下の場所 |
| 起動エントリー候補 | 通常の`.lnk` | `.desktop`候補 | Alias、アプリケーション入口などを調査して決定 |
| リンク先の読込・変更 | Shell Link API | Desktop Entry仕様に従う実装 | 採用形式のOS APIに従う実装 |
| 実行中判定 | Windowsプロセス実装 | Linuxプロセス実装 | macOSプロセス実装 |
| 実行ファイル名 | `.exe` | 拡張子なしを基本 | `.app`構成または採用する配布形式 |
| Release資産 | `win-x64` | 対象RIDごとの資産 | 対象RIDごとの資産 |

macOSの更新対象をAlias、`.app`、Dock項目のどれにするかは、実装着手前にOSの正式な配布・署名・公証方式と合わせて調査します。Windowsの`.lnk`設計をそのままmacOSへ模倣しません。Linuxでもデスクトップ環境ごとの差異があるため、最初はFreedesktop準拠の通常`.desktop`だけを候補とし、各デスクトップ固有のピン留めは別能力として扱います。

### 能力による画面構成

Presentationは`OperatingSystem.IsWindows()`などで画面分岐しません。構成時に注入されたプラットフォーム能力を参照します。

```text
LauncherMaintenanceCapabilities
  CanInstallLauncher
  CanDiscoverLauncherEntries
  CanRegisterLauncherEntry
  CanRewriteLauncherEntry
  SupportsAutomaticRollback
  MaximumRegisteredEntries
  UnsupportedReason
```

未実装OSではボタンを消して処理を暗黙に無効化するのではなく、「このOSではランチャー起動エントリーの自動更新は未対応です」と理由を表示します。パッケージの取得・検証だけ対応できるOSでは、配置まで実行して手動入口作成を案内できるよう、能力を一つの真偽値にまとめません。

最大登録件数5件はv4.1.0の製品仕様としてApplicationが所有します。OSアダプターが件数や確認順序を独自に変更しません。一件ずつ［はい］［いいえ］を尋ねる状態機械も共通であり、OS実装は指定された一件を検査・更新して結果を返すだけです。

### 配置場所とRelease資産の抽象化

Application内に`%LOCALAPPDATA%`、`win-x64`、`.exe`を文字列として固定しません。プラットフォーム実装から、次をまとめた記述子を受け取ります。

- 管理ルート
- `Current`、`Previous`、`Versions`、一時作業場所
- 対象RID
- Release資産名
- 起動ファイルの相対パス
- ファイル版またはパッケージ版の検証方法
- プロセス起動・生存確認方法

ZIPの安全展開、SHA-256、staging、状態遷移は共通処理とし、パス比較規則、実行可能形式、署名、公証、実行権限などOS差がある検査だけをアダプターへ委譲します。

### プロジェクト分割の発展形

v4.1.0では既存構成を増やしすぎず、Windows実装を`KifuwarabeGo2026.GameOasis.Gui.Windows`の構成点から注入できます。ただし、OS固有クラスは`LauncherMaintenance/Windows`など明確な名前空間とフォルダーへ隔離します。

二つ目のOS実装へ着手する時点で、次のいずれかへ物理分割します。

```text
KifuwarabeGo2026.GameOasis.Platform.Windows
KifuwarabeGo2026.GameOasis.Platform.Linux
KifuwarabeGo2026.GameOasis.Platform.MacOS
```

または既存のOS別GUI起動プロジェクトが十分に薄い場合は、各`GameOasis.Gui.{OS}`を構成ルートとして維持します。どちらの場合もApplication／Storageの共通ユースケースをコピーせず、OSアダプターだけを追加します。

参照方向は必ず次を守ります。

```text
OS別起動・アダプター ──> GUI Presentation ──> GameOasis.Application
          │                                      ▲
          └────────────> GameOasis.Storage ──────┘
```

ApplicationからWindows、Linux、macOSの各プロジェクトを参照しません。Storageの共通文書形式もOS固有APIを参照しません。

### OSアダプター契約試験

共通の契約試験一式を作り、各OSアダプターへ同じシナリオを適用できるようにします。

- 候補の列挙が読取専用である
- 未登録項目を勝手に変更しない
- 現在のリンク先を検査できる
- 承認された一件だけを更新する
- 引数など、そのOSで維持対象とした属性を保存する
- 中断または失敗時に元の起動エントリーを壊さない
- 管理ルート外のパッケージファイルを変更しない
- 空白、非ASCII文字、長いパスを扱う
- 未対応能力が明示的な理由を返す

Windowsでは一時`.lnk`を使う結合試験を追加します。Linux／macOSを追加するときは、共通契約試験にそのアダプターを参加させ、各OS固有の実行・署名・デスクトップ統合試験を追加します。

## 実装段階

### 第1段階: 契約と非UI状態機械

- ランチャーRelease、インストール状態、更新結果の型をApplicationへ追加します。
- `Current`、`Previous`、`Versions`、stagingの状態遷移を定義します。
- 最大5件の登録、重複防止、順次確認、スキップ、中止、再開を持つショートカット更新セッションを追加します。
- ファイルシステム、Release取得、プロセス照会、起動エントリー操作をOS非依存インターフェースにします。
- 配置場所、RID、資産名、起動ファイル、版検査をプラットフォーム記述子から受け取るようにします。
- 対応能力と未対応理由を表す`LauncherMaintenanceCapabilities`を追加します。
- 偽実装によるApplication単体試験を追加します。

完了条件: Windows APIと画面なしで、5件の［はい］［いいえ］［中止］および部分失敗を決定的に再現できます。

### 第2段階: パッケージ取得と安全配置

- Launcher ZIPとSHA-256の取得を実装します。
- 安全展開、必須ファイル、ファイル版を検査します。
- ランチャー起動中の切替拒否を実装します。
- `Versions`への確定、`Current`切替、`Previous`退避、失敗時ロールバックを実装します。
- 中断状態からの復旧試験を追加します。

完了条件: 壊れたZIP、ハッシュ不一致、版不一致、切替失敗のどの場合も、旧ランチャーと既存ショートカットが壊れません。

### 第3段階: Windowsショートカット実装

- 共通`ILauncherEntryService`に対する、`.lnk`の読込、リンク先検査、保存をWindows実装へ追加します。
- 登録文書の読込、原子的保存、重複修復をStorageへ追加します。
- デスクトップ、OneDriveデスクトップ、スタートメニューフォルダーの候補探索を追加します。
- 空白、日本語、長いパスを含む一時ショートカットでWindows結合試験を追加します。

完了条件: 利用者設定を維持しながらリンク先を固定入口へ変更でき、無関係なショートカットを拒否できます。

### 第4段階: コンシェルジュ画面

- 設定画面へ［ランチャー更新］を追加します。
- 現在版、最新版、固定配置先、取得・検証・配置進捗を表示します。
- 最大5件の登録一覧と追加・解除を実装します。
