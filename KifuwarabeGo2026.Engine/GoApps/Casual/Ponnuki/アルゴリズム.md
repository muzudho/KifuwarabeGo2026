## 思考の流れ

`PonnukiStrategy.GenerateMove` は次の順に処理します。

```text
全交点を走査
  ↓
合法手だけを候補にする
  ↓
各候補を着手後の盤面で評価する
  ↓
最高優先度の手だけを残す
  ↓
残った手から選ぶ
```

### 1. 合法手の収集

`LegalMoveCandidates.Collect` がすべての交点を走査します。

- `GoBoard.TryPlaceStone` で、着手禁止点・自殺・コウを含む合法性を確認する。
- 合法手ごとに、着手後の盤面 `BoardAfterMove` と捕獲石数 `CapturedStones` を保存する。
- `GenerateMoveRequest.AvoidEyes` が有効なら、自分の眼への着手は候補から除く。

候補が一つもなければ `null` を返し、GTP 側ではパスとして扱われます。

### 2. 候補手の評価

`PonnukiMovePrioritizer.Evaluate` は、着手後の自連を調べ、優先度を次の 2 項目で作ります。

```text
優先度 = (CapturedStones, ContestedContactPriority)
```

比較は左の項目を最優先する辞書順です。

1. `CapturedStones` — 今回取れる相手石の数。多いほど優先。
2. `ContestedContactPriority` — 相手に接していて、面積評価が拮抗する自連を優先する度合い。

`ContestedContactPriority` は Strong Analyzer の評価値を使い、次の規則です。

| 条件 | 値 |
| --- | ---: |
| 相手連に接触しない | `0` |
| 自連の面積 == 隣接する全相手連の面積の合計 | `1` |
| 面積が等しくない | `0` |

ここでの面積は、連に含まれる石の数です。つまり、まず「多く取れる手」を選び、捕獲数が同じなら「相手に接し、相手連の合計と拮抗している自連」を優先します。これはノビの形そのものを検出する規則ではありません。

### 3. 同順位の手を選ぶ

最高優先度が同じ手はすべて残します。`MoveSelector.Select` がその中から 1 手を選びます。

- `MoveSelectionMode.Normal`: 乱数で 1 手を選ぶ。
- `MoveSelectionMode.ChebyshevDistanceFromStar`: 星からの距離を使う選択器へ委譲する。

そのため、同じ局面でも乱数シードや選択モードによって着手が変わることがあります。

## ポン抜きゲーム固有のルール

`GtpEngine.Ponnuki.cs` は思考そのものとは別に、Casual App のゲーム進行を管理します。

- 初期局面は、指定手数までランダムな合法手を交互に置いて作る。
- 捕獲石数を黒白別に累計する。
- どちらかが **20 子** 捕獲するとゲーム終了とする。

## 改造の入口

目的別に、次の場所を変更します。

| 変えたいこと | 主な変更先 |
| --- | --- |
| 捕獲を最優先する順序 | `PonnukiMovePriority.CompareTo` |
| 面積比較・接触評価の条件 | `PonnukiMovePrioritizer.Evaluate` |
| 眼を避けるか | `GenerateMoveRequest.AvoidEyes` を設定する呼び出し側 |
| 同順位のランダム選択 | `MoveSelector` または選択モード |
| 初期局面の作り方 | `GtpEngine.Ponnuki.ExecuteMakePosition` |
| 終局に必要な捕獲数 | `GtpEngine.Ponnuki` の `PonnukiCaptureTarget` |

Board Lens の `Strong Lens` と Shared の `StrongAnalyzer` は「自連の面積 − 隣接する全相手連の面積」を返します。値が `0` の接触手が `ContestedContactPriority` の対象です。この判定はノビの形そのものを検出するものではありません。
