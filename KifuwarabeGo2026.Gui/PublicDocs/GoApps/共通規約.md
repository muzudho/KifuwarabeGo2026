# Go Apps共通規約

## 1. アプリID

アプリIDは、相互運用するアプリの種類を表す小文字の識別子です。

```text
go-play
ponnuki
```

アプリIDへエンジン名、作者名、プロトコル名を接頭辞として付けません。例えば、ポン抜きのアプリIDは`ponnuki`であり、`kfw-ponnuki`ではありません。

> **引用用要件：アプリID**  
> アプリIDは特定実装の所有者を表さず、相互運用するアプリの種類を表す。同じアプリIDを名乗る実装は、そのIDで普及しているプロトコルとの互換性を維持しなければならない。

## 2. エンジンの役割

Go Appsでは、アプリIDに加えてエンジンの役割を区別します。

| 役割 | 識別子 | 主な責務 |
|---|---|---|
| Player | `player` | 盤面を受け取り、次の着手を生成する |
| Provider | `provider` | 初期局面の生成、着手の監視、アプリ固有の終局判定を行う |

対象用途は、`ponnuki player`、`ponnuki provider`のように「アプリIDと役割」の組で表します。

> **引用用要件：役割**  
> PlayerとProviderは独立した役割である。Playerは着手生成を担当し、Providerはアプリ固有の局面や進行判定を担当する。一つのエンジンが両方へ対応することは必須ではない。

## 3. 通信方式

Go Appsのエンジンは、標準入力でコマンドを受け取り、標準出力へGTP形式の応答を返します。

成功応答は`=`、失敗応答は`?`で始め、最後に空行を出力します。

```text
= response body

? error message

```

JSONを返すコマンドでも、JSONだけを出力するのではなく、GTP成功応答の本文として出力します。診断メッセージを標準出力へ混入させることは禁止します。ログが必要な場合は標準エラーなど、GTP応答を壊さない出力先を使用します。

## 4. 能力確認

エンジンはGTP Version 2の`known_command`と`list_commands`へ正しく応答してください。対応するKFW拡張コマンドは`list_commands`へ含め、`known_command <command-name>`へ`true`を返します。

```text
> known_command kfw-make-position
= true

> known_command kfw-listen-move
= true
```

未対応のコマンドを受け取った場合は、成功したように見せずGTPエラーを返してください。

> **引用用要件：能力確認**  
> エンジンは対応する拡張コマンドを`list_commands`で公開し、`known_command`へ正しく回答しなければならない。GUIはコマンドを使用する前に能力を確認する。

## 5. コマンド名

KifuwarabeGo2026で提案された独自GTP拡張は、標準GTPコマンドと区別するため`kfw-`接頭辞とkebab-caseを使用します。

```text
kfw-make-position
kfw-listen-move
kfw-begin-position
kfw-add-black
kfw-add-white
kfw-set-to-play
kfw-commit-position
kfw-abort-position
```

`kfw-`はプロトコルの名前空間です。第三者のエンジンも、同じ意味と応答形式を実装する場合は同じコマンド名を使用できます。

## 6. エラー処理

引数の個数、アプリID、バージョン、座標、値が不正な場合、エンジンは理由を含むGTPエラーを返します。不正な要求を黙って受理したり、成功応答の中にエラーを埋め込んだりしてはいけません。

GUIが処理を継続できるよう、エラーが起きたコマンドで盤面や進行状態を途中まで変更しない設計を推奨します。指定局面の受け渡しでは、[ポン抜きPlayer](Ponnuki/Player.md)に記載する原子的指定局面コマンドを使用します。
