# Go Apps実装リファレンス

> 対応バージョン：KifuwarabeGo2026 v3.3.0<br>
> 記事の更新日：2026-08-02

Go Appsは、囲碁の着手生成だけでなく、局面生成、問題、練習ゲーム、アプリ固有の終局判定などをGTPエンジンとGUIの組み合わせで実現するための仕組みです。

このリファレンスは特定のエンジンの内部実装を説明するものではありません。自分のエンジンをGo Appsへ接続したい作者が、必要なコマンドと応答をすぐ確認できることを目的とします。

## 最初に読む文書

1. [共通規約](共通規約.md) — アプリID、役割、GTP応答、能力確認
2. [Play](Play/README.md) — 通常の対局を行うGTPエンジンの実装
3. [Ponnuki](Ponnuki/README.md) — ポン抜きへ対応するProviderとPlayerの実装

## 最小の実装経路

エンジンを動かしながら一段ずつ確認する場合は、次の順序で実装します。

1. GTP成功応答と失敗応答を返せるようにする。
2. `protocol_version`、`name`、`version`を実装する。
3. `known_command`と`list_commands`を実装する。
4. `kfw-list-apps [player|provider]`を実装し、role別の対応アプリIDを返す。
5. 実装するアプリとroleを一つ選ぶ。
6. 選んだroleの必須コマンドを実装する。
7. 必要であれば、エンジンオプションを実装する。

各段階でエンジンを単体起動し、その段階までのコマンドへ正しく応答できることを確認してから次へ進んでください。`kfw-list-apps`の具体的な実装と確認方法は、[共通規約の実装フロー](共通規約.md#最初から順に実装する)に記載します。

ポン抜きはGo Appsの参照実装用アプリです。新しい実装では、目的に応じて次のどちらかから始められます。

- 局面を作り、アゲハマと勝敗を判定したい場合は、`ponnuki provider`を実装します。
- 与えられた局面で着手を生成したい場合は、`ponnuki player`を実装します。

ProviderとPlayerは別の役割です。一つの実行ファイルが両方へ対応しても、片方だけへ対応しても構いません。

通常の囲碁対局へ参加するエンジンを作りたい場合は、[Play](Play/README.md)から始めます。従来画面の`Go Play`とGo Appsの`Play`は同じアプリです。

## 安定性

ここに掲載するコマンドは、現在の公開実装を基準とします。検討中のコマンドは掲載しません。互換性を壊す変更が必要な場合は、アプリの対応バージョンを区別して移行できる形を優先します。
