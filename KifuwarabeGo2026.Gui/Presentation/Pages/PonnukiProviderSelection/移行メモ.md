# ポン抜きプロバイダー選択画面の独立化

## 現状

`PonnukiProviderSelectionScreen.cs` は作成済みです。画面が所有するレイアウトは次のとおりです。

- `Headline`、`ProviderLabel`（文房具 UI の `Headline`）
- `ProviderDisplayBounds`、`ProviderTextBounds`、`CapabilityStatusBounds`
- `BackButton`、`RecheckButton`、`StartButton`（文房具 UI の `Button`）

ヒット判定用の矩形は `GoScreenRenderer` からこのインスタンスのプロパティを参照しています。

## 完了した移行

描画本体はまだ次のメソッドに残っています。

`Presentation/Pages/Title/GoScreenRenderer.Title.cs` の
`DrawPonnukiProviderSelection`、`DrawAppProviderLoadingSpinner`、`DrawAppProviderTabHints`。

これらは `PonnukiProviderSelectionScreen` の `Draw` メソッドへ移しました。`GoScreenRenderer` 側は仮想座標へ変換済みのマウス位置と描画コールバックを渡す薄い呼び出しです。

## 描画コールバック

画面クラスへ渡す専用インターフェースまたはコールバックには、少なくとも次が必要です。

- 通常・動的・フィット文字の描画
- 線の描画（ローディングスピナー用）
- コマンドボタン、タブ移動ヒントの描画
- 付箋の描画
- `LinkUnderline` と `ActionBadge` の描画面

`PonnukiProviderSelectionDrawingCallbacks` がこの機能を表します。`GoScreenRenderer` は既存の描画メソッドをコールバックとして渡し、画面クラスは `GoScreenRenderer` 型そのものへ依存しません。

## 互換性

タイトル画面からの遷移・クリック判定を保つため、既存の `TitleRenderer` 公開 API は維持しています。各 API は
`PonnukiProviderSelectionScreen.Default` の `Button.Bounds` を判定に使います。
