# ポップアップテキストボックスのアルゴリズム

## 用途

GTP エンジンの GUI オプションのうち、`string` 型の値をゲーム内で編集するモーダル入力画面である。
OS のネイティブ入力ダイアログは使わず、数値ポップアップと同じ描画・操作モデルを採用する。

## 処理の流れ

1. `string` 型オプションの EDIT を押すと、現在の下書き値で `TextBoxController` を初期化して開く。
2. 共通テキストボックスが文字入力、選択、コピー・切り取り・貼り付け、undo/redo、キーリピートを処理する。
3. 入力欄のクリック・ドラッグは、文字幅から変換したキャレット位置をコントローラーへ渡して選択を更新する。
4. DEFAULT は入力欄を既定値へ戻す。Enter または OK ではテキストを下書きへ保存する。Escape または CANCEL では保存せず閉じる。

## 表示と制限

`PopupTextBox.cs` は暗幕付きの単一行入力欄、選択ハイライト、キャレット、OK/CANCEL を描画する。
`showDefaultButton` を指定した呼び出しだけ、DEFAULT ボタンも表示する。
入力欄は文字サイズに少量の余白を加えた高さにし、複数行入力ではないことを見た目でも示す。
最大文字数は `GtpEngineGuiOptions.MaximumTextLength`（現在 10,000）で、上限に達した追加入力時はメッセージを表示する。

値の妥当性は文字列型オプションに固有のルールがある場合に、呼び出し側またはエンジン側で扱う。現在の `EngineTag` は文字列型操作のデモ用プロパティであり、追加の内容検証は行わない。

## 日本語 IME

現在の実装は MonoGame の `TextInput` イベントで受け取る**確定後の文字**を編集欄へ追加する。
そのため、IME の変換途中の文字列や下線は入力欄には描画されず、確定後にだけ表示される。
変換途中の表示までゲーム内で再現するには、OS ごとの IME composition API を受け取り、未確定文字列を別途描画する実装が必要になる。

Windows 版では `WindowsTextCompositionService` が `WM_IME_COMPOSITION` を受け取り、
`ImmGetCompositionStringW` から未確定文字列と IME 内キャレット位置を取得する試作を実装している。
ポップアップはその文字列を黄色と下線で描画し、確定済みの文字列とは区別する。
非 Windows 環境では空の composition サービスを渡すため、未確定文字列は描画されず、確定文字だけが従来どおり入力される。

試作の動作確認用に、ポップアップ右上へ診断ランプを表示する。`SDL` は SDL ウィンドウから HWND を取得できた状態、`HOOK` は Win32 のウィンドウ手続きをフックできた状態、`IME` は未確定入力中を表す。SDL と HOOK は緑、IME は黄色で点灯する。
