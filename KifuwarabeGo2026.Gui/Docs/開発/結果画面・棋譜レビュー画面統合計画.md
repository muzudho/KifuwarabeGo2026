# 結果画面・棋譜レビュー画面統合計画

最終更新: 2026-08-15

## 目的

ローカル対局終了後の独立した［結果画面］を廃止し、［棋譜レビュー画面］のタイムライン終端に `RESULT` を追加する。

対局終了時は統合後の棋譜レビュー画面を直接開き、最初から `RESULT` を表示する。利用者は一手戻せば最終着手後の盤面を確認でき、終端へ進めばいつでも結果表示へ戻れるようにする。

```text
初期局面 ─ 1手目 ─ … ─ 最終手 ─ RESULT
   0          1             N       N+1
```

`RESULT` は棋譜上の架空の一手ではない。棋譜の `Moves.Count`、着手コメント、形勢グラフのインデックスには含めず、レビューUI上の終端状態として扱う。

## 対象範囲

第一対象はローカル対局の `GoAppModeKind.GameOver` と `GameOverRightSidePanel` である。

CGOSの `CgosConnectionFlowKind.Result` は通信対局固有の保存・通知・観戦状態を持つため、同じ見た目であっても本計画で同時に削除しない。ローカル統合後に共通化できる範囲を別途判断する。

## 現在地

### 現在の結果画面

- 終局時に `GoAppModeKind.GameOver` へ遷移する。
- `RightSidePanel` は `GameOverRightSidePanel` を描画する。
- `LocalMatchScreen` が次の結果画面用部品を所有する。
  - `ReturnToSetupButton`
  - `ExportSgfButton`
  - `GameOverReviewButton`
  - `GameOverRightSidePanel`
- `GameOverRightSidePanel` は結果、プレイヤー、チャート、SGF出力、棋譜レビュー入口を表示する。
- ［KIFU REVIEW］を押すと `StartReviewingGameRecord(CurrentGameRecord.Clone(), ...)` を呼ぶ。

### 現在の棋譜レビュー画面

- `ReviewMoveIndex` の範囲は `0..ReviewMoveCount` である。
- `ReviewMoveCount` は `_reviewGameRecord.Moves.Count` と同じである。
- `MoveReview` は移動先を `0..ReviewMoveCount` にクランプする。
- `ReviewMoveNavigation` は `ReviewMoveCount` を最大値としている。
- 最終手では正方向ボタンが無効になる。
- 表示は `STEP {ReviewMoveIndex} / {ReviewMoveCount}` である。
- `ApplyReviewPosition` は指定手数まで棋譜を再生し、盤面、アゲハマ、手番、使用時間を復元する。
- ［BACK TO HOME］は `ReturnFromReviewingToResting()` を呼び、結果画面へは戻らない。

## 基本設計

### レビュー位置と結果位置を区別する

単純に `ReviewMoveCount` を1増やすだけにはしない。次のいずれかの明示的なモデルを導入する。

推奨案:

```csharp
public enum ReviewTimelinePositionKind
{
    Move,
    Result,
}

public readonly record struct ReviewTimelinePosition(
    ReviewTimelinePositionKind Kind,
    int MoveIndex);
```

またはセッションに次の状態を持たせる。

```csharp
public bool IsReviewResultPosition { get; }
public int ReviewTimelineIndex =>
    IsReviewResultPosition ? ReviewMoveCount + 1 : ReviewMoveIndex;
public int ReviewTimelineMaximum => ReviewMoveCount + 1;
```

実装量が少ない後者でもよいが、`ReviewMoveIndex == ReviewMoveCount + 1` を許容して盤面再生メソッドへそのまま渡す設計は避ける。

### RESULT位置の盤面

- 盤面は最終手まで再生した状態を表示する。
- 終局直前に確定した `Winner`、`GameOverReason`、`CurrentGameRecord.Result` を保持して表示する。
- 結果位置へ移動しても、棋譜の着手数や現在コメントの添字を変更しない。
- 結果位置から一手戻した場合は `ReviewMoveCount`、つまり最終手位置へ移動する。
- 最終手位置から一手進めた場合は `RESULT` へ移動する。

### 対局終了時の遷移

終局処理の順序を次のようにする。

1. 勝者、終局理由、SGF結果を確定する。
2. エンジン停止、時計停止、自動保存、終局音など既存の終局処理を完了する。
3. `CurrentGameRecord` をレビュー用正本として確定する。
4. 統合棋譜レビュー画面へ遷移する。
5. レビュータイムラインを `RESULT` に合わせる。

終局処理の条件に現在 `GoAppModeKind.GameOver` を使っている箇所があるため、表示統合とモード削除を同時に行わない。まず `GameOver` を内部の短命な終局処理状態として残し、終局処理完了後に `Reviewing` へ遷移させる。
