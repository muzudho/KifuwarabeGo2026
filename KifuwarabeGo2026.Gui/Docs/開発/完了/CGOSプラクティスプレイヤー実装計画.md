# CGOS プラクティスプレイヤー実装計画

更新日: 2026-08-21

実装状態: 完了

## 実装結果

- CGOS 接続画面の表示名を `PRACTICE PLAYER` へ変更した。
- プラクティスプレイヤーのログ出力先を `PracticePlayer` とした。
- プレイヤー1用とプラクティスプレイヤー用に、独立した
  `CgosGameObservation` を保持するようにした。
- 両接続が同じゲームIDを報告した場合は練習対局と判断し、プレイヤー1側の
  観戦状態だけを残して重複適用を防ぐ。

- うっかり対局終了時は、SGF自動保存が有効なら
  `unexpected-practice-` 接頭辞付きで保存する。
- 盤分離、参加者判定、投了確認状態、盤リセットのスモークテストを追加した。

## 1. この文書の目的

CGOS 接続画面に現在ある「プレイヤー2」を、練習相手として待機させる
「プラクティスプレイヤー」として明確に定義する。

プラクティスプレイヤーがプレイヤー1以外と意図せずマッチングした場合でも、
メインの CGOS 対局盤を壊さず、内部の「うっかり対局盤」で対局状態を保持し、
GUI から安全に投了できるようにする。

人間プレイヤー対応より先に、この複数対局の振り分け基盤を実装する。

## 2. 用語

| 用語 | 意味 |
| --- | --- |
| プレイヤー1 | GUI が主として操作・観戦する CGOS プレイヤー。将来 HUMAN/ENGINE を選べるようにする。 |
| プラクティスプレイヤー | プレイヤー1の練習相手として接続するエンジン専用プレイヤー。旧称プレイヤー2。 |
| メイン対局 | プレイヤー1が参加している、GUI に表示する対局。 |
| 練習対局 | プレイヤー1とプラクティスプレイヤーが互いにマッチングした対局。メイン対局として表示する。 |
| うっかり対局 | プラクティスプレイヤーがプレイヤー1以外とマッチングした対局。GUI に盤を表示しない。 |
| うっかり対局盤 | うっかり対局を内部的に保持する盤・棋譜・時計・参加者などの状態一式。 |

## 3. 現状と問題

- プレイヤー1側と旧プレイヤー2側は、別々の CGOS 通信プロセスとして接続する。
- 両プロセスは別々の相手とマッチングする可能性がある。
- `Game1` は現在、単一の `_cgosGameObservation` を持つ。
- `UpdateCgosGameObservation()` は両通信プロセスの出力を、その単一状態へ渡す。
- 旧プレイヤー2専用の盤状態は存在しない。
- 別対局の `setup`、`play`、`gameover` が混ざると、正常な同時管理ができない。

## 4. 目標仕様

### 4.1 表示名

GUI 上の「Player 2」「プレイヤー2」は、原則として
「Practice Player」「プラクティスプレイヤー」へ変更する。

内部の `White`、`Player2` という名前は、一括変更によるリスクを避けるため、
通信上の色・既存保存形式・互換性を確認しながら段階的に変更する。
特にプラクティスプレイヤーは実際の対局で白になるとは限らないため、
新規コードでは役割名と石色を分離する。

### 4.2 盤状態

最低限、次の2つの独立した CGOS 対局状態を持つ。

```csharp
private readonly CgosGameObservation _primaryCgosGame = new();
private readonly CgosGameObservation _practiceUnexpectedGame = new();
```

- `_primaryCgosGame`: プレイヤー1の対局を保持し、GUI に表示する。
- `_practiceUnexpectedGame`: プラクティスプレイヤーだけが参加している別対局を保持する。

変数名は実装時に既存命名規則へ合わせて調整してよい。

「盤」は `GoBoard` だけを指さない。ゲームID、参加者、手順、時計、結果、
担当色、投了状態を含む `CgosGameObservation` 相当の対局状態全体を指す。

### 4.3 振り分け

通信ログを接続元とゲームID付きのイベントとして扱う。

```text
プレイヤー1接続から受信した対局
    -> メイン対局

プラクティス接続から受信し、対戦相手がプレイヤー1
    -> メイン対局（練習対局）

プラクティス接続から受信し、対戦相手がプレイヤー1以外
    -> うっかり対局
```

判定には `setup` のゲームIDと参加者名を使う。
参加者名はランク表記を除去し、大文字・小文字を無視して比較する。
表示名ではなく、実際に接続へ使用したログイン名を比較元とする。

同じゲームIDを両接続が報告する練習対局では、同じ着手を重複適用しない。
イベントの一意性を、少なくともゲームID、手数、手番、着手座標で確認する。

### 4.4 うっかり対局の GUI

うっかり対局の盤面そのものは表示しない。CGOS 接続画面に状態欄を設ける。

表示候補:

```text
PRACTICE PLAYER
STATUS: UNEXPECTED MATCH
OPPONENT: ExampleBot
COLOR: WHITE
MOVE: 37
TIME: 08:42

[PRACTICE RESIGN]
```

日本語表示を採用する場合、ボタン名は
「プラクティスプレイヤー投了」とする。

### 4.5 投了

- うっかり対局が進行中のときだけ投了ボタンを有効にする。
- 押下時に確認ダイアログを表示する。
- 確認画面に対戦相手、ゲームID、プラクティスプレイヤーの担当色を表示する。
- 確認後、プラクティスプレイヤーの通信プロセスだけへ `resign` を送る。
- メイン対局側の通信プロセスへは送らない。
- 二重送信を防ぐため、投了要求後はボタンを無効にして `RESIGN REQUESTED` と表示する。
- `gameover` を受信するまで、うっかり対局状態を保持する。
- 終局ログと SGF の保存後に、次の対局を受け付けられる状態へ戻す。

既存の `SendCgosPlayerResign(GoStone stone)` は石色を接続役割のように扱っている。
新規処理では `CgosPlayerRole.Primary` / `CgosPlayerRole.Practice` のような役割を
導入し、通信プロセスの選択と対局中の実際の石色を分離することを推奨する。

## 5. 状態遷移

```text
DISCONNECTED
    -> CONNECTING
    -> WAITING
    -> MATCHED_WITH_PRIMARY       -> MAIN GAME
    -> MATCHED_WITH_OTHER_PLAYER  -> UNEXPECTED GAME

UNEXPECTED GAME
    -> RESIGN REQUESTED
    -> GAMEOVER RECEIVED
    -> SAVE LOG/SGF
    -> WAITING または DISCONNECTED
```

切断時は、進行中の対局状態を即座に消さない。切断理由と、その時点までの棋譜を
保存して `CONNECTION LOST` として終了させる。

## 6. 実装段階

### 第1段階: 呼称と役割の導入

- GUI 表示を「プラクティスプレイヤー」へ変更する。

- 既存の黒用・白用プロセス参照を、主プレイヤー用・練習用として参照できる
  境界を作る。
- 保存設定の互換性を維持する。

### 第2段階: 対局イベントの構造化

- 標準出力の文字列を直接1盤へ渡す処理を整理する。

- 古いゲームIDの遅延イベントを破棄できるようにする。

### 第3段階: 2つの CGOS 対局状態

- メイン対局状態とうっかり対局状態を分離する。
- プレイヤー1の対局だけを観戦画面へ渡す。
- 練習対局の重複ログを二重適用しない。
- うっかり対局を表示せずに最後まで追跡する。

### 第4段階: 状態表示と投了

- プラクティスプレイヤー状態欄を追加する。
- 投了確認ダイアログを追加する。
- プラクティス接続だけへ投了を送る。
- 終局後にログと SGF を保存する。

### 第5段階: 人間プレイヤー対応への接続

- プレイヤー1へ HUMAN/ENGINE 選択を追加する。
- 人間名の `_human` 補完を追加する。
- 人間着手待機をメイン対局だけで扱う。
- うっかり対局は人間の盤入力を占有しない。

## 8. 安全条件

- 投了コマンドには対象の接続役割と期待ゲームIDを指定する。
- 通信プロセス側でも、期待ゲームIDが現在対局と一致しなければ投了を拒否する。
- 対局中の再接続や次局開始で、古い投了要求を次局へ適用しない。
- プラクティス側の異常がメイン対局の盤、時計、棋譜、投了へ影響しない。
- パスワードをイベント、画面、通常ログへ出力しない。

## 9. 受け入れテスト

1. プレイヤー1だけを接続し、従来どおり対局を表示できる。
2. プラクティスプレイヤーだけを接続し、待機状態を表示できる。
3. 両者が互いにマッチングし、1つのメイン盤へ重複なく表示できる。
4. プラクティスプレイヤーが別人とマッチングしても、メイン盤が変化しない。
5. うっかり対局の対戦相手、ゲームID、色、手数、時間を表示できる。
6. 投了のキャンセルでは何も送信しない。
7. 投了の確定ではプラクティス側だけが投了する。
8. 投了を連打しても1回だけ送信する。
9. 古いゲームIDを指定した投了要求を拒否する。
10. うっかり対局のログと SGF が保存される。
11. うっかり対局の終了後、プラクティスプレイヤーが再び待機できる。
12. 同時に届く両対局のイベントを混同しない。

## 10. 完了条件

- GUI とドキュメントで「プラクティスプレイヤー」の役割が一貫している。
- メイン対局とうっかり対局が、ゲームIDと接続役割によって分離されている。
- プラクティスプレイヤーの別対局がメイン盤へ一切混入しない。
- GUI から対象を確認して安全にプラクティスプレイヤーを投了させられる。
- 既存のプレイヤー1エンジン対局と CGOS 棋譜レビューに回帰がない。

## 11. プレイヤー1の人間参加（2026-08-21 実装）

- CGOS のプレイヤー1では、エンジンに加えて `HUMAN` の Entry Profile を選択できる。
- プラクティスプレイヤーは従来どおりエンジン専用とし、人間は選択できない。
- Human の接続プロセスは `--human` で起動し、GTP エンジンを起動しない。
- CGOS から着手要求が届くと、通信プロセスは GUI からの入力を待つ。
- GUI の対局盤で交点をクリックすると、`move <gameId> <vertex>` を通信プロセスへ送る。
- 対局盤に `PASS` と `RESIGN` を表示し、人間の手番ではパス、対局中は投了を送れる。
- プレイヤー1が黒番・白番のどちらでマッチングしても、CGOS のログイン名から実際の担当色を判定する。
- 盤上入力は自分の手番だけ受け付け、着手済みの交点、自殺手、コウ、および同一手番の二重送信を拒否する。
- Human の Client Identity 取得では GTP エンジンを必須としない。選択した Entry Profile に紐づく HANDLE / PASSWORD を使用する。
