# CGOS 人間プレイヤー対応 引き継ぎメモ

更新日: 2026-08-21

## 目的

CGOS 接続のプレイヤー1で、人間または GTP エンジンを選べるようにする。
プレイヤー2は従来どおり GTP エンジン専用とする。

先行作業として、プレイヤー2を役割名「プラクティスプレイヤー」へ整理し、
別の相手との対局を内部の「うっかり対局盤」へ分離する。詳細は
`CGOSプラクティスプレイヤー実装計画.md` を参照する。

この先行作業は 2026-08-21 に完了した。人間プレイヤー対応では、実装済みの
メイン対局とうっかり対局の分離を前提として作業を続ける。

人間プレイヤーの CGOS ログイン名は、floodgate の慣習にならって末尾を
`_human` とする。GUI で自動補完する場合は、既に `_human` で終わる名前へ
重複して付加しない。

## 現状の重要事項

- プレイヤー1側とプレイヤー2側の CGOS 通信クライアントは別プロセスである。
- 両プロセスは別々にマッチングされる可能性がある。
- GUI が保持する CGOS 観戦状態は `Game1` の単一の
  `CgosGameObservation` である。
- `UpdateCgosGameObservation()` は両プロセスの出力を同じ
  `CgosGameObservation` へ渡している。
- したがって、両者が別対局へマッチングされた場合に、プレイヤー2専用の
  盤が新しく作られるわけではない。
- 対局IDの異なる2局のログが単一の観戦状態へ入る設計なので、後から来た
  `setup` による盤の切替や、他方の `play` が無視されるなど、表示が正しく
  なくなる可能性がある。

## 推奨仕様

- プレイヤー1: `HUMAN` または `ENGINE`
- プラクティスプレイヤー（旧プレイヤー2）: `ENGINE` のみ
- GUI の CGOS 盤は、常にプレイヤー1が参加している対局を表示する。
- 各通信イベントに、接続元と CGOS のゲームIDを持たせる。
- GUI は表示対象のゲームIDと一致するイベントだけを盤へ反映する。
- プラクティスプレイヤーが別対局へ入った場合、その対局をプレイヤー1の盤へ
  混ぜず、内部の「うっかり対局盤」で追跡する。
- うっかり対局はGUIに盤面を表示しない。対戦相手、ゲームID、担当色、手数、
  時計を状態欄へ表示し、確認付きの「プラクティスプレイヤー投了」ボタンを置く。
- うっかり対局の終局後は、ログと棋譜をゲームID別に保存する。

## 人間着手の通信案

既存の GUI と CGOS 通信プロセス間の標準入出力を拡張する。

```text
CGOS -> 通信クライアント: genmove b ...
通信クライアント -> GUI: HUMAN_MOVE_REQUEST game=123 color=b
GUI -> 通信クライアント: move D4
通信クライアント -> CGOS: d4
```

- `setup` で実際の担当色を判定する。プレイヤー1は常に黒とは限らない。
- 人間の手番で `genmove` を受け取ったとき、エンジンを呼ばず GUI の入力を待つ。
- GUI は着手待機中かつ表示中のゲームIDが一致する場合だけ盤クリックを許可する。
- GUI 側で合法手を確認してから送信する。
- `PASS` と `RESIGN` も送信できるようにする。
- 相手の `play` は観戦状態へ反映する。
- 切断、対局終了、別の `setup` を受信した場合は、古い着手待機を解除する。

## 盤に関する現状整理

画面上の用途と、独立した盤状態は同じ数ではない。

- ローカル対局、棋譜レビュー、通常の盤面表示は主に
  `GoAppSession` の盤状態をモードに応じて使う。
- 変化・盤面編集は別の `GoAppSession` (`_variationSession`) を作って扱う。
- CGOS 観戦は `CgosGameObservation` が独自のライブ盤を持ち、棋譜を戻した
  ときだけ再生用の盤を一時的に構築する。
- 描画部品の `BoardRenderer` は共用であり、用途ごとに4個の盤描画器がある
  わけではない。
- プレイヤー2専用の盤状態・盤画面は現在存在しない。

したがって、現在のアプリを「対局盤・棋譜レビュー盤・盤面編集盤・
プレイヤー2用盤の4盤構成」と捉えるのは正しくない。特にプレイヤー2が
別マッチへ入ったとき、その対局用の第2盤は生成されない。

## 主な変更候補

- `GoAppSession.CgosState.cs`: プレイヤー1の HUMAN/ENGINE 種別、表示対象ゲームID、
  人間着手待機状態
- `CgosLoginRenderer.cs`: プレイヤー1種別選択と `_human` の案内
- `Game1.cs`: 人間着手の盤入力、接続元・ゲームID別イベント振り分け
- `CgosConnectionProcess.cs`: 構造化イベントの受信と人間着手コマンドの送信
- `KifuwarabeGo2026.Reference.Communication.Cgos.Host/Program.cs`: 人間モード、`genmove`
  待機、着手応答、切断時の待機解除
- `CgosGameObservation.cs`: 異なるゲームIDのイベントを混在させない防御

## テスト観点

- プレイヤー1エンジン対局は従来どおり動く。
- 人間名へ `_human` が一度だけ付く。
- 人間が黒・白のどちらへ割り当てられても着手できる。
- 人間の手番以外は盤をクリックできない。
- 合法手、パス、投了、切断、時間切れを扱える。
- プレイヤー1とプレイヤー2が別対局になっても盤面が混ざらない。
- 古いゲームIDの遅延イベントが新しい対局へ入らない。
- 対局終了後に SGF を保存し、レビューできる。
