# Match分離に向けたローカル対局調査

調査日: 2026-07-31

整理状態: 完了（ファイル名の日付は開始日）

## 目的

現在GUIプロジェクトにあるローカル対局を、OSと表示方式に依存しない `KifuwarabeGo2026.Match` へ段階的に分離するため、実装場所と依存関係を整理する。

この調査ではプロジェクトの追加やソースコードの移設は行わない。

## 現在の構成

- `KifuwarabeGo2026.Gui` は `net8.0` だが、MonoGameパッケージを参照している。
- `KifuwarabeGo2026.Shared` はMonoGameを参照しない `net8.0` ライブラリである。
- `GoBoard`、`GoPoint`、`GoStone` などの盤面基本型はすでにSharedにある。
- 現在のソリューションには `KifuwarabeGo2026.Match` はまだ存在しない。

## ローカル対局の主な実装場所

### `Application/GoAppSession.cs`

対局中核に近い次の状態と操作がある。

- 現在の盤面、手番、コウ、連続パス数
- 黒白のプレイヤー種別と持ち時間
- `TryPlaceStone`、`Pass`、`Resign`
- 棋譜への着手追加、手番交代、終局判定
- リプレイ、盤面編集、棋譜レビュー用の状態復元

一方で、CGOS画面、設定編集、ダイアログ、表示モードなどGUIアプリケーション全体の状態も同じクラスにある。`GoAppSession` をそのままMatchへ移すことはできない。

### `Application/Local/Playing/PlayingScene.cs`

ローカル対局中画面の進行役だが、現在は次の責務が結合している。

- MonoGameのマウス座標と描画領域を使った入力判定
- `GoAppSession` に対する着手、パス、投了の呼び出し
- GTPエンジンプロセスの生成、コマンドキュー、同期、エラー処理
- 効果音の再生要求
- GUIログの出力

MonoGame、Presentation、GTP、ログへ直接依存しているため、このクラスもそのままMatchへ移さない。

### `Application/Local/Playing/GoGameRecord.cs` と `GoGameMove.cs`

対局メタデータ、初期配置、着手列、コメント、解析情報を保持する。MonoGameへの直接依存は見当たらず、Matchへ移す初期候補である。

ただしSGF入出力や棋譜レビューでも使われているため、名前空間変更の影響範囲を先に確認する必要がある。

### `Gtp/GtpEngineClient.cs` など

思考エンジンの外部プロセスと標準入出力で通信する。対局ルールそのものではなく、プレイヤーを実現する外部アダプターとして扱うのがよい。

最初のMatchプロジェクトへ直接移す対象にはしない。将来はMatchが定義するプレイヤー要求をGUI側または専用インフラストラクチャがGTPへ変換する。

### `Game1.cs` と `Presentation/`

画面遷移、クリック処理、描画、効果音、自動保存などのUI責務である。GUIに残す。

## 判明した主な結合

| 現在の処理 | 結合先 | 分離後の扱い |
|---|---|---|
| 着手、パス、投了、終局 | `GoAppSession` | Matchの対局セッションへ抽出 |
| 盤面ルール | Sharedの盤面基本型 | MatchからSharedを参照 |
| マウスクリック | MonoGame、Presentation | GUIに残してMatchのコマンドへ変換 |
| コンピューター着手 | GTPプロセス | 外部プレイヤーアダプターとしてMatchの外に置く |
| 効果音、ログ、画面遷移 | GUIサービス | Matchが返す結果またはイベントをGUIが処理 |
| 棋譜保存、自動保存 | ファイルシステム | Matchの外に置き、対局スナップショットを保存 |
| CGOS観戦 | CGOS通信とGUI状態 | 今回は移さない。将来の観戦API設計時に再検討 |

## Matchへ置く責務

- 対局の生成と識別
- 盤サイズ、コミ、ルール、初期配置
- 参加者と黒白の割り当て
- 現在局面、手番、コウ、連続パス
- 着手、パス、投了の受付と検証
- 終局状態と結果
- 棋譜または対局スナップショット
- 状態変更を表す、UI非依存の結果またはイベント

## Matchへ置かない責務

- MonoGameの型、描画、クリック判定、画面遷移
- Windows API、ファイルダイアログ、レジストリ
- HTTP、WebSocket、ログイン認証
- GTPプロセスの起動と標準入出力
- 効果音、ログファイル、SGFファイルの保存先
- GUI設定画面とCGOS接続画面の状態

## 推奨する移設順序

1. `KifuwarabeGo2026.Match` を `net8.0` クラスライブラリとして追加し、Sharedだけを参照する。
2. MatchがGUI、MonoGame、Windows専用アセンブリを参照していないことを移植性スモークで検査する。
3. 対局コマンドと結果の最小APIを決める。
4. 棋譜型を移すか、Match用スナップショット型を新設するかを、利用箇所の調査後に決める。
5. `GoAppSession` の着手、パス、投了、手番交代、終局処理をMatchの対局セッションへ一つずつ移す。
6. GUIからMatchを呼び、現在と同じ人間同士のローカル対局を通す。
7. GTP連携を外部プレイヤーアダプターとして接続する。
8. 時計、再接続に必要なスナップショット、観戦イベントを追加する。

## 最初の実装単位

最初は人間同士の対局だけを対象にする。

- 19路盤、黒番開始
- 合法手の着手
- パス
- 投了
- 手番交代
- 終局状態の取得

GTP、時計、棋譜ファイル、自動保存、盤面編集からの開始は後続段階にする。この小さな単位なら、MatchのAPI境界を確認しながら既存GUIの動作を維持できる。

## 未決事項

- `GoGameRecord` をMatchへ移すか、保存用棋譜と進行中スナップショットを別型にするか。
- 純碁の終局判定を初期APIへ含めるか、現在の挙動を保った後で整理するか。
- 時計をMatchが能動的に進めるか、外部から経過時間を渡す決定論的APIにするか。
- 将来のWeb観戦用イベントを、コマンド結果と同じ仕組みにするか、別のイベント列にするか。
