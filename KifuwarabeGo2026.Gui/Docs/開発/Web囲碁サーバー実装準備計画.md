# Web囲碁サーバー実装準備計画

作成日: 2026-08-01

## 目的

`KifuwarabeGo2026.Match` を中核として、ログイン、対局、観戦、結果合意を提供するWeb囲碁サーバーの実装単位を整理する。

## 責務の境界

- Matchは対局状態、時計スナップショット、操作履歴、結果合意、観戦イベントを扱う。
- サーバーは認証、権限、通信、永続化、再接続、配送保証を扱う。
- クライアントはサーバーから受け取った正本を表示し、時計表示だけを次の同期まで補間する。

## 実装段階

1. サーバーホストとMatchセッションの生成・破棄境界を作る。
2. 利用者、対局者、観戦者、審判、管理者の認証・権限を定義する。
3. Matchの初回スナップショットと差分イベントを永続化し、再起動後に復元する。
4. HTTPとWebSocketのAPIを定義し、再接続時にリビジョン以降のイベントを配送する。
5. 信頼できる時計サービスだけがMatchの時計更新APIを呼べるようにする。
6. 結果申告、不一致、再開、審判裁定、タイムアウトをAPIと画面へ接続する。
7. 配送確認、再送、遅い観戦者の扱い、イベント保持期間を決める。

## 未決事項

- `ResumePlay` を両者合意、審判判断、大会規定のどれで許可するか。
- 結果申告のタイムアウトと審判呼び出しの導線。
- イベント永続化方式と、スナップショット作成間隔。
- Webクライアントを同じリポジトリに置くか、別プロジェクトにするか。

## 完了条件

- 認証済み利用者だけが権限に応じたMatch操作を行える。
- 再起動と再接続後に同じ対局状態を復元できる。
- 対局者と観戦者へ順序どおりのスナップショットとイベントを配送できる。
- サーバー固有型がMatchへ逆流していない。
