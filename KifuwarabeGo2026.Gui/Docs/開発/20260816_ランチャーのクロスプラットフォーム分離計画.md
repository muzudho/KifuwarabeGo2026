# ランチャーのクロスプラットフォーム分離計画

作成日: 2026-08-16  
状態: 計画作成済み・実装未着手  
関連文書: `20260816_共通ランチャー導入計画.txt`

## 目的

現在の `KifuwarabeGo2026.Launcher` は、アンインストール機能の要件を確認するために Windows Forms で作った最初の実装である。
この実装で確定した安全規則と画面要件を保ちながら、OSに依存しない処理、既存の文房具UIで構成する画面、OS固有処理を分離する。

最初の正式配布対象は引き続き Windows x64 とする。ただし、Coreと画面構造は最初から Linux・macOSへ移植できる境界にしておく。

## 現在のWindows依存

| 依存 | 現在の場所 | 分離方針 |
| --- | --- | --- |
| `net8.0-windows` | Launcherプロジェクト | Windows起動プロジェクトだけに残す |
| Windows Forms | `LauncherForm`、`Program` | 文房具UI画面へ置換し、試作画面は廃止する |
| `explorer.exe` | `LauncherForm.OpenSelectedFolder` | `IPlatformFolderOpener` のWindows実装へ移す |
| 実行プロセスの列挙 | `InstalledVersionCatalog` | `IRunningProcessCatalog` のOS別実装へ移す |
| `%LOCALAPPDATA%` | `InstalledVersionCatalog` | `ILauncherPathProvider` から管理ルートを受け取る |
| メッセージボックス | `LauncherForm` | 文房具UIの確認・結果ダイアログへ置換する |

`System.IO`、`Path`、JSON、バージョン比較そのものはクロスプラットフォームで使える。ただし保存場所の決定、実行中判定、フォルダーを開く操作はOS境界として扱う。

## 目標プロジェクト構成

```text
KifuwarabeGo2026.Launcher.Core/
  ドメインモデル、設定、一覧取得、更新、削除、ロールバック
  OS API、Windows Forms、MonoGameを参照しない

KifuwarabeGo2026.StationeryUI/
  GUIとLauncherが共有する文房具UI部品
  Button、Headline、StickyNote、MessageDialogなど
  囲碁対局のApplication層を参照しない

KifuwarabeGo2026.Launcher.Presentation/
  ランチャーの画面モデル、入力処理、文房具UIによる描画
  Launcher.CoreとStationeryUIを参照する

KifuwarabeGo2026.Launcher.Desktop/
  クロスプラットフォームなデスクトップ起動口
  MonoGame DesktopGL、ウィンドウ、描画資源を組み立てる

KifuwarabeGo2026.Launcher.Windows/
  Windows用パス、プロセス照会、Explorer、Windows配布設定
  必要な場合だけDesktop起動口へWindows実装を注入する
```

依存方向は外側から内側への一方向にする。

```text
Launcher.Windows ─┐
                  ├─> Launcher.Desktop -> Launcher.Presentation -> Launcher.Core
Linux/macOS実装 ──┘                         |
                                             -> StationeryUI
```

`Launcher.Core` から Presentation、MonoGame、Windowsを参照してはいけない。`StationeryUI` からGUIのゲームセッションやランチャーCoreも参照してはいけない。

## 文房具UIの再利用方針

現在の文房具UIには再利用候補として次がある。

- `BackgroundRenderer`
- `KfwStationeryDrawingTools`
- `DynamicTextRenderer`
- `Button`
- `Headline`
- `SectionLabel`
- `StickyNote`
- `ActionBadge`
- `MessageDialog`
- `TableRowLabel`
- `LinkUnderline`

ただし現在のクラスは `KifuwarabeGo2026.Gui` 名前空間、MonoGameの型、GUI用の描画コンテキストに結び付いている。最初から全ファイルを移動せず、ランチャー画面で必要になった部品から一つずつ抽出する。

抽出時の規則は次のとおりとする。

1. 囲碁盤、対局セッション、CGOS、GUI設定への参照を持たせない。
2. 描画に必要な機能は、小さな描画サーフェスまたは既存の `KfwScreenCanvas` 相当の抽象を介す。
3. マウス・キーボード・ゲームパッド入力は画面モデルへイベントとして渡す。
4. OSの確認ダイアログを直接呼ばず、文房具UI内のモーダル画面を使う。
5. GUIとLauncherで色、余白、文字サイズ、ボタン状態を共有する。
6. 抽出のたびにGUI既存画面の表示と操作が変わっていないことを確認する。

## ランチャー画面計画

### 最小画面

```text
KIFUWARABE GO 2026

GUI       v3.14.0  [START]        [UPDATE]
ENGINE    v3.14.0  [OPEN FOLDER]  [UPDATE]

[INSTALLED VERSIONS]              [CHECK ALL UPDATES]
```

### インストール済みバージョン画面

- GUI、Engine、旧Updatesを同じ一覧で表示する。
- 製品、バージョン、容量、状態、保存場所を表示する。
- current、previous、実行中は選択不可または削除不可として理由を表示する。
- 複数選択、合計解放容量、再読み込み、保存場所表示を用意する。
- アンインストール前に対象と解放予定容量を文房具UIの確認ダイアログへ表示する。
- 一部失敗した場合は、成功と失敗を対象ごとに結果表示する。

WinForms試作画面で確認できた情報量と操作は、この画面の受け入れ基準として引き継ぐ。

## テスト計画

### Core自動テスト

- currentとpreviousを削除できない。
- 実行中として報告された版を削除できない。
- 管理ルート直下以外を削除できない。
- `v3.14.0` と `3.14.0` を同じ版として比較できる。
- 壊れた設定JSONでも一覧取得がクラッシュしない。
- `.downloading` をインストール済み版として表示しない。
- リパースポイントを容量計算で追跡しない。
- 複数削除で一件が失敗しても、残りの結果を報告できる。

### Presentationテスト

- current、previous、実行中の理由が画面に表示される。
- 選択対象と解放予定容量が確認画面に一致する。
- 削除キャンセルではファイルを変更しない。
- 0件、長い版名、長いパス、100件以上でも操作できる。
- マウスなしでも主要操作を完了できる。

### OS別スモークテスト

- 管理ルートがOSの所定場所になる。
- GUIを正しいWorkingDirectoryで起動できる。
- 保存場所をExplorer、Finder、既定ファイルマネージャーで開ける。
- 実行中の版をアンインストールできない。

## 次に着手する作業

最初に第1段階を行う。WinFormsの見た目を先に作り直さず、現在動いている `InstalledVersionCatalog` からOS非依存の規則をCoreへ切り出す。
その後、Windows用アダプターを通して現在の試作画面が同じ動作をすることを確認する。ここまで終わってから、文房具UIの共有化へ進む。

この順序なら、各段階でビルド可能・動作確認可能な状態を保ちながら、Windows依存を外側へ押し出せる。
