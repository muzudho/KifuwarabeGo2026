# v4.0.0プロジェクト再構成計画

## 文書の位置づけ

この文書は、`KifuwarabeGo2026`を囲碁プログラム兼ゲームプラットフォーム `Kifuwarabe Game Oasis` として再構成するための、v4.0.0向け引き継ぎ資料です。

v3系までのプロジェクト構成を直ちに変更する指示書ではありません。プロジェクトの作成、改名、移動、削除、名前空間変更、参照変更は、この文書とは別の実装作業として段階的に行います。

## v4.0.0とする理由

次の変更は、既存のプロジェクト名、名前空間、参照方向、実行時の責務境界に広く影響するため、v4.0.0の破壊的変更として扱います。

- GUIからゲーム運営をゲームコンシェルジュへ分離する
- ゲームルールと状態をプレイスペースエンジンへ分離する
- プロトコルP、M、G、Sを公開境界として定義する
- プレイヤー、ゲームマスター、GUI、プレイスペースを交換可能な外部実装として扱う
- `Match`、`Shared`、`Engine`、`Gui.Core`などを責務別に分割する
- Game Oasis本体と公式参照実装を名前空間で区別する

## 公開識別子の命名規約

Game Oasisのゲーム種別、文書スキーマ、公式参照エンジンなど、リポジトリー外部との契約に現れる識別子は、C#名前空間とは別に管理します。きふわらべ公式実装が発行する識別子の所有ルートは次です。

```text
io.github.muzudho.kifuwarabego2026
```

これはGitHub PagesでGitHub利用者に割り当てられる`muzudho.github.io`を逆順にした所有名前空間です。リポジトリーURLは`https://github.com/muzudho/KifuwarabeGo2026`です。公式ゲームとスキーマは、例えば次のように構成します。

```text
io.github.muzudho.kifuwarabego2026.games.go
io.github.muzudho.kifuwarabego2026.games.ponnuki
io.github.muzudho.kifuwarabego2026.games.go.state.v1
io.github.muzudho.kifuwarabego2026.games.ponnuki.action.v1
```

識別子の比較は大文字と小文字を区別します。ただし公式識別子の発行値はASCII小文字、数字、ピリオド、ハイフンだけで構成します。したがって`io.github.muzudho.KifuwarabeGo2026`は公式値として使用しません。表示名、C#型名、リポジトリー名の大文字表記はこの制限の対象外です。

外部開発者が独自ゲーム、プレイヤー、ゲームマスターを公開するときは、`io.github.muzudho...`を流用せず、自分が所有・管理できるドメインまたはリポジトリーホスト由来の名前空間を使用します。きふわらべ実装と互換なフォークは、同じ契約上のゲームを実装する場合に限り既存ゲーム種別IDを使用し、独自スキーマを追加する場合は自分の所有名前空間で新しいスキーマIDを発行します。

v4.0.0開発中に使用していた`org.kifuwarabe...`は仮識別子であり、公開前に廃止します。永続データや外部設定へ旧IDを書き出す互換期間はまだ存在しないため、旧IDの別名受付は追加しません。

## 将来の言語非依存接続

v4.0.0の現在段階では、ContractsのC#インターフェースとC#参照実装を先に完成させます。これは最終的にGame Oasisへの参加をC#へ限定するという意味ではありません。

将来は、次のすべてを実装言語や実行環境を問わず接続できるようにします。

- プレイヤーエンジン（Protocol P）
- ゲームマスターエンジン（Protocol M）
- GUIエンジン（Protocol G）
- プレイスペースエンジン（Protocol S）

C#版で要求、応答、通知、エラー、ライフサイクル、リビジョン、能力情報の意味を十分に検証した後、その意味契約をテキストベースの言語非依存仕様へ写します。標準入出力、ソケット、JSON Lines、メッセージID、非同期通知、プロセス起動・終了、タイムアウト、文字コードなどの配送仕様は、その段階で整理します。

現時点ではテキスト形式や配送方式を確定しません。先に形式を固定してC#概念モデルを歪めたり、C#型名やアセンブリ名を外部仕様へ露出させたりしないためです。`ContractDocument`、安定識別子、Protocol P・M・G・Sの境界は、将来の直列化を妨げない粒度に保ちます。

### Game Oasis本体

Game Oasis本体は、外部実装との境界契約と、公式コンシェルジュを所有します。

### 製品外郭と汎用ライブラリー


### 通信アダプター

GTPやCGOSは、Game Oasisの概念モデルそのものではなく、外部プロセスまたは外部サービスへ接続する通信方式です。公式参照実装が使用するアダプターとして、次を候補とします。

```text
KifuwarabeGo2026.Reference.Communication.Gtp
KifuwarabeGo2026.Reference.Communication.Cgos
```

名称は実装開始時に `Communication` と `Adapters` を比較して最終決定します。この文書では、現行名との対応を説明しやすいため `Communication` を使用します。

### テストとスモーク実行

製品アセンブリとテスト用実行ファイルを名前で区別します。

```text

KifuwarabeGo2026.Tests.Reference.GUI.Windows
KifuwarabeGo2026.Tests.Launcher.Smoke
```

## Contracts単体試験とProtocol結合試験の区別

Protocol P、M、G、Sのインターフェース、要求・応答DTO、識別子、状態、エラー、JSON Schemaは`KifuwarabeGo2026.GameOasis.Contracts`の一部です。ProtocolをContractsとは別の製品境界として扱うものではありません。

テストプロジェクトは、製品アセンブリの所属ではなく検証範囲で分けます。`KifuwarabeGo2026.Tests.GameOasis.Contracts`はContractsだけを対象に、DTO、識別子、シリアライズ、Schema、文書妥当性などの意味契約を検査します。`KifuwarabeGo2026.Tests.GameOasis.Integration.ProtocolP`、`ProtocolM`、`ProtocolG`は、Contractsに定義された各Protocolを使い、Concierge、参照GUI、参照プレイヤー、参照プレイスペースなど複数アセンブリを通す縦方向の結合シナリオを検査します。

この分離により、Contracts単体の破損と構成・実装間連携の破損を判別しやすくし、各Protocolのプロセス通信、タイムアウト、互換性シナリオが増えても依存を分離できます。`Integration`をプロジェクト名に明記し、ProtocolがContractsの外にあるように見える曖昧さを避けます。

## Game Oasisはゲームを知らない

Game Oasis本体とConciergeは、利用者が何のゲームをしているかを解釈しません。盤面、石、駒、カード、得点計算、合法手、勝利条件などのゲーム固有状態と規則は、Protocol Sを実装するプレイスペースだけが所有します。盤面を持たないゲームも同じ仕組みへ参加できます。

Conciergeが所有するのは、セッションID、選択されたプレイスペースへの結び付け、参加者の役割とバインディング、停止・再開などの運営状態、運営リビジョン、汎用的な終了・裁定文書、要求の直列化とライフサイクルです。プレイスペースから受け取るゲーム状態は、スキーマID付きの不透明な契約文書として中継し、内容を解釈・複製・正規化しません。

GUIやプレイヤーが表示・判断用の共通投影を必要とする場合、それはProtocol G/Pの端点または登録されたゲーム別アダプターが作ります。共通盤面投影はGUI再利用のための任意能力であり、Game Oasis本体の内部状態ではありません。

## プロジェクト別の分割・統合方針

### `KifuwarabeGo2026.Engine`

現行EngineはGTP実行ファイルであると同時に、通常対局用の着手生成、次の一手、詰碁、ポン抜き、アプリプロバイダーを含んでいます。v4.0.0では役割で分割します。

```text
現行 Engine
├─ PlayStrategy、GenerateMoveStrategyなど
│    → Reference.PlayerEngine
├─ PonnukiStrategy、PonnukiAppProviderなど
│    → Reference.PlaySpace.Ponnuki または Reference.PlayerEngine
│       ※局面生成・ルール・終局はPlaySpace、着手選択はPlayerEngine
├─ Tsumego、NextMoveなど
│    → 将来の個別PlayerEngineまたはPlaySpace。v4初期移行では保留可能
└─ GTP標準入出力、コマンド受付
     → Reference.Communication.Gtp
```

同じ「ポン抜き」という名前でも、ゲーム状態を変える処理はプレイスペース、次の着手を選ぶ処理はプレイヤーエンジンです。ファイル単位ではなくメソッドの責務単位で仕分けます。

### `KifuwarabeGo2026.GtpExtensions`

現行GtpExtensionsには二種類の責務があります。

```text
Capabilities、Protocol、Engines
    → Reference.Communication.Gtp

InitialPosition、Strategies、Sgf
    ├─ GTP通信形式とコマンド組み立て → Reference.Communication.Gtp
    └─ どの方式で初期局面を準備するかという方針 → GameOasis.Concierge
```

固定置き石、SGF読み込み、逐次着手などの「通信手段」と、ゲーム開始前にどの方法を選ぶかという「運営判断」を分けます。

### `KifuwarabeGo2026.Gui.Core`

現行Gui.Coreは、表示以外にセッション、ローカル対局、プレイヤー、時計、GTPエンジン管理、CGOS、ポン抜きプロバイダー、棋譜、設定、更新処理を所有しています。次のように段階的に分割します。

| 現行領域 | v4.0.0の所有先 |
|---|---|
| `Presentation/**`、MonoGame描画、画面遷移、入力部品 | `Reference.GUI` |
| GUI向け表示モデル、Protocol Gのクライアントアダプター | `Reference.GUI` |
| `Sessions/Game`の進行、参加者、時計、開始・終了 | `GameOasis.Concierge` |
| 人間またはエンジンの参加者選択と接続 | `GameOasis.Concierge`と`Reference.GUI`へ境界で分割 |
| `Gtp/**`、GTPプロセス、能力確認、エンジンプロファイル | `Reference.Communication.Gtp` |
| `Application/GoApps/**/Ponnuki`の局面・ゲーム処理 | `Reference.PlaySpace.Ponnuki` |
| CGOS接続設定と接続処理 | `Reference.Communication.Cgos`。編集画面だけは`Reference.GUI` |
| `Sgf/**`、棋譜、レビュー、変化図 | 当面`Reference.GUI`。後に記録用プロジェクトを作るか再評価 |
| 盤面解析、連表示など | `Reference.PlaySpace.Go.Foundation`またはGUI専用の読み取りモデルに分ける |
| GUI設定、ファイルダイアログ抽象 | `Reference.GUI` |
| リリース更新 | Launcherとの統合を検討し、v4初期移行では現状維持可能 |

`GoAppSession`を一括移動しません。部分クラスに集積した状態を、Protocol Gのコマンド、通知、GUI表示状態、コンシェルジュセッションへ分解します。

### `KifuwarabeGo2026.Match`

`MatchSession`は名前上は対局全体に見えますが、実装には囲碁盤、コウ、合法手、パス、投了、局面ハッシュなどプレイスペースの責務が多く含まれます。一方で時計同期や裁定結果も含まれています。

```text
MatchSession
├─ 盤、石、手番、コウ、合法手、着手、パス、投了
│    → Reference.PlaySpace.Go
├─ 座標、石、盤の基礎型
│    → Reference.PlaySpace.Go.Foundation
├─ 時計進行と時計同期
│    → GameOasis.Concierge
└─ ゲームマスターによる裁定、結果合意、運営イベント
     → GameOasis.Concierge
```

プレイスペースが返す「ルール上の終了状態」と、コンシェルジュが管理する「運営上確定したセッション結果」を別の型にします。

### `KifuwarabeGo2026.Shared`

Sharedは廃止を目標とし、型を実際の所有者へ移します。

| 現行型 | 移行先 |
|---|---|
| `GoBoard` | `Reference.PlaySpace.Go.Foundation` |
| `GoPoint` | `Reference.PlaySpace.Go.Foundation` |
| `GoStone` | `Reference.PlaySpace.Go.Foundation` |
| `GoRenParseResult` | `Reference.PlaySpace.Go.Foundation`または解析専用名前空間 |
| `StrongAnalyzer` | `Reference.PlaySpace.Go.Foundation`またはGoプレイスペース |
| `ApplicationFamilySettings` | Launcher側または将来の`KifuwarabeGo2026.ProductSettings`候補 |

プロトコルのDTOで黒・白などを表す必要があっても、Contractsから参照実装の`GoStone`を参照しません。契約側に汎用の参加者IDや役割IDを定義するか、Protocol Sのペイロードとして表現します。

### `KifuwarabeGo2026.StationeryUI`

プロジェクトは維持します。ただし現行名前空間に`KifuwarabeGo2026.Gui.*`が残っているため、v4.0.0では次へ整理します。

```text
KifuwarabeGo2026.StationeryUI
KifuwarabeGo2026.StationeryUI.Controls
KifuwarabeGo2026.StationeryUI.Audio
KifuwarabeGo2026.StationeryUI.Effects
KifuwarabeGo2026.StationeryUI.Platform
```

StationeryUIはProtocol G、ゲーム状態、囲碁盤、CGOS、コンシェルジュを参照しません。

### `KifuwarabeGo2026.Gui.Communication.Cgos`

このプロジェクトはCGOSサーバー、GTPエンジンプロセス、人間の着手入力、標準入出力リレーを一つの実行ファイルで扱っています。まず`Reference.Communication.Cgos`へ改名し、その後必要に応じて次へ分けます。

```text
Reference.Communication.Cgos
├─ CGOS transport/client
├─ Game Oasis adapter
└─ executable host
```

通信ライブラリーと実行ホストを別プロジェクトにするかは、Protocol G、P、Mとの接続方法を決めてから判断します。

### Launcher系列

Launcher系列はGame Oasisの外側で既に比較的明確に分割されているため、v4.0.0でも原則維持します。

```text
Launcher              実行ホスト
Launcher.Core         更新、インストール、設定、起動ユースケース
Launcher.Platform     OS・デスクトップ固有実装
Launcher.Presentation Launcher画面
```

`ApplicationFamilySettings`をLauncher.Coreへ統合するか、製品全体の設定として独立させるかは未決定です。

## 目標とする参照方向

実行時の通信は双方向でも、C#プロジェクトの参照はContractsへ向かう一方向を基本とします。

```text
Reference.PlayerEngine ─────────────→ Contracts.ProtocolP
Reference.GameMasterEngine ─────────→ Contracts.ProtocolM
Reference.GUI ───────────────────────→ Contracts.ProtocolG
Reference.PlaySpace.Go ──────────────→ Contracts.ProtocolS
Reference.PlaySpace.Ponnuki ─────────→ Contracts.ProtocolS

GameOasis.Concierge ─────────────────→ Contracts.ProtocolP
                      ├───────────────→ Contracts.ProtocolM
                      ├───────────────→ Contracts.ProtocolG
                      └───────────────→ Contracts.ProtocolS
```

禁止する参照方向は次のとおりです。

```text
Contracts ──×──→ ConciergeまたはReference実装
Reference.GUI ──×──→ Reference.PlaySpace.Goの具象実装
Reference.GUI ──×──→ Reference.PlaySpace.Ponnukiの具象実装
PlaySpace ──×──→ GUIまたはMonoGame
PlayerEngine ──×──→ GUI
```

`Reference.Communication.*`は各プロトコルと外部通信方式を変換するアダプターです。変換先の具象実装を直接所有しないようにします。

## 一対一で変更しないもの

次の現行プロジェクトは複数責務を持つため、単純なプロジェクト改名を禁止します。

- `KifuwarabeGo2026.Engine`
- `KifuwarabeGo2026.GtpExtensions`
- `KifuwarabeGo2026.Gui.Core`
- `KifuwarabeGo2026.Match`
- `KifuwarabeGo2026.Shared`

これらは移行元を残した状態で新しい所有先を作り、テスト可能な小単位でコードを移します。移行元が空になり、全参照がなくなってから廃止します。
