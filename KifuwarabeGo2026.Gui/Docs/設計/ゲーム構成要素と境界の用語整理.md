# ゲーム構成要素と境界の用語整理

## 目的

`Provider Engine` という名称だけでは責務が伝わりにくいため、ゲームを構成するオブジェクトと、その境界に使う用語を整理します。

この文書では、ゲームルールを適用し、プレイヤーの行動によって状態を変化させるプログラムを「ゲームスペースエンジン」と呼びます。

これは将来の設計に向けた用語案です。現行コードや既存プロトコルに残る `Provider` を、ただちに一括改名することを定めるものではありません。

## 全体像

```text
［プレイヤー］ ── P ──┐
［プレイヤー］ ── P ──┤
                          ├── ［ゲームマスター］ ── G ── ［ＧＵＩ］
［プレイヤー］ ── P ──┘
                                         │
                                         S
                                         │
                             ［ゲームスペースエンジン］
                                                   ├─ ゲームルール
                                                   ├─ ゲーム設定
                                                   └─ ゲーム状態
```

ゲームマスターはゲームの進行を統括し、プレイヤー、GUI、ゲームスペースエンジンを接続します。  
ゲームスペースエンジンはルール、設定、現在状態を保持し、行動を適用した結果を返します。

## オブジェクト

### ゲームマスター

ゲームマスターは、ゲームの開始、手番、入力、判定依頼、終了、記録を統括する進行管理オブジェクトです。演奏における指揮者に相当します。

「インターフェース」と呼ぶと、プログラム言語上の `interface` や通信境界と混同しやすいため、  
「進行役」または「ゲーム進行エンジン」と表現します。

主な責務は次のとおりです。

- プレイヤーの参加と手番の管理
- プレイヤーへ着手を要求し、応答を受け取る
- ゲームスペースエンジンへ行動の適用を依頼する
- ゲームスペースエンジンから得た結果をGUIとプレイヤーへ通知する
- 時計を進行させる
- ゲームの開始と終了を管理する
- 棋譜を作成する

### プレイヤー

プレイヤーはゲームマスターへ接続し、対局者としてゲームへ参加する人またはコンピューターです。

基本的な責務は、ゲームマスターから局面と手番を与えられ、その局面で選んだ一手を応答することです。

### GUI

GUIは、設定の編集、ゲームへの入力、観戦、研究、および各画面へのナビゲーションを提供します。  
「きふわらべの碁2026」はGUIを含みます。

GUIはルールを独自に確定せず、ゲームマスターから通知された状態と判定結果を表示します。

### ゲームスペースエンジン

ゲームスペースエンジンとは、ゲームルールを適用し、プレイヤーの行動によってゲーム状態を変化させるプログラムです。

ここでいう「スペース」は、囲碁盤のような物理的な場所だけを指しません。  
囲碁の四択クイズなら、問題、選択肢、回答状況、得点などが存在して変化する論理的な場所も管理対象です。

ゲームスペースエンジンは次のものを含みます。

- ゲームルール
- ゲーム設定
- 現在のゲーム状態

ゲームスペースエンジンは次のものを含みません。

- プレイヤー
- GUI
- ゲームマスター
- 棋譜など、ゲームの外部へ保存する記録

ゲームスペースエンジンは行動を受け取り、少なくとも次の結果を返します。

- 行動を受理できるか
- 行動適用後の状態
- 盤上から取り除かれた石や駒
- 次の手番
- ゲームが終了したか
- 勝者と終了理由

### ゲームルール

ゲームルールは、ゲームスペースエンジンが状態を変化させるときに従う規則です。  
ゲームルール自体は、ゲームを動かす主体ではないため「エンジン」とは呼びません。

ゲームルールは、次の判断方法を定めます。

- 着手や回答などの行動が合法か判定する
- 行動適用後の状態を計算する
- 盤上から取り除かれる石や駒を計算する
- 終了条件と勝敗を判定する

囲碁、五目並べ、リバーシ、チェスなどは「ゲーム種別」です。日本ルールや中国ルールなど、同じゲーム種別の中で異なる規則は「ルールセット」と呼びます。

### ゲーム設定

ゲーム設定は、ゲームスペースエンジンの動作を決める静的なデータです。独立したプレイ対象や、ゲームマスターと接続する能動的なオブジェクトではありません。

```text
ゲーム設定
├─ ルール設定
│  ├─ ルールセット
│  ├─ 盤サイズ
│  ├─ コミ
│  └─ 禁止手など
├─ 進行設定
│  ├─ ゲーム形式
│  ├─ 初期局面
│  └─ 終了条件
└─ 時計設定
   ├─ 基本時間
   └─ 秒読み
```

持ち時間の設定値はゲーム設定に含めますが、時計の進行は原則としてゲームマスターが担当します。  
時間切れを勝敗へ反映する必要がある場合は、その事象をゲームスペースエンジンへ渡します。

### ゲーム状態

ゲーム状態は、ゲーム開始後に変化するデータです。

- 現在の局面
- 現在の手番
- アゲハマや得点
- キャスリング権など、以後の合法手へ影響する状態
- 終了状態と勝敗

ゲーム設定とゲーム状態を分けることで、「開始時に決める値」と「プレイ中に変化する値」を区別します。

## 境界

| 記号 | 推奨名称 | 接続対象 | 主な内容 |
|---|---|---|---|
| P | プレイヤープロトコル | ゲームマスターとプレイヤー | 着手要求、着手応答、着手通知、投了 |
| G | GUIプロトコル | ゲームマスターとGUI | 操作入力、状態通知、表示更新、画面遷移 |
| S | ゲームスペースプロトコル／ゲームスペースAPI | ゲームマスターとゲームスペースエンジン | 初期化、行動適用、状態取得、終局結果 |
| C | 設定スキーマ／設定API | ゲームスペースエンジンとゲーム設定 | 設定の記述、読み込み、検証、適用 |

P、G、S、Cは、特定のデータ形式ではなく「どの役割同士を接続する境界か」を示す記号です。実装時には、それぞれの境界に適した通信方式やAPIを選びます。

### プロトコルP

プレイヤーとの境界です。GTPは代表的な実装候補です。

ゲームマスターはプレイヤーへ「この局面で一手を選ぶ」よう要求し、プレイヤーは選んだ着手を応答します。また、他プレイヤーの着手やゲーム終了など、進行に必要な情報をゲームマスターから通知します。

### プロトコルG

GUIとの境界です。JSONなどの構造化データを利用できます。

GUIからは利用者の操作を入力し、ゲームマスターからは局面、消えた石、手番、棋譜、結果などを通知します。GUIは通知を受けて画面表示を更新します。

### ゲームスペースプロトコル／ゲームスペースAPI S

ゲームマスターとゲームスペースエンジンの境界です。  
ゲームマスターが初期設定やプレイヤーの行動を渡し、ゲームスペースエンジンが受理の可否、適用後の状態、次の手番、終局状態などを応答します。

ゲームマスターは、ゲームスペースエンジン内部のルール計算方法や状態保持方法を知る必要がありません。

GTPまたは独自プロトコルを通信手段として利用することは可能ですが、GTPの一般的な主用途はプレイヤーエンジンの操作です。そのため、境界Sの役割はGTPそのものとは分けて定義します。

SGFは主に棋譜やゲーム木を保存・交換するデータ形式です。  
境界Sで局面や着手列を受け渡す形式として利用することはできますが、ゲームスペースプロトコル自体とは区別します。

### 設定スキーマ／設定API C

ゲームスペースエンジンがゲーム設定を解釈する境界です。  
内部実装だけで完結する場合は、独立した通信プロトコルを設ける必要はありません。

設定項目の型、既定値、許容範囲、相互制約を表す場合は「設定スキーマ」、設定の取得、検証、適用を操作として提供する場合は「設定API」と呼び分けます。

## ゲームの分類

| 用語 | 意味 | 例 |
|---|---|---|
| ゲーム種別 | 基本となるゲームのカテゴリー | 囲碁、連珠、リバーシ、チェス |
| ゲーム形式 | ゲームの遊び方や進行形式 | 通常対局、指定局面戦、ポン抜き、四択クイズ |
| ルールセット | 同じゲーム種別における規則の違い | 日本ルール、中国ルール、純碁 |
| ゲーム設定 | ゲームスペースエンジンを初期化する値 | 9路、コミ6目半、初期局面 |
| ゲームセッション／対局 | 実際に開始された一回のゲーム | 2026年8月22日に開始した黒対白の対局 |

「囲碁対局」「指定局面戦」「ポン抜き」などを独立したプログラムという意味で「ゲームアプリ」とは呼びません。  
ここではプログラムの配布単位ではなく、ゲームスペースエンジン上で提供される遊び方として「ゲーム形式」に分類します。

## 推奨用語

| 日本語 | 英語 | 意味 |
|---|---|---|
| ゲームマスター／ゲーム進行エンジン | Game Master / Game Flow Engine | ゲーム全体の進行役 |
| プレイヤー | Player | 一手や回答を選ぶ参加者 |
| ユーザーインターフェース | GUI / User Interface | 操作、表示、画面遷移 |
| ゲームスペースエンジン | Game Space Engine | ルールを適用し、ゲーム状態を変化させるプログラム |
| ゲームルール | Game Rules | ゲーム状態を変化させるときに従う規則 |
| ゲーム種別 | Game Type | 囲碁、連珠、リバーシ、チェスなど |
| ゲーム形式 | Game Format | 通常対局、指定局面戦、ポン抜き、四択クイズなど |
| ルールセット | Ruleset | 日本ルール、中国ルール、純碁など |
| ゲーム設定 | Game Configuration | ゲームスペースエンジンを初期化する静的データ |
| ゲーム状態 | Game State | プレイ中に変化する状態 |
| プレイヤープロトコル | Player Protocol | 境界Pの契約 |
| GUIプロトコル | GUI Protocol | 境界Gの契約 |
| ゲームスペースプロトコル／ゲームスペースAPI | Game Space Protocol / Game Space API | 境界Sの契約 |
| 設定スキーマ／設定API | Configuration Schema / API | 境界Cの契約 |

## `Provider Engine` の扱い

`Provider Engine` は、初期局面の生成、着手監視、ルール判定、終局判定、状態保持など複数の責務を含み得るため、名称だけでは役割を特定しにくい用語です。

新しい設計では、実際の責務に応じて次の語へ分解します。

- プレイヤーの行動へルールを適用し、状態を変化させるもの: ゲームスペースエンジン
- ゲーム全体の進行を担当するもの: ゲームマスター／ゲーム進行エンジン
- ゲームスペースエンジンが従う規則: ゲームルール
- ゲームマスターとゲームスペースエンジンの境界: ゲームスペースプロトコル／ゲームスペースAPI
- ゲーム開始時の条件を表すもの: ゲーム設定
- ゲーム中に変化するもの: ゲーム状態

既存の `Provider` コマンドや文書は互換性のために旧称として残し、変更するときはプロトコル互換性と移行手順を別途定めます。

## 将来の拡張

この分離により、ゲームマスターとGUIを再利用しながら、ゲームスペースエンジンを差し替えられます。  
さらに、ゲームスペースエンジン内部のゲームルール、ルールセット、ゲーム形式を組み替えられます。

通常の囲碁だけでなく、変則囲碁、囲碁の四択クイズ、連珠、リバーシ、チェスなどへの拡張を想定できます。
