# 指定局面コンシェルジュ利用ガイド

## できること

盤面編集で作った置き碁、黒白混在局面、研究用局面から、GTPエンジンとのローカル対局を開始できます。

エンジンによって対応コマンドが違うため、GUIが能力を調べ、利用できそうな方式を順番に試します。黒番と白番に別のエンジンを設定した場合は、それぞれ独立して進みます。

## 使い方

1. ローカル対局準備画面で盤面編集を開く。
2. 初期石と開始手番を設定して準備画面へ戻る。
3. 黒番または白番を `Computer` にし、GTPエンジンを選ぶ。
4. 対局を開始する。
5. 指定局面コンシェルジュに表示された結果を確認する。
6. 自動確認済みなら、そのエンジンは `READY` になる。
7. 局面を自動確認できない成功では、実際のエンジン動作を確認して［このまま続ける］を押す。
8. 失敗して次候補がある場合は［別の方法を試す］を押す。

全コンピューターエンジンが確認済みまたは利用者承認済みになるまで、思考は始まりません。

## 画面に出る主な結果

| 表示 | 意味 | 利用者の操作 |
|---|---|---|
| 局面を確認できました | 応答内容または原子的commitにより確認済み | 操作不要 |
| 応答成功・局面は未確認 | コマンドは成功したが標準GTPでは盤面照合できない | エンジンを確認して［このまま続ける］、または［別の方法を試す］ |
| コマンド非対応 | 能力検査で非対応と判明 | 次方式を試す |
| エンジンが拒否 | コマンドへエラー応答 | 次方式を試す |
| 設定後の局面が不一致 | 応答座標が要求局面と違う | 別方式を試す |
| 想定外の応答 | 応答を安全に解釈できない | GTPログを確認 |
| 通信に失敗 | タイムアウト、プロセス終了など | GTPログとエンジン設定を確認 |

## 設定方式

| 方式 | 主な用途 | 確認方法 |
|---|---|---|
| `fixed_handicap` | 2子から9子の標準置き碁 | エンジンが返した座標を照合 |
| `set_free_handicap` | 黒石だけの自由置き碁 | 成功応答。標準GTPだけでは完全照合できない場合がある |
| `loadsgf` | 黒白混在、開始手番を含むSGF対応エンジン | 成功応答。標準GTPだけでは完全照合できない |
| 連続 `play` | 他方式がない場合の互換手段 | 成功応答。途中局面の合法性に左右される |
| きふわらべ原子的方式 | 同梱きふわらべ、自由編集局面 | 全コマンド成功時に原子的commit契約で確認済み |

## エンジン別設定

エンジン選択画面から対象を編集し、`POSITION` 欄を使います。

- `PROFILE AUTO` は、`name` 応答からProfileを選ぶ。
- 明示Profileは `GENERIC-GTP`、`KIFUWARABE`、`KATAGO`、`LEELA-ZERO`、`GNU-GO` から選べる。
- `METHOD AUTO` は能力検査と前回成功結果から順番を決める。
- 手動方式を選ぶと、その方式を最優先する。

一度、自動確認または［このまま続ける］で承認した方式は、エンジン名、version、Profileと一緒に保存されます。同じ組み合わせでは次回その方式を優先します。nameまたはversionが変わると自動結果だけを破棄して再検査し、手動優先は残します。

## 困ったとき

### ［別の方法を試す］を押せない

次候補がないか、エンジン処理中です。`GTP LOG` を開き、`known_command`、`list_commands`、最後のエラー応答を確認してください。

### `loadsgf` が失敗する

エンジンが `loadsgf` 非対応、SGFの開始手番やルールを拒否、一時ファイルのパス引用方式が不一致、作業ディレクトリやファイルアクセスに問題がある可能性があります。Profileを `AUTO` に戻すか、別方式を試してください。

### 連続 `play` が途中で失敗する

編集局面の途中状態が、そのエンジンの合法手判定に反しています。黒白混在や呼吸点のない石を含む局面では、`loadsgf` または対応するきふわらべ原子的方式を使ってください。

### 起動後すぐ通信失敗になる

実行ファイル、引数、作業ディレクトリ、モデルファイルを確認します。KataGoやLeela Zeroは、エンジン本体だけでなく設定ファイルやニューラルネットワークの重みが必要です。

### 動いたように見えるが自信がない

［このまま続ける］は利用者承認です。盤面が一致しているか判断できない場合は押さず、`GTP LOG` を保存して別方式を試してください。

## ログ

`GTP LOG` は実行ファイルの `logs/gtp.log` を開きます。黒番と白番は `[black-engine]`、`[white-engine]` の接頭辞で区別できます。問題報告にはエンジン名、version、OS、選んだProfile、試した方式、該当ログを添えてください。
