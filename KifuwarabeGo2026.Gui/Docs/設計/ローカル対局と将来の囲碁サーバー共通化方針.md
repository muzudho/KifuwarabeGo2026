# ローカル対局と将来の囲碁サーバー共通化方針

## 将来像

- 将来、Web上でログイン、対局、観戦ができる囲碁サーバーを構築する。
- WebサーバーのホストOSはUbuntuを想定する。
- 囲碁サーバーの中核部分はWindowsへ依存させない。

## 基本方針

- 現在GUI内にある「ローカル対局」の中核処理を、`KifuwarabeGo2026.Match` プロジェクトへ分離する。
- ローカルPC版とWeb版で、対局の開始、着手、投了、状態取得、観戦などの同じアプリケーションAPIを利用できる形を目指す。
- ローカルPC版は同一プロセス内のAPI呼び出し、またはローカル用アダプターを通して利用する。
- Web版はHTTP、WebSocket、認証、永続化などの接続部分で中核APIを包む。
- 対局ルールと状態遷移を通信プロトコルへ直接結び付けない。
- GUI、Windows API、MonoGame、ファイルダイアログ、レジストリなどへの依存を `KifuwarabeGo2026.Match` に持ち込まない。

## 境界の考え方

`KifuwarabeGo2026.Match` はサーバーや画面ではなく、対局を表すOS非依存の.NETライブラリとする。外側に実行環境別の入口を置く。

- 中核: 対局セッション、参加者、盤面、手番、時計、着手、投了、終局、観戦用イベント
- ローカル用入口: GUIから中核APIを呼ぶアダプター
- Web用入口: Ubuntu上のASP.NET Coreホスト、認証、HTTP/WebSocket、データ保存
- 表示側: Windows GUIや将来のWebクライアント

これにより、ローカル対局とWeb対局で中核ロジックを共有しつつ、通信障害や認証などWeb固有の事情を中核から分離する。

## 着手時の注意

- 既存のローカル対局コードを一度に移さず、最初に公開APIと依存関係を決める。
- APIは画面操作ではなく、利用者が行いたい操作を表す。
- 対局状態の更新結果やイベントは、ローカルでもWebでも同じ意味になるようにする。
- Web化すると同時実行、切断と再接続、権限、永続化が必要になるため、中核APIへUIオブジェクトやソケットを渡さない。
- プロジェクト作成と移設は別作業として、既存ローカル対局の責務を調査してから段階的に行う。

## プロジェクトの依存方向

```text
KifuwarabeGo2026.Gui       ─┐
                             ├─> KifuwarabeGo2026.Match ─> KifuwarabeGo2026.Shared
将来のWebサーバーホスト   ─┘

KifuwarabeGo2026.Engine ────────────────────────────────> KifuwarabeGo2026.Shared
```

`Match` からGUI、Webサーバーホスト、Engineへは依存しない。
