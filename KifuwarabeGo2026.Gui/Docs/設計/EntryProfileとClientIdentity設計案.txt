PLAYER PROFILE と CLIENT IDENTITY の設計案
最終更新: 2026-08-12

1. 目的

Entry Profile は「誰として対局するか」を表す。
Engine Profile は「どの GTP エンジン実行ファイルを、どの引数で起動するか」を表す。
両者は別の責務であり、同じ Engine Profile を、表示名や接続先の異なる複数の Entry Profile から参照できる。

Entry Profile、Engine Profile、Client Identity Profile は、それぞれ独立して登録する。
Entry Profile は Engine Profile と Client Identity Profile を一方向に参照する。
Client Identity Profile は、ある用途・接続先において、その Player をどう識別するかを表す。

### Player の成立条件（2026-08-12 追記）

この設計での **Player** は、単独の Profile ではない。対局または接続において、次の二つを明示選択して初めて Player として成立する。

```text
Player = Entry Profile + Client Identity
```

- Entry Profile は「誰が打つか」を決める。Human / Computer の別と、Computer の場合の Engine Profile を解決する。
- Client Identity は「その Player が今回のサービスで何と名乗るか」を決める。CGOS ではログイン認証、LocalMatch では出力ファイル名用の HANDLE を与える。
- 選択できる Client Identity は、選択済み Entry Profile の `ClientIdentityProfileIds` に含まれ、かつ現在のサービスに適合するものに限る。
- Entry Profile だけ、または Client Identity だけでは Player は成立しない。黒白それぞれについて両方の選択結果を画面に表示する。

したがって Player 選択画面は、Entry Profile の選択後に、その Entry Profile が利用できる Client Identity を選ぶ二段階の操作とする。既定 Client Identity を候補として初期選択してよいが、今回使う Client Identity は Player の構成要素として明示する。


2. 用語と画面名

- PLAYER PROFILE
  対局者の登録情報。現在の EntryProfile に相当する。

- DISPLAY
  Player の人が読む呼び名。画面表示および SGF の PB / PW に使う。
  旧「DISPLAY NAME」は、この意味で Entry Profile に置く。

- ENGINE PROFILE
  Computer Player が参照する、GTP エンジンの起動・GUI オプション・GTP ログなどの設定。
  旧「EDIT GTP ENGINE」は「EDIT ENGINE PROFILE」と呼ぶ。
  Engine Profile の表示名は、エンジン設定を識別するための名前であり、対局者名ではない。

- CLIENT IDENTITY
  Player が利用する用途または接続先ごとの設定。
  表示名、LOGIN NAME、LOGIN PASS を持つ。Player の ClientIdentityProfileIds の先頭を既定 Client Identity とする。

- LOGIN NAME
  システムへのログインや、ファイル名など機械的な用途に使う識別子。
  アプリ全体では文字種・文字数を制限せず、実際の接続先・出力先が必要な検査と変換を行う。

- LOGIN PASS
  システムへの接続に使うパスワード。画面上は伏せ字で扱う。

- OUTPUT NAME
  LocalMatch Client Identity における LOGIN NAME の画面上の呼称。ログインはしないため、出力ファイル名などの材料を表す。
  LocalMatch では LOGIN PASS を表示・使用しない。


3. 独立カタログと参照の構造

EntryProfile
  Id
  DisplayName
  Kind                 Human / Computer
  EngineProfileId      Computer の場合だけ使用する Engine Profile への参照
  ClientIdentityProfileIds[]   使用可能な Client Identity Profile への参照

EngineProfile
  Id
  DisplayName          エンジン設定を識別する表示名
  ExecutablePath
  WorkingDirectory
  Arguments
  GuiOptions
  GtpLog など

ClientIdentityProfile
  Id
  DisplayName          例: CGOS / LocalMatch / Test Server
  ConnectionProfileId  接続先の Host / Port 等を持つカタログ項目への参照。LocalMatch では空
  LoginName
  LoginPass

Entry Profile は Engine Profile と Client Identity Profile を逆参照しない。
Engine Profile と Client Identity Profile は、どの Player から参照されているかを保存しない。
削除時だけ Entry Catalog を検索し、参照中なら削除を拒否するか、利用者へ参照先の差し替えを求める。

Client Identity Profile の DisplayName は画面表示用の任意文字列である。
CGOS の Host、Port、イベント、ラウンド等は、既存の CGOS Connection Profile 側で管理する。
Client Identity Profile は ConnectionProfileId によりそれを参照する。将来の接続先カタログでは、安定した ID を必須にする。

接続先カタログは、現在は「接続先（CGOS）」である。将来は他サービスも扱えるよう、ConnectionProfile は接続種別（現在は Cgos）を持つものとして一般化する。
ClientIdentityProfile が保持するのは Host / Port を連結した接続文字列ではなく ConnectionProfile の不変 Id である。接続文字列は編集・表記揺れ・TLS 等の接続オプション追加で変化し得るため、参照キーにしない。
接続種別と正規化済み Host / Port から作る EndpointKey（例: cgos://uec-go.com:6809）は、重複候補の検出・警告・初期候補の決定に使う。同一 Endpoint でもイベント、ラウンド、接続オプションが異なる複数 ConnectionProfile は許可する。


4. Client Identity のサンプル

Computer Player: 「きふわらべ」

  DISPLAY: きふわらべ
  ENGINE PROFILE: Kifuwarabe Go 2026

  CLIENT IDENTITY PROFILE: OnlineMatch (CGOS)
    LOGIN NAME: kifuwarabe
    LOGIN PASS: (秘密情報)
    CONNECTION PROFILE: CGOS Server 9-ro

  CLIENT IDENTITY PROFILE: LocalMatch
    OUTPUT NAME: kifuwarabe-local
    CONNECTION PROFILE: なし

Human Player: 「山田太郎」

  DISPLAY: 山田太郎

  CLIENT IDENTITY PROFILE: LocalMatch
    OUTPUT NAME: yamada-taro
    CONNECTION PROFILE: なし

同一 Player が CGOS 用と LocalMatch 用で異なる LOGIN NAME を持てる。
同じ Engine Profile を参照する別 Player にも、それぞれ独立した Client Identity Profile を設定できる。
LOGIN NAME と LOGIN PASS は参加者固有の情報なので、通常は別 Player 間で同じ Client Identity Profile を共有しない。


5. LocalMatch の利用規則

LocalMatch のインターバル画面では、黒白それぞれについて次の二段階を選ぶ。

  1. PLAYER PROFILE
  2. CLIENT IDENTITY

Client Identity 候補は、選択した Entry Profile が参照するものだけを表示する。
LocalMatch 開始時は、黒白とも LocalMatch 用 Client Identity Profile を選択する。
将来、Player ごとに複数の LocalMatch Client Identity Profile を参照することも許可する。
その場合は利用者が明示選択する。候補が一つだけでも自動選択せず、画面に選択結果を表示する。

棋譜の内容とファイル名の責務は次のように分ける。

  SGF PB / PW       Entry Profile の DISPLAY
  LocalMatch の
  ファイル名の材料  選択 LocalMatch Client Identity の LOGIN NAME

ファイル名へ書き出す際だけ、OS に依存する禁止文字の置換などを行う。
LOGIN NAME 自体を保存時に変換・制限しない。
LOGIN NAME が空欄の場合は、ファイル保存時に DISPLAY を代替値として使うか、保存前に利用者へ警告する。実装時に一方を仕様として確定する。


6. UI 方針

現在、Player の DISPLAY は Player 編集画面にあり、CGOS LOGIN / CGOS PASS は Engine Profile 編集画面と CGOS 接続画面に分散している。
これを次の形に統合する。

EDIT PLAYER PROFILE
  DISPLAY
  CLIENT IDENTITY               既定 Client Identity の表示
    [SELECT CLIENT IDENTITY]    Client Identity 一覧を開く
  KIND
  ENGINE PROFILE       Computer の場合だけ。EDIT ENGINE PROFILE を開く
  CLIENT IDENTITY PROFILES
    [CGOS]        LOGIN NAME / LOGIN PASS / 接続先
    [LocalMatch]  LOGIN NAME
    [USE] [CREATE CLIENT IDENTITY] [EDIT CLIENT IDENTITY] [REMOVE CLIENT IDENTITY]

EDIT ENGINE PROFILE
  ENGINE DISPLAY
  EXE
  WORKDIR
  ARGS
  GUI OPTIONS
  POSITION
  GTP LOG

Engine Profile 編集画面から CGOS LOGIN / CGOS PASS を削除する。
OnlineMatch (CGOS) 接続画面は黒白の Entry Profile と OnlineMatch (CGOS) Client Identity を選び、その Client Identity の認証情報を接続プロセスへ渡す。


7. JSON 保存と移行

現状:

- player-list.json
  Player の Id、DisplayName、Identifier、Kind、EngineProfileId を保存する。

- gtp-engine-list.json
  GTP エンジン設定に defaultCgosLoginName と defaultCgosPlainTextPassword が混在する。

- application-settings.json
  CGOS 接続先の DisplayName、Host、Port、Event、Round、Note を保存する。

目標の player-list.json 例:

{
  "players": [
    {
      "id": "player-kifuwarabe",
      "displayName": "きふわらべ",
      "kind": "computer",
      "engineProfileId": "engine-kifuwarabe",
      "targetProfileIds": ["target-cgos-kifuwarabe", "target-localmatch-kifuwarabe"]
    }
  ]
}

目標の target-list.json 例:

{
  "targets": [
    {
      "id": "target-cgos-kifuwarabe",
      "displayName": "CGOS",
      "connectionProfileId": "cgos-9ro",
      "loginName": "kifuwarabe",
      "loginPass": "..."
    },
    {
      "id": "target-localmatch-kifuwarabe",
      "displayName": "LocalMatch",
      "connectionProfileId": "",
      "loginName": "kifuwarabe-local",
      "loginPass": ""
    }
  ]
}

移行手順:

1. ClientIdentityProfile と Client Identity Catalog を追加し、既存 Player は空の ClientIdentityProfileIds として読めるようにする。
2. GtpEngineProfile の defaultCgosLoginName / defaultCgosPlainTextPassword を読み取り、対応する Computer Player ごとに独立した OnlineMatch (CGOS) Client Identity Profile を一度だけ生成して参照させる。
3. 各既存 Player に独立した LocalMatch Client Identity Profile を生成して参照させる。LOGIN NAME は旧 Identifier を最初の候補として使う。
4. CGOS Connection Profile に不変 ID を追加し、ClientIdentityProfile.ConnectionProfileId から参照できるようにする。
5. OnlineMatch (CGOS) の実行時認証情報を、選択 Player が参照する Client Identity Profile から解決する。
6. 移行猶予後に Engine Profile の旧 CGOS 認証項目と、CGOS 接続画面の黒白一時認証編集を削除する。


8. パスワードの扱い

既存の GTP Engine JSON はパスワードを平文保存している。
移行だけなら平文値を PlayerClient Identity.LoginPass へ移せるが、新規設計では OS の保護ストア（Windows では DPAPI など）を使うことを推奨する。
少なくとも、画面は伏せ字、コピーを抑制し、ログ・SGF・ファイル名へ LOGIN PASS を出力しない。

9. 最新実装ステータス（2026-08-12）

完了:
- Player / Engine / Client Identity の責務分離、Client Identity の JSON 保存、OnlineMatch (CGOS) 実行時の Client Identity 認証情報参照。
- Player 編集画面の Client Identity 表示、`SELECT CLIENT IDENTITY`、`EDIT CLIENT IDENTITIES`、Client Identity 一覧、最大5件の追加、削除、選択、OnlineMatch (CGOS) 接続先の選択。
- Client Identity の DISPLAY / LOGIN NAME / LOGIN PASS のテキスト編集。パスワードは非編集中に伏せ字で表示する。
- LocalMatch Client Identity の画面では LOGIN NAME を OUTPUT NAME と表示し、LOGIN PASS を表示しない。
- `USE` で選択 Client Identity を Player の既定 Client Identity（ClientIdentityProfileIds の先頭）へ設定する。

残作業:
- LocalMatch 開始設定で黒白それぞれの LocalMatch Client Identity を明示選択し、OUTPUT NAME を出力ファイル名へ使用する。
- OnlineMatch (CGOS) で接続先ごとに複数 Client Identity がある場合の選択画面・既定選択規則を明示する。
- Client Identity の OnlineMatch (CGOS) Connection Profile 選択 UI を接続先一覧と統合する。
- LOGIN PASS の OS 保護ストア移行。

運用方針:
- Client Identity は Player ごとに1～5件の少数を前提とする。ORDER とページ送りは作らない。
- LocalMatch Client Identity の接続先は LOCAL MATCH 固定。OnlineMatch (CGOS) Client Identity は ConnectionProfile の ID を参照する。
