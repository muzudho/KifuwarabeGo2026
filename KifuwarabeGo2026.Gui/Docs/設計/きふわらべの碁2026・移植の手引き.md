# きふわらべの碁2026・移植の手引き

最終更新: 2026-07-29

## はじめに

［きふわらべの碁2026］のGUI版は、現在Windowsだけを正式な動作対象にしています。

作者はWindows環境しか所有していないため、Linux版とmacOS版を作者自身で動作確認することはできません。その一方で、ほかの開発者がリポジトリをフォークし、LinuxやmacOSへ移植してくれることは大歓迎です。

移植しやすいように、ゲーム本体とWindows固有処理は別プロジェクトへ分けてあります。移植で分かったこと、修正、手順書、動作報告などの共有も歓迎します。

この文書は移植を保証するものではなく、移植作業の出発点を説明するものです。対象OSで必要になるパッケージ、ウィンドウシステム、ファイルダイアログ、フォントなどは、移植を担当する開発者が実機で確認してください。

## 最初に確認すること

共通GUIがWindows APIなしでコンパイルできることは、次のコマンドで確認できます。

```powershell
dotnet build KifuwarabeGo2026.Gui\KifuwarabeGo2026.Gui.Core.csproj
dotnet run --project KifuwarabeGo2026.Gui.PortabilitySmoke\KifuwarabeGo2026.Gui.PortabilitySmoke.csproj
```

2番目のコマンドはGUIウィンドウを開きません。移植用の最小構成がコンパイルできることだけを確認します。

LinuxやmacOSでは、シェルに合わせてパス区切りを `/` に読み替えてください。

## プロジェクト構成

### 共通GUI

`KifuwarabeGo2026.Gui/KifuwarabeGo2026.Gui.Core.csproj`

- MonoGameのゲーム本体
- 画面表示と入力処理
- ローカル対局、棋譜、GTP、CGOS連携
- OS固有機能を呼び出すためのインターフェース
- 対象フレームワークは `net8.0`

### Windows起動プロジェクト

`KifuwarabeGo2026.Gui.Windows/KifuwarabeGo2026.Gui.Windows.csproj`

- Windows用エントリーポイント
- WinFormsのダイアログ
- Windowsのクリップボード、外部アプリ起動、文字画像生成
- ウィンドウアイコン
- Windows向けContentビルドとpublish

Windows版のプロジェクト名には `.Windows` が付きますが、利用者が起動するファイル名は `KifuwarabeGo2026.Gui.exe` です。

### 移植用スモークプロジェクト

`KifuwarabeGo2026.Gui.PortabilitySmoke/KifuwarabeGo2026.Gui.PortabilitySmoke.csproj`

- Windows APIを使わない最小実装
- `Game1`へプラットフォームサービスを渡す構成例
- Linux版またはmacOS版の起動プロジェクトを作る際の雛形

ここにある無操作実装は、製品として利用するための実装ではありません。

## 移植の進め方

1. リポジトリをフォークする。
2. `KifuwarabeGo2026.Gui.PortabilitySmoke` を参考に、対象OS用の起動プロジェクトを作る。
3. 例としてLinuxなら `KifuwarabeGo2026.Gui.Linux`、macOSなら `KifuwarabeGo2026.Gui.Mac` とする。
4. 対象OS用プロジェクトから `KifuwarabeGo2026.Gui.Core` を参照する。
5. `PortablePlatformServices` の無操作処理を、対象OSで動く実装へ一つずつ置き換える。
6. Windowsプロジェクトを参考に、MonoGame Contentをビルドして実行場所の `Content` フォルダーへ配置する。
7. タイトル画面から少しずつ起動確認を行い、利用できない機能は安全にキャンセルまたは案内表示する。
8. 対象OS用のbuild、run、publish手順を文書化する。

最初からすべての機能を実装する必要はありません。タイトル画面とローカルの人間同士の対局を最初の目標にし、その後でファイル操作、GTP、CGOSの順に広げる方法が安全です。

## 対象OSで実装する機能

共通側の契約は `KifuwarabeGo2026.Gui/Application` にあります。

| インターフェース | 用途 | 未実装時の安全な動作 |
|---|---|---|
| `IClipboardService` | 文字列をクリップボードへコピー | `false`を返す |
| `IMessageDialogService` | 警告を表示 | GUI内表示またはログへ記録 |
| `IFileDialogService` | ファイルの読込、保存、フォルダー選択 | `null`を返してキャンセル |
| `ITextInputDialogService` | 文字列と整数の入力 | `null`を返してキャンセル |
| `IDesktopLauncher` | ログやフォルダーを外部アプリで開く | 何も開かず、GUIで未対応を案内 |
| `ITextRasterizer` | 動的な説明文をPNG画像へ描画 | 透明な代替画像を返す |
| `IWindowIconService` | ネイティブウィンドウへアイコンを設定 | 何もしない |
| `IPlatformExecutableService` | 実行ファイル名と選択フィルターを決定 | 対象OSの命名規則を返す |

インターフェースの引数や戻り値へ、特定OSのGUIライブラリの型を追加しないでください。OS固有の型は対象OS用プロジェクト内だけで利用します。

## MonoGame Content

ゲーム本体はCoreにありますが、画像、フォント、効果音などのContentビルドは起動プロジェクトが担当します。

Windowsプロジェクトは、既存の `KifuwarabeGo2026.Gui/Content` と `KifuwarabeGo2026.Gui/Content/Content.mgcb` を参照しています。新しいOS用プロジェクトでも同じ素材と定義を再利用し、実行時に `Content.RootDirectory = "Content"` から読める配置を維持してください。

フォント、音声、画像形式の対応状況は対象OSで確認が必要です。

## 実行ファイルと外部プロセス

GTPエンジンとCGOS通信コンポーネントは、標準入力と標準出力を使う別プロセスとして起動します。

- Windowsでは通常、実行ファイル名に `.exe` が付きます。
- LinuxとmacOSでは、通常は `.exe` を付けません。
- 対象ファイルに実行権限が必要なOSでは、権限の設定とエラー案内が必要です。
- シェルで開く処理と、標準入出力を接続して起動する処理を混同しないでください。

実行ファイルの命名差は `IPlatformExecutableService` で吸収します。

## 最低限の動作確認

対象OSの実機で、実装した範囲に応じて次を確認してください。

- Coreと対象OS用起動プロジェクトが警告なしでビルドできる。
- タイトル画面が表示され、正常に終了できる。
- 画像、フォント、効果音を読み込める。
- ウィンドウサイズ変更とマウス、キーボード入力が動く。
- ローカルの人間同士の対局を開始できる。
- SGFを読み込み、保存できる。
- GTPエンジンの実行ファイルと作業フォルダーを選べる。
- GTPエンジンを起動し、終了時に子プロセスが残らない。
- クリップボード、警告、文字入力、整数入力が動く。
- ログファイルを開き、保存場所を表示できる。
- CGOS通信コンポーネントを探索して起動できる。
- 設定、ログ、自動保存棋譜がユーザーの書込み可能な場所へ保存される。
- publishした配布物だけを別フォルダーへ置いて起動できる。

実装していない機能は、クラッシュさせず「未対応」と分かる動作にしてください。

## 変更を共有するとき

Linux版やmacOS版の移植、途中経過、対象OS固有の注意点、再現手順、スクリーンショット、文書だけの改善も歓迎します。

共有時には、次の情報があると確認しやすくなります。

- OS名とバージョン
- CPUアーキテクチャ
- .NET SDKのバージョン
- MonoGameのバージョン
- 実行したbuildまたはpublishコマンド
- 動いた機能と、まだ動かない機能
- エラーログと再現手順

作者はWindowsで確認できる共通部分を確認します。対象OSだけで発生する問題については、実機を持つ協力者による調査と確認をお願いする場合があります。
