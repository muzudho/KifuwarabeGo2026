PLAYER PROFILE と TARGET の設計案
最終更新: 2026-08-12

1. 目的

Player Profile は「誰として対局するか」を表す。
Engine Profile は「どの GTP エンジン実行ファイルを、どの引数で起動するか」を表す。
両者は別の責務であり、同じ Engine Profile を、表示名や接続先の異なる複数の Player Profile から参照できる。

Player Profile、Engine Profile、Target Profile は、それぞれ独立して登録する。
Player Profile は Engine Profile と Target Profile を一方向に参照する。
Target Profile は、ある用途・接続先において、その Player をどう識別するかを表す。


2. 用語と画面名

- PLAYER PROFILE
  対局者の登録情報。現在の PlayerProfile に相当する。

- DISPLAY
  Player の人が読む呼び名。画面表示および SGF の PB / PW に使う。
  旧「DISPLAY NAME」は、この意味で Player Profile に置く。

- ENGINE PROFILE
  Computer Player が参照する、GTP エンジンの起動・GUI オプション・GTP ログなどの設定。
  旧「EDIT GTP ENGINE」は「EDIT ENGINE PROFILE」と呼ぶ。
  Engine Profile の表示名は、エンジン設定を識別するための名前であり、対局者名ではない。

- TARGET
  Player が利用する用途または接続先ごとの設定。
  表示名、LOGIN NAME、LOGIN PASS を持つ。Player の TargetProfileIds の先頭を既定 Target とする。

- LOGIN NAME
  システムへのログインや、ファイル名など機械的な用途に使う識別子。
  アプリ全体では文字種・文字数を制限せず、実際の接続先・出力先が必要な検査と変換を行う。

- LOGIN PASS
  システムへの接続に使うパスワード。画面上は伏せ字で扱う。

- OUTPUT NAME
  LocalMatch Target における LOGIN NAME の画面上の呼称。ログインはしないため、出力ファイル名などの材料を表す。
  LocalMatch では LOGIN PASS を表示・使用しない。


3. 独立カタログと参照の構造

PlayerProfile
  Id
  DisplayName
  Kind                 Human / Computer
  EngineProfileId      Computer の場合だけ使用する Engine Profile への参照
  TargetProfileIds[]   使用可能な Target Profile への参照

EngineProfile
  Id
  DisplayName          エンジン設定を識別する表示名
  ExecutablePath
  WorkingDirectory
  Arguments
  GuiOptions
  GtpLog など

TargetProfile
  Id
  DisplayName          例: CGOS / LocalMatch / Test Server
  ConnectionProfileId  接続先の Host / Port 等を持つカタログ項目への参照。LocalMatch では空
  LoginName
  LoginPass

Player Profile は Engine Profile と Target Profile を逆参照しない。
Engine Profile と Target Profile は、どの Player から参照されているかを保存しない。
削除時だけ Player Catalog を検索し、参照中なら削除を拒否するか、利用者へ参照先の差し替えを求める。

Target Profile の DisplayName は画面表示用の任意文字列である。
CGOS の Host、Port、イベント、ラウンド等は、既存の CGOS Connection Profile 側で管理する。
Target Profile は ConnectionProfileId によりそれを参照する。将来の接続先カタログでは、安定した ID を必須にする。

接続先カタログは、現在は「接続先（CGOS）」である。将来は他サービスも扱えるよう、ConnectionProfile は接続種別（現在は Cgos）を持つものとして一般化する。
TargetProfile が保持するのは Host / Port を連結した接続文字列ではなく ConnectionProfile の不変 Id である。接続文字列は編集・表記揺れ・TLS 等の接続オプション追加で変化し得るため、参照キーにしない。
接続種別と正規化済み Host / Port から作る EndpointKey（例: cgos://uec-go.com:6809）は、重複候補の検出・警告・初期候補の決定に使う。同一 Endpoint でもイベント、ラウンド、接続オプションが異なる複数 ConnectionProfile は許可する。


4. Target のサンプル

Computer Player: 「きふわらべ」

  DISPLAY: きふわらべ
  ENGINE PROFILE: Kifuwarabe Go 2026

  TARGET PROFILE: CGOS
    LOGIN NAME: kifuwarabe
    LOGIN PASS: (秘密情報)
    CONNECTION PROFILE: CGOS Server 9-ro

  TARGET PROFILE: LocalMatch
    OUTPUT NAME: kifuwarabe-local
    CONNECTION PROFILE: なし

Human Player: 「山田太郎」

  DISPLAY: 山田太郎

  TARGET PROFILE: LocalMatch
    OUTPUT NAME: yamada-taro
    CONNECTION PROFILE: なし

同一 Player が CGOS 用と LocalMatch 用で異なる LOGIN NAME を持てる。
同じ Engine Profile を参照する別 Player にも、それぞれ独立した Target Profile を設定できる。
LOGIN NAME と LOGIN PASS は参加者固有の情報なので、通常は別 Player 間で同じ Target Profile を共有しない。


5. LocalMatch の利用規則

LocalMatch のインターバル画面では、黒白それぞれについて次の二段階を選ぶ。

  1. PLAYER PROFILE
  2. TARGET

Target 候補は、選択した Player Profile が参照するものだけを表示する。
LocalMatch 開始時は、黒白とも LocalMatch 用 Target Profile を選択する。
将来、Player ごとに複数の LocalMatch Target Profile を参照することも許可する。
その場合は利用者が明示選択する。候補が一つだけでも自動選択せず、画面に選択結果を表示する。

棋譜の内容とファイル名の責務は次のように分ける。

  SGF PB / PW       Player Profile の DISPLAY
  LocalMatch の
  ファイル名の材料  選択 LocalMatch Target の LOGIN NAME

ファイル名へ書き出す際だけ、OS に依存する禁止文字の置換などを行う。
LOGIN NAME 自体を保存時に変換・制限しない。
LOGIN NAME が空欄の場合は、ファイル保存時に DISPLAY を代替値として使うか、保存前に利用者へ警告する。実装時に一方を仕様として確定する。


6. UI 方針

現在、Player の DISPLAY は Player 編集画面にあり、CGOS LOGIN / CGOS PASS は Engine Profile 編集画面と CGOS 接続画面に分散している。
これを次の形に統合する。

EDIT PLAYER PROFILE
  DISPLAY
  TARGET               既定 Target の表示
    [SELECT TARGET]    Target 一覧を開く
  KIND
  ENGINE PROFILE       Computer の場合だけ。EDIT ENGINE PROFILE を開く
  TARGET PROFILES
    [CGOS]        LOGIN NAME / LOGIN PASS / 接続先
    [LocalMatch]  LOGIN NAME
    [USE] [CREATE TARGET] [EDIT TARGET] [REMOVE TARGET]

EDIT ENGINE PROFILE
  ENGINE DISPLAY
  EXE
  WORKDIR
  ARGS
  GUI OPTIONS
  POSITION
  GTP LOG

Engine Profile 編集画面から CGOS LOGIN / CGOS PASS を削除する。
CGOS 接続画面は黒白の Player Profile と CGOS Target を選び、その Target の認証情報を接続プロセスへ渡す。


7. JSON 保存と移行

現状:

- player-list.json
  Player の Id、DisplayName、Identifier、Kind、EngineProfileId を保存する。

- gtp-engine-list.json
  GTP エンジン設定に defaultCgosLoginName と defaultCgosPlainTextPassword が混在する。

- application-settings.json
  CGOS 接続先の DisplayName、Host、Port、Event、Round、Note を保存する。

目標の player-list.json 例:

{
  "players": [
    {
      "id": "player-kifuwarabe",
      "displayName": "きふわらべ",
      "kind": "computer",
      "engineProfileId": "engine-kifuwarabe",
      "targetProfileIds": ["target-cgos-kifuwarabe", "target-localmatch-kifuwarabe"]
    }
  ]
}

目標の target-list.json 例:

{
  "targets": [
    {
      "id": "target-cgos-kifuwarabe",
      "displayName": "CGOS",
      "connectionProfileId": "cgos-9ro",
      "loginName": "kifuwarabe",
      "loginPass": "..."
    },
    {
      "id": "target-localmatch-kifuwarabe",
      "displayName": "LocalMatch",
      "connectionProfileId": "",
      "loginName": "kifuwarabe-local",
      "loginPass": ""
    }
  ]
}

移行手順:

1. TargetProfile と Target Catalog を追加し、既存 Player は空の TargetProfileIds として読めるようにする。
2. GtpEngineProfile の defaultCgosLoginName / defaultCgosPlainTextPassword を読み取り、対応する Computer Player ごとに独立した CGOS Target Profile を一度だけ生成して参照させる。
3. 各既存 Player に独立した LocalMatch Target Profile を生成して参照させる。LOGIN NAME は旧 Identifier を最初の候補として使う。
4. CGOS Connection Profile に不変 ID を追加し、TargetProfile.ConnectionProfileId から参照できるようにする。
5. CGOS の実行時認証情報を、選択 Player が参照する Target Profile から解決する。
6. 移行猶予後に Engine Profile の旧 CGOS 認証項目と、CGOS 接続画面の黒白一時認証編集を削除する。


8. パスワードの扱い

既存の GTP Engine JSON はパスワードを平文保存している。
移行だけなら平文値を PlayerTarget.LoginPass へ移せるが、新規設計では OS の保護ストア（Windows では DPAPI など）を使うことを推奨する。
少なくとも、画面は伏せ字、コピーを抑制し、ログ・SGF・ファイル名へ LOGIN PASS を出力しない。

9. 最新実装ステータス（2026-08-12）

完了:
- Player / Engine / Target の責務分離、Target の JSON 保存、CGOS 実行時の Target 認証情報参照。
- Player 編集画面の Target 表示、`SELECT TARGET`、`EDIT TARGETS`、Target 一覧、最大5件の追加、削除、選択、CGOS 接続先の前後切替。
- Target の DISPLAY / LOGIN NAME / LOGIN PASS のテキスト編集。パスワードは非編集中に伏せ字で表示する。
- LocalMatch Target の画面では LOGIN NAME を OUTPUT NAME と表示し、LOGIN PASS を表示しない。
- `USE` で選択 Target を Player の既定 Target（TargetProfileIds の先頭）へ設定する。

残作業:
- LocalMatch 開始設定で黒白それぞれの LocalMatch Target を明示選択し、OUTPUT NAME を出力ファイル名へ使用する。
- CGOS で接続先ごとに複数 Target がある場合の選択画面・既定選択規則を明示する。
- Target の CGOS Connection Profile 選択 UI を接続先一覧と統合する。
- LOGIN PASS の OS 保護ストア移行。

運用方針:
- Target は Player ごとに1～5件の少数を前提とする。ORDER とページ送りは作らない。
- LocalMatch Target の接続先は LOCAL MATCH 固定。CGOS Target は ConnectionProfile の ID を参照する。
