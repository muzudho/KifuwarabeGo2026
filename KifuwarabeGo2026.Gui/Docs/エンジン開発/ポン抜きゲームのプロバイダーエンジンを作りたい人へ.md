# ポン抜きゲームのプロバイダーエンジンを作りたい人へ

## 役割

App Provider Engineは、ポン抜きゲームの初期局面作成、着手の監視、アゲハマの集計、終局判定と勝者決定を担当します。GUI自身は「アゲハマ20個で勝ち」を判定せず、プロバイダーの応答を信頼して結果画面へ進みます。

GTPと同じく、GUIがコマンドを送り、エンジンが成功応答 `=` または失敗応答 `?` を返します。独自コマンドの正式名は `kfw-` 接頭辞のkebab-caseです。応答本文の構造化データには1行のJSONを使います。

## 能力確認

GUIの［RECHECK PROVIDER］は次を送ります。

```text
known_command kfw-make-position
known_command kfw-listen-move
```

両方に対応するエンジンは、それぞれ `= true` を返してください。

## 初期局面

```text
kfw-make-position ponnuki 1 9 20
```

引数はApp ID、プロトコルバージョン、盤サイズ、初期局面を作るための目安手数です。成功応答の例です。

末尾へ整数シードを指定すると、同じ初期局面を再現できます。

```text
kfw-make-position ponnuki 1 9 20 12345
```

シードを省略した場合、エンジンがシードを自動生成します。きふわらべ標準エンジンは、OSの暗号学的乱数源から偏りのない整数を選びます。自動生成時も指定時も、実際に使ったシードを応答の `seed` へ必ず格納してください。

```text
= {"app":"ponnuki","version":1,"boardSize":9,"black":["D4"],"white":["E4"],"toPlay":"black","captures":{"black":0,"white":0},"seed":12345}
```

`black`と`white`は初期配置として扱います。それ以前の仮想手順で生じたアゲハマは持ち越さず、ゲーム開始時は双方0個です。プロバイダーはこの局面と手番を保持し、同じプロセスで後続の着手通知を待ってください。

GUIは応答されたシードをGUI操作ログにも記録します。これを指定付きコマンドへ戻すことで、検討時に同じ初期局面を再現できます。

## 着手通知と終局判定

GUIは、盤上へ反映された着手ごとに次を送ります。

```text
kfw-listen-move A3
```

パスは次の形です。

```text
kfw-listen-move pass
```

プロバイダーは保持している盤面へ現在手番の着手を適用し、取った石を現在手番側のアゲハマへ加算します。継続時の例です。

```text
= {"accepted":true,"gameOver":false,"winner":"","reason":"","blackCaptures":7,"whiteCaptures":4,"nextToPlay":"white"}
```

どちらかがアゲハマ20個へ達した直後の例です。

```text
= {"accepted":true,"gameOver":true,"winner":"black","reason":"PONNUKI BLACK CAPTURED 20","blackCaptures":20,"whiteCaptures":12,"nextToPlay":"white"}
```

`gameOver: true` を受けたGUIは対局中画面から結果画面へ遷移します。`winner`は `black`、`white`、または引き分けを表す空文字列です。

通知された手が局面と一致しない場合は、成功扱いにせずGTP失敗応答を返してください。

```text
? illegal provider move notification
```

## 最小対応コマンド

- 標準GTP: `protocol_version`、`name`、`version`、`known_command`、`list_commands`、`quit`
- 独自拡張: `kfw-make-position`、`kfw-listen-move`

現在の勝利条件は「先にアゲハマ20個」です。将来ルールを増やす場合は、既存バージョンの意味を変更せず、新しいAppプロトコルバージョンとして追加してください。
