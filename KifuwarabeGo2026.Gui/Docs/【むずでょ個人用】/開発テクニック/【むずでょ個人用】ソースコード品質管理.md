# 【むずでょ個人用】ソースコード品質管理


## セクションコメント

（１）以下のように、コを左右逆にした形のコメントを、  
このプロジェクトでは［セクションコメント］と名付けるぜ（＾～＾）  
長い部分のスラッシュの数は 40 個。  

```csharp
////////////////////////////////////////
//
////////////////////////////////////////
```

（２）以下のようにセクション名を付けるぜ（＾～＾）  

```csharp
////////////////////////////////////////
// 生成
////////////////////////////////////////
```


## セクションコメントの使い方

構造はフラットであり、上から下の順序を持つ。つまりリストと同じだぜ（＾～＾）  

```csharp
////////////////////////////////////////
// 生成
////////////////////////////////////////

////////////////////////////////////////
// データメンバー
////////////////////////////////////////

////////////////////////////////////////
// 機能
////////////////////////////////////////
```

どのようなセクションがあるかは、任意だが、だいたい他のソースコードと合わせていくぜ（＾～＾）  
あとで説明するが、  
このセクションコメントは、ここで要素は同質の集まりではなくなる、のような切れ目であり、  
［同質のツリー構造］に付けたタイトルみたいな感じで使う（＾～＾）  


## パンくずリストコメント

一般的には `#region` は使うなと言われているが、  
このプロジェクトは一般的ではないので、以下のように `#region` も使っていく（＾～＾）  

```csharp
#region ［Table　＞　Element］
#endregion
```

わたしは日本人なので、全角文字の `［　＞　］` を使っていく（＾～＾）  
べつに半角文字の `[ > ]` を使っても構わない（＾～＾）  
表記ゆれすることになるが、どちらかに揃えようとすると収束しないので、放置すること（＾～＾）  

ただし、ネストは好まない。以下のように、深さ優先探索で並べること（＾～＾）    

```csharp
#region ［Table］
#endregion

#region ［Table　＞　Element］
#endregion

#region ［Table　＞　Element　＞　SubElement］
#endregion
```

# 実装例

```csharp
    // ========================================
    // 生成
    // ========================================

    #region ［生成　＞　固定オブジェクト］
    #endregion

    #region ［生成　＞　ファクトリーメソッド］
    #endregion

    #region ［生成　＞　コンストラクター］
    #endregion

    // ========================================
    // データメンバー
    // ========================================

    // ========================================
    // 機能
    // ========================================
```
